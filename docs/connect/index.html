Connecting your AI tools

Slate runs an MCP server out of its own app bundle, and connects it to your AI tools when you turn them on. Most people never read past the first section — the rest is for a tool Slate doesn't know about yet, and for anyone who would rather see the config than trust that it happened.

The easy way

Setup's Connect step, or Connect → AI tools any time after it, lists five tools: Claude Code, Codex, Gemini, Cursor and OpenCode. Gemini CLI now needs an API key or a paid Code Assist licence from Google. Pick the tool and the profile it runs under, switch it on, and Slate is installed for that config folder — every project on this computer included.

What the switch writes. In Claude Code, Codex, Gemini and Cursor, Slate installs its plugin, and the plugin supplies the MCP server. In OpenCode it adds an MCP entry and one plugin module to opencode.json. Without Node 24 or newer, Slate writes into the tool's config instead. A tool's dialog names the file Slate writes, every write copies the original aside first, and turning the switch off takes out what Slate put there.
It asks first, once. Nothing outside Slate's own folder is touched until you connect a tool yourself. After that, Slate keeps tools you install later connected too, without asking again.

The binary

For connecting by hand. It ships inside the app: there is no separate install, no Node, and nothing to add to your PATH — every config below is the same one line pointed at this file. 

/Applications/Slate.app/Contents/MacOS/slate-mcp

Claude Code

Add this to ~/.claude.json, creating the file if it isn't there. Restart Claude Code and slate appears in /mcp. 

{
  "mcpServers": {
    "slate": {
      "command": "/Applications/Slate.app/Contents/MacOS/slate-mcp",
      "args": []
    }
  }
}
Connected from the app? Skip this. There Slate is installed as a Claude Code plugin, which supplies the server — so on its next launch Slate removes a hand-added slate entry rather than list every tool twice.

Cursor

Settings → MCP → Edit, which opens ~/.cursor/mcp.json. Reload Cursor and the Slate tools appear in the agent's tool list. 

{
  "mcpServers": {
    "slate": {
      "command": "/Applications/Slate.app/Contents/MacOS/slate-mcp",
      "args": []
    }
  }
}

Anything else

The server speaks stdio MCP. Point any MCP-aware tool at the binary with no arguments — that is the whole integration. 

command:  /Applications/Slate.app/Contents/MacOS/slate-mcp
args:     []

Check it worked

Ask the tool you just connected:

“Use the slate_capabilities tool to check the Slate contract, then use recall with query test to check if Slate is connected.”

You should get an answer that references your workspace. An empty result is a success, not a failure — it means the connection is live and nothing matches test yet.
