Connecting your AI tools

Slate runs an MCP server out of its own app bundle. On first launch it registers itself with the tools it finds, so most people never read this page — it is here for when it didn't, for a tool Slate doesn't know about yet, and for anyone who would rather see the config than trust that it happened.

The binary

It ships inside the app. There is no separate install, no Node, and nothing to add to your PATH — every config below is the same one line pointed at this file. 

/Applications/Slate.app/Contents/MacOS/slate-mcp

Claude Code

Add this to ~/.claude/settings.json, creating the file if it isn't there. Restart Claude Code and slate appears in /mcp. 

{
  "mcpServers": {
    "slate": {
      "command": "/Applications/Slate.app/Contents/MacOS/slate-mcp",
      "args": []
    }
  }
}
Per project instead. The same block in .claude/settings.json at a repo root activates Slate only inside that project, alongside your global config.

Cursor

Settings → MCP → Edit, which opens ~/.cursor/mcp.json. Reload Cursor and the Slate tools appear in the agent's tool list. 

{
  "mcpServers": {
    "slate": {
      "command": "/Applications/Slate.app/Contents/MacOS/slate-mcp",
      "args": []
    }
  }
}

Anything else

The server speaks stdio MCP, protocol 2024-11-05. Point any MCP-aware tool at the binary with no arguments — that is the whole integration. 

command:  /Applications/Slate.app/Contents/MacOS/slate-mcp
args:     []

Check it worked

Ask the tool you just connected:

“Use the slate_capabilities tool to check the Slate contract, then use recall with query test to check if Slate is connected.”

You should get an answer that references your workspace. An empty result is a success, not a failure — it means the connection is live and nothing matches test yet.
