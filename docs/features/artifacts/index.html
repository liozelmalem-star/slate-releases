Features

Artifacts

An artifact is a web page an agent made for you to look at: an HTML page, dashboard, chart, report or Markdown note. Any connected tool publishes one with Slate's publish_artifact MCP tool. It is stored in your workspace on this computer and listed in Artifacts in the left rail.

An app is a different thing, built with get_app and publish_app. Given an app, the artifact tools refuse and name those.

Making and changing one

You do not write or edit an artifact by hand. You ask.

  • Ask for one in plain words: "make me a dashboard of this data as an artifact". Every connected tool is also told to show a chart, table or report this way on its own. The tool sends the web page with a title, or writes it to a file and sends the path. Slate reads such a file only from the working folder or a temp folder. It never reads a file, or a file in a folder, whose name starts with a dot below your home folder or the working folder (.env, .ssh). It does not trust a working folder that is your home folder or wider.
  • Ask for a change: "make the bars blue". Type it in Ask for a change under the artifact's title, or say it to any tool. The box opens a session in the project the artifact was made in, on that project's own tool. The tool reads the web page with get_artifact and sends only the parts that change. That adds a version; older ones stay. Publishing the same web page again adds none. On an older version the box says so ("This change starts from v1, not the newest (v3)") and the tool sends the whole web page as a new version, because edits only apply to the newest.
  • Open it: click the slate://artifacts link the tool gives you. The link names the workspace, so Slate switches to it first.

The Artifacts screen

  • The side panel starts with Overview, then lists every artifact in the workspace, newest first, with an icon for HTML or Markdown and when it last changed. Artifacts belong to the workspace, not a project, so there is no project picker. Filter artifacts narrows the list by title and description.
  • Overview shows every artifact as a card, newest first, with a still picture above its name. The cards are the ones Apps draws. An HTML picture is the web page in a frame that runs no script, with Slate's look and the current light or dark theme. A chart the web page draws with a script shows only what its markup holds. A Markdown picture uses the viewer's renderer. A picture is drawn only while its card is on screen, at most nine at a time.
  • An open artifact fills the main area, under its name, who made it and when, and what it is.
  • Preview | Code switches between the web page and its read-only source. HTML source is laid out one block per line, indented by depth; only spacing changes. Copy HTML copies the web page exactly as published.
  • ‹ v2 of 3 › steps through versions. An older one says "You are looking at v2. The newest is v3." and offers Restore this version, which publishes it again as a new version, so nothing in between is lost.
  • Ask for a change shows only on an artifact you published and made under a project folder. A teammate's has one writer, and a folderless one has nowhere to start a session.
  • ⋯ holds Copy HTML or Copy Markdown, Open in browser (HTML only), Rename, and Delete forever, which asks ("Delete every version forever?") before it removes every version. If a rename or removal fails, the menu stays open and says why.

Finding one again

  • ⌘K finds an artifact by title or description, and a Markdown artifact by its text. Results sit under ARTIFACTS, after the reports. HTML code is not searched, so "table" or "style" does not match every dashboard.
  • The doc it was made on lists it under Artifacts made here. A branch shows its own; a project shows every one made inside it.
  • recall, which every connected tool uses, returns up to 2 artifacts after the memories when every word of the question matches one. A session can find last week's dashboard and change it instead of rebuilding it.

How an HTML artifact looks

Every HTML artifact gets Slate's look before its own styles: the app's font, colours, and plain buttons, inputs, tables, code and headings. It follows light or dark and your workspace's colour, and changes at once when you switch. A web page's own styles win over Slate's.

Tools are told this when they publish, so they write plain HTML with Slate's colours: var(--text), var(--muted), var(--surface), var(--border), var(--accent), the chart colours var(--c1) to var(--c5), and the classes card, badge, grid, row and stack. In your own browser the web page uses Slate's default colours and your system's light or dark setting.

Live artifacts

A tool can publish an artifact live (live: true). A live artifact reads your workspace while you look at it, so a dashboard stays true without being published again. Its header says Reads your workspace · no internet. Turning live on or off adds a version. The reasons are in ADR 0070.

  • What it reads: the docs, one doc's text, the memories and the AI sessions of the project it was made in (the whole workspace when made under none). Newest first, up to 5,000 rows each. It cannot change anything.
  • No way out: no fetch, no WebRTC, no image or font from the internet, no form, no new window. Scripts may still load from cdnjs, jsDelivr and unpkg, so a chart library works. If the web page tries to leave for another address, Slate closes it.
  • No origin of its own: it shares nothing with other artifacts, not even localStorage. It talks to Slate only over a private channel it opens at start.
  • Yours only: in a shared workspace, a teammate's live artifact shows as a plain web page and never reads your store. A live artifact restored on another computer also arrives as a plain web page.

Where it runs

An HTML artifact runs its own scripts. It is served from your workspace on a private local address, apart from Slate and your data, and cannot steer the Slate window. Nothing is copied to disk. It can load scripts and fonts from the internet like any web page. A Markdown artifact is shown as formatted text.

A teammate's web page runs without storage of its own. It keeps scripts, forms, downloads and popups, but cannot read what your own web pages keep in the browser. Your own web pages keep their storage.

Artifacts live in the workspace they were published from. In a shared workspace every member sees them in Artifacts. Each has one writer, the publisher. A teammate's artifact shows "Written by" and their name, with no Rename or Delete forever. A new version they publish reaches you on the next sync. Only the newest version is sent, so you keep each version you received; someone who joins later starts at the newest. Moving a group or project to another workspace takes its artifacts along.

Limits

  • One web page per artifact, up to 5,000,000 characters.
  • HTML or Markdown only.

Slate is in alpha. Your data stays on your machine.
