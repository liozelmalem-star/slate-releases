Features

Artifacts

An artifact is a page an AI tool made for you to look at: an HTML app, a dashboard, a chart, a report, or a note in Markdown. Any connected tool (Claude Code, Codex, Cursor, Gemini, OpenCode) publishes one with Slate's publish_artifact MCP tool. It is stored in your workspace, on this Mac, and appears in the Artifacts tab of the left rail.

Making and changing one

The way Claude's artifacts work: you do not write or edit an artifact by hand. You ask.

  • Ask for one in plain words: "publish this as an artifact", "make me a dashboard of this data as an artifact". Every connected tool is told to show a chart, a table or a report this way on its own. The tool sends the page with a title, or writes it to a file in its working folder and sends the file's path.
  • Ask for a change: "make the bars blue", "add a summary at the top". Type it in Ask for a change under the artifact's title, or say it to any tool. The box starts a session in the project the artifact was made in, on that project's own tool, and opens it. The tool reads the current page with get_artifact and sends only the parts that change. That adds a version, and the older ones stay. Publishing the same page again adds no version.
  • Open it: the tool gives you a slate://artifacts link. Click it and Slate opens on that artifact. The link names the workspace the artifact is in, so Slate switches to that workspace first when the window is showing another.

The Artifacts tab

  • The pane lists every artifact, newest first, with an icon for HTML or Markdown and when it last changed. The project picker at its head narrows the list to the artifacts made anywhere inside one project; one made under no page shows on All projects only. Filter artifacts under it narrows the list by title and description. With nothing picked, the first one the pane lists is shown.
  • The artifact fills the stage. The header still says Artifacts; under it, the artifact's own name, who made it and when, and what it is.
  • Preview | Code switches between the page and its source. The source is read-only. HTML is laid out to be read: one block per line, indented by depth. Only the spacing changes, and a script keeps its own lines. Copy HTML still copies the page exactly as the tool published it.
  • ‹ v2 of 3 › steps through the versions when there is more than one.
  • Ask for a change sits under the title of an artifact you published. It is not shown on a teammate's artifact, which has one writer, or on one made under no project folder, where there is nowhere to start a session.
  • The ⋯ menu holds Copy (the page's HTML or Markdown), Open in browser (HTML only), Rename, and Delete, which asks once more and then removes every version.

Finding one again

  • ⌘K finds an artifact by its title or description, and a Markdown artifact by its text too. They are listed under ARTIFACTS, after the reports, and open here. An HTML artifact's code is not searched, so a word like "table" or "style" does not match every dashboard.
  • The page it was made on lists it under Artifacts made here — a branch shows its own, a project shows every one made anywhere inside it. Click one to open it here.
  • recall, which every connected tool uses, returns up to 2 artifacts after the memories when every word of the question matches one. So a session can find last week's dashboard and change it instead of building it again.

How an HTML artifact looks

Every HTML artifact gets Slate's look before its own styles: the app's font, its colours, and plain buttons, inputs, tables, code and headings. It follows the app as you use it — light or dark, and your workspace's colour — and changes at once when you switch, without reloading. A page that styles itself keeps its own look, because any rule it writes wins over Slate's.

The AI tools are told this when they publish, so they write plain HTML and use Slate's colours: var(--text), var(--muted), var(--surface), var(--border), var(--accent), the chart colours var(--c1) to var(--c5) (the mark's five), and the classes card, badge, grid, row and stack. Opened in your own browser, the page uses Slate's default colours and your system's light or dark setting.

Live artifacts

A tool can publish an artifact live. A live artifact reads your workspace while you look at it, so a dashboard stays true without being published again. Its header says so: Reads your workspace · no internet.

  • What it can read: the pages, one page's text, the memories and the AI sessions of the project it was made in (the whole workspace when it was made under none). Newest first, up to 5,000 rows each. It cannot change anything.
  • No way out: a live artifact cannot open any connection — no fetch, no image or font from the internet, no form, no new window. Scripts may still load from cdnjs, jsDelivr and unpkg, so a chart library works. If the page tries to leave for another address, Slate closes it.
  • Yours only: in a shared workspace, a teammate's live artifact shows as a plain page. It never reads your store. The setting does not travel with a shared workspace, so a live artifact restored on another computer arrives as a plain page.

Live is the publisher's choice: the tool passes live: true. Turning it on or off adds a version. The decision and its reasons are ADR 0070.

Where it runs

An HTML artifact runs its own scripts. It is served straight from your workspace on a private local address, apart from Slate and your data, and it cannot steer the Slate window. Nothing is copied to disk to show it. It can load scripts and fonts from the internet like any web page. A Markdown artifact is shown as formatted text.

Artifacts live in the workspace they were published from, like pages. In a shared workspace they are shared like pages too: every member sees them in Artifacts. Each artifact has one writer, the person who published it. A teammate's artifact shows "Written by" and their name, and its menu has no Rename or Delete. A new version they publish reaches you on the next sync. Only the newest version is sent, so you keep each version you received. Someone who joins later starts at the newest one. Moving a group or project to another workspace takes its artifacts with it.

Limits

  • One page per artifact, up to 5,000,000 characters.
  • HTML or Markdown only.

Slate is in alpha. Your data stays on your machine.
