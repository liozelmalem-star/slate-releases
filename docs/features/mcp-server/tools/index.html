Tool Reference

Slate's MCP server exposes 22 tools, grouped below. There were 29 until 2026-09-24: the ones almost no session called were merged into the tools that do the same job, or left to Slate's in-app agent. Fewer tools is also what every AI vendor's own guidance asks for, because a model picks the right tool more often from a short list.

Almost every tool takes an optional cwd — your working directory. Slate resolves it to the workspace that owns that folder, so a tool working in a shared checkout reads and writes that workspace. Omit it and you get your Personal one. The three exceptions are slate_capabilities, recall_workspaces and workspace_page, which read no local workspace at all.

Every tool also carries the standard MCP labels: a title, whether it only reads, whether a write can replace what is stored, and that none reaches outside Slate. Claude Code loads recall and remember at session start and the rest when they are needed.

Pages

ToolPurpose
create_documentCreate a typed document (title + doc_type, user_approved:true, optional parent_id, source_ref, markdown). Fills a template when no markdown is given. A second call for the same type on the same branch rewrites that page rather than adding one. The tool refuses the write unless the user first said yes.
get_pageRead one page by id or target. Returns title, icon, breadcrumb path and body as Markdown. A page a colleague shared is read with workspace_page.
append_to_pageAppend Markdown to the end of a page, by id or target. Replies with the page's id, title and path, so a target resolved from the branch says where it landed.

To find a page, use recall: it searches page titles and bodies alongside memory, and kind: "pages" keeps to pages alone.

Creating plain pages, renaming, moving and trashing are done in the app

A connected AI tool can save a typed document and add to a page. It cannot create a plain page, rename, reparent, duplicate, trash or find-and-replace inside one. Those are direct-manipulation gestures: you do them in one drag in Slate, and you can undo them. Over MCP there is no undo, and the tool cannot see what it did.

Slate's own in-app agent still does all five for you, and undoes a page it created by archiving it again. The other four are not undone: rely on the page's own history instead.

Memory

ToolPurpose
rememberSave one typed knowledge atom (kind: decision \preference \state \fact \lesson), scoped by cwd and deduped against what's known — a near-duplicate strengthens, an update supersedes. replaces names the memories this one corrects, by ref, and retires them. when makes it a lesson handed over on a matching tool call: {tool: "shell", match} or `{tool: "read" \"edit", path}; a pattern that matches everything is refused. Text that reads as passing status, or a git snapshot, is refused rather than stored. A decision needs its reason, as reason or in the sentence. Keys and tokens are replaced with [secret]`. A claim that contradicts a firmer memory is held for review in Memory.
recallThe one search. Returns the branch brief on a feature branch, then memories and pages ranked lexically (keyword coverage × recency × confidence). Each memory is one line with its ref (m:7f3a2b1c) and citation. Default 8 results, 25 maximum. Silent when nothing is relevant. kind: "pages" searches page titles and bodies only, each hit with a snippet. With as_of (2026-08-01), answers from what the memory believed at the end of that day: memories only, each one replaced since marked with until.
get_memoryRead memories in full by refs: the claim, its reason, its citation, and citation — same, changed, gone or unchecked — for whether the cited file changed since; evidence, which tools confirmed and cited it; and history, what it replaced and what replaced it. Refs that name nothing come back under unknown.
list_memoriesFor a tidy the person agreed to: the repo's memories, oldest first, up to 100 per call from offset, each with its ref and whether it is resting.
propose_memory_changePropose a merge (several refs into one text), a retire, or a lesson (refs into one lesson text with its when). Nothing changes until the person accepts it in Slate under Memory → Needs review. Refs outside the repo are refused.
log_mission_progressAppend a session summary to a Progress section — on the branch's Plan page when one exists, otherwise on the branch page. It never creates a page. Takes mission_id — the branch page id recall returned — and summary, plus optional decisions, open_items and goal.

Workspaces

ToolPurpose
recall_workspacesSearch what other people published, across every workspace you belong to. Returns two halves: memory — their recorded decisions, facts and preferences, one sentence each with an author — and pages, with title, doc type, author and a text excerpt. Default 8 of each, 25 maximum.
workspace_pageRead one shared page in full, by the id recall_workspaces returned.

These read the cloud, not your local file. They need a cloud sign-in and are read-only — a shared page belongs to its author. When you are not a member of a workspace, Row Level Security returns an empty result rather than someone else's rows; signed out, they say so plainly instead of returning nothing, since an empty result would read as "nobody has shared anything". They stay separate from recall and get_page on purpose: private and shared knowledge carry different trust, and one tool that could return either would hide which you got.

Activity

ToolPurpose
activityWhat you have been doing across every tool and project. view: "recent" (the default) lists sessions newest first; days bounds the window, default 1 (today), and each row carries the pageId it is filed under. view: "parked" lists branches left carrying UNCOMMITTED changes and not returned to — which git cannot show, since a commit records only what landed. Idle threshold stale_after_hours, default 48; limit default 10.

Session totals and the project list are drawn in the app, on Activity and in the sidebar.

Your Work list

ToolPurpose
my_workYour Work list. view: "today" (the default) returns your own tasks that are overdue or due today — grouped the way the Work tab groups them — and the first 10 open items your tools gave you, each with the key you know it by (PROJ-12, acme/api#412). view: "all" returns every open task and up to 100 items. Counts of what was left out come back as more_tasks and more_items. Today's meetings are not included: Slate keeps them only in the app's memory, never in the store.
update_my_workAdd a line to your own list, or change one of yours. Without an id it adds title; with one it can tick it off (done: true), reopen it (done: false), rename it (title), or set or clear its reminder. Give in_minutes (Slate does the arithmetic on its own clock) or at as an ISO instant; clear_reminder: true takes it off. A reminder rings a notification when it comes due. It refuses a Jira, Linear or GitHub item and says which tool to change it in.

Other agents

ToolPurpose
handoffLeave one note for the other agents working in the same repository, or send it to one of them with to. Each is shown it once, at the start of their next turn. Notes that only narrate work in progress are refused, and the refusal says so.
live_sessionsEvery AI session running on this machine right now — tool, status (working / waiting / idle), project, repo, branch, its opening prompt, the last thing it said, when it was last active, its goal and next unchecked item, its page id, and its folder (cwd). To read a session's page, pass that page id and that cwd to get_page — the folder is what reaches a page owned by a shared workspace. Pass cwd to see only the sessions sharing your repo, and your own sessionId to be left out.

An agent does not have to ask. When another agent is working in the same repo, Slate says so once at the start of a turn, and the block carries that session's own words — what it was asked to do, and the last thing it said — so you know what it is doing inside the turn you are already reading. A page id comes with it for the rest.

Two agents talk by leaving notes addressed to each other. handoff with a to is a message; a reply is another handoff addressed back. That is the whole mechanism — there is no channel to open, no inbox to poll and no queue underneath it. A note with no to is for everyone working here.

Slate carries the notes and assigns nothing. There is no scheduler and nothing that tells an agent what to do about what it has been told.

Decisions

ToolPurpose
record_decisionRecord a decision — title and reasoning, plus optional alternatives, confidence and outcome. Writes a decision atom and a decision page holding the full reasoning. Returns JSON with the page id and the atom's id under atom, the same shape remember returns. recall returns decisions first when a question asks why.
publish_artifactPublish a page for the person to look at — title, kind (html or markdown) and content, plus optional description. It opens in Slate's Artifacts tab. Pass the artifact_id a previous call returned to add a new version; older versions stay readable. The same content again adds no version, only the new title or description. Returns JSON with artifact_id and version. Refuses an empty title or content, or a page over 5,000,000 characters, with invalid_artifact.
get_artifactRead an artifact before changing it — artifact_id, plus an optional older version. Returns its title, kind, description, the version read, the newest version number and the full content. Without artifact_id it lists every artifact, newest first, without content. An unknown id answers artifact_not_found.

Tasks

Only for a session a Slate task started. Its first prompt carries the task's token. They are listed in every session, as the MCP spec requires one list per server; outside a task get_task answers no_task.

ToolPurpose
get_taskReturn the task's current step, its attempt and the step's instructions. Takes cwd, and the token from the first prompt or a task_id. A blocked task returns why it is blocked and tells the agent to stop and wait, with no step instructions.
report_task_stepReport the step get_task gave: outcome done, blocked, needs_input or failed, a short summary, and optional JSON body. A report for an old step is refused and says which step is current.

Contract

ToolPurpose
slate_capabilitiesContract version, supported tools, access levels, approval policies, schema hash. Read-only discovery, no arguments. A tool's access level is its readOnlyHint label, so the two cannot disagree.

Resolving a target

get_page and append_to_page do not need an explicit page id. Instead they accept a target descriptor and resolve the page from it:

FieldMeaning
kindbranch for the branch overview, knowledge_page for a typed child under it.
cwdYour working directory — anchors to the right repo, and to its active branch when branch is omitted.
branchThe branch to scope to.
doc_typeThe knowledge page's type, e.g. plan, design, bug-report.
titleThe page title, when doc_type is not enough.

Slate writes only when the descriptor resolves to exactly one page. An ambiguous target is refused.

Why this isn't the only tool list

Slate exposes its operations on two surfaces: this one, MCP over stdio, which your own AI tools reach, and an in-process one that Slate's Console commands and scheduled routines call directly. The two lists differ, and each difference is deliberate — slate_capabilities has no meaning in-process, navigating Slate's own UI is not an outside tool's job, and the in-app agent keeps finer tools (search_pages, recent_activity, list_decisions and others) that its routines name. Every concept is declared once in packages/shared/src/tools/catalog.ts with the surfaces it belongs on, so that file says whether an absence was a decision.
