Tool Reference

Slate's MCP server exposes 27 tools. A short list helps a model pick the right one.

Almost every tool takes an optional cwd, your working directory. Slate resolves it to the workspace that owns the folder. slate_capabilities, recall_workspaces and workspace_doc read no local workspace.

One session works in one workspace. The first call with a cwd ties the session to that folder's workspace. After that, a call without cwd runs there too. A call whose cwd belongs to another workspace is refused with wrong_workspace and the session's workspace name: start a session in a folder of the other workspace instead. Before the first call with a cwd, a call without one gets your Personal workspace. Only live_sessions and the two cloud tools above work across workspaces. An agent run's agent reaches its task with the task's token, or from inside the task's folder, wherever the task lives.

Every tool carries the standard MCP labels: a title, whether it only reads, and whether a write can replace what is stored. None is marked as reaching outside Slate. Claude Code loads recall and remember at session start and the rest when needed.

Slate replaces recognised keys, tokens and passwords with [secret] in what an agent writes through remember, record_decision, create_doc, append_to_doc, log_mission_progress, update_my_task and the summary of report_agent_run_step. It does not do this for publish_artifact and publish_app (they carry code) or the body of report_agent_run_step.

Docs

ToolPurpose
create_docCreate a typed document: title, doc_type, user_approved:true, markdown, optional parent_id, source_ref. With no parent_id it files under the project that holds cwd, labelled with the git branch checked out there. A typed doc with no markdown is refused: Slate makes no blank docs. A second call for the same type on the same branch rewrites that doc. Refused unless the user said yes first.
get_docRead one doc by id or target: title, icon, breadcrumb path, body as Markdown. A colleague's shared doc is read with workspace_doc.
append_to_docAppend Markdown to the end of a doc, by id or target. Replies with the doc's id, title and path.

To find a doc, use recall. It searches doc titles and bodies with memory, and kind: "docs" keeps to docs.

Plain docs, renaming, moving and trashing are done in the app

A connected tool can save a typed document and add to a doc. It cannot create a plain doc, rename, move, duplicate, trash or find-and-replace in one. Those are gestures you can undo in Slate. Over MCP there is no undo. What an agent wrote through MCP can be undone when the inverse is exact: a new document goes to Trash, and a new memory is retired.

Memory

ToolPurpose
rememberSave one typed memory (kind: decision, preference, state, fact or lesson), filed by cwd and checked against what is known. A near-duplicate strengthens an existing memory. A new claim on the same slot replaces the old one. replaces names memories this one corrects, by ref, and retires them. when makes it a lesson given on a matching tool call: {tool: "shell", match} or `{tool: "read" \"edit", path}. A pattern that matches everything is refused. index: true pins it into the project's index, unindex takes refs out. The reply carries saved, the memory and up to 3 neighbours to replace. The write is refused, with the reason, when: the text is passing status, a git snapshot, or a tool call's own markup; a decision has no reason; an agent's memory holds three or more numbers (they belong in reason); a state has no subject; the project's [memory settings](../memory/decisions-and-facts.md#what-a-project-keeps) turn off that writer, kind or word; or, with AI memory care on, reason is under four words. A write in a workspace that is read-only for you fails with its reason. A line that reads as a title is kept with a warning`. A claim that contradicts a firmer memory is held for review in Memory.
recallThe one search. On a feature branch the first result is the branch brief, with the target_doc_id writes file under. Then memories, ranked lexically (BM25 over sentence, tags, citation and reason, with recency and confidence as small lifts), then docs whose title or text holds the query. Each memory is one line with its ref (m:7f3a2b1c) and citation, marked weak for a thin match and citation: changed or gone when its cited code moved. Default 8 results, 25 at most, at most half of them memories. scope: "all" searches every project. also takes up to 3 other phrasings, merged by rank. Then at most 2 artifacts that match every word, each with artifact_id, title, snippet and link. kind: "docs" searches docs only: up to 20 hits, each with a snippet. as_of (2026-08-01) answers from what memory believed at the end of that day: memories only, each later replaced one marked until.
get_memoryRead memories in full by refs (up to 20): claim, reason, citation (same, changed, gone or unchecked), evidence (which tools confirmed it) and history (what it replaced and what replaced it). Unknown refs come back under unknown.
list_memoriesFor a tidy the person agreed to: the project's memories, oldest first, up to 100 per call from offset, each with ref, kind, text and whether it is resting. Memories the person hid from sessions are left out.
propose_memory_changePropose a merge (2 or more refs into one text; up to 50 refs), a retire, a lesson (refs into one lesson text with its when), or a skill (one lesson as a skill file in the project's folder; Slate offers these itself). Nothing changes until the person accepts it under Memory → Needs review. proposal_refused for a ref outside the project (unplaced refs come back under unknown), a merge or lesson with no text, a lesson with no when, or text the save rules refuse.
log_mission_progressReport a session's work on its branch. Takes cwd and summary, plus optional branch (when the work was on another branch git knows), goal, open_items and decisions. The summary becomes a session entry of the project, the goal and open items the branch's goal and open items in the next brief, each decision a memory, all labelled with the branch. It makes no doc.

Workspaces

ToolPurpose
recall_workspacesSearch what others published across every workspace you belong to. Two halves: memory (recorded decisions, preferences and other memories, one sentence each with an author) and pages (title, doc type, author, excerpt). Default 8 of each, 25 at most.
workspace_docRead one shared doc in full, as plain text, by the id recall_workspaces returned.

These read the cloud, not your local file. They need a cloud sign-in and are read-only. For a workspace you are not in, Row Level Security returns an empty result. Signed out, they say so, because an empty result would read as "nobody has shared anything". They stay apart from recall and get_doc so you can tell which kind of knowledge you got.

Activity

ToolPurpose
activityWhat you did across every tool and project. view: "recent" (default) lists sessions newest first; days sets the window, default 1, at most 90. A session is one conversation the tool gave an id, read from the tool's own files and counted once. Each row carries the docId of its captured session doc, or of its project when it has none. view: "parked" lists branches left with UNCOMMITTED changes and not returned to, which git cannot show. stale_after_hours defaults to 48; limit defaults to 10, at most 50.

Your Tasks list

ToolPurpose
my_tasksYour Tasks list. view: "today" (default) returns your own to-dos that are overdue or due today, grouped as the Tasks tab groups them, and the first 10 open items your tools gave you, each with the key you know it by (PROJ-12, acme/api#412). view: "all" returns every open to-do and up to 100 items. Counts of what was left out come back as more_tasks and more_items. Meetings are not included: Slate keeps them only in the app's memory. The old name my_work still answers for one release.
update_my_taskAdd a line to your own list, or change one. Without an id it adds title. With one it can tick it off (done: true), reopen it (done: false), rename it, or set or clear its reminder. Give in_minutes or at (an ISO instant); clear_reminder: true removes it. A reminder rings a notification when due. A Jira, Linear or GitHub item is refused, with the tool to change it in. The old name update_my_work still answers for one release.

Apps you connected in Slate

ToolPurpose
connected_toolsThe apps this workspace connected in Connect → Integrations, such as Linear, Notion and Jira, and the tools of each that only read. app lists one. An app whose tools cannot be listed says why, for example that it needs signing in again.
read_connectedRead through one: tool is <app>__<tool> as connected_tools lists it, args are that tool's own. Slate makes the call with the sign-in it holds, so your agent needs no MCP server for the app. Reads only; a tool that writes is refused. The answer is the app's text, marked trust: "outside", cut at 20,000 characters. The same read within a minute answers from the last call.

Both need Slate open, since Slate holds the sign-in. While it is closed they answer slate_not_running. Each session reads only the apps of its folder's workspace. Your rules treat a read through Slate as a call to the app itself: a Deny of mcp__linear__* holds here too.

Other agents

ToolPurpose
handoffLeave one note for the other agents in the same project, or send it to one with to. Each sees it once, at the start of its next turn. Notes that only narrate work in progress are refused, and the refusal says so.
live_sessionsEvery AI session running on this machine now: tool, status (working / needs_you / idle), project, git repository, branch, title, last thing said, last active, goal and next unchecked item, doc id (targetDocId) and folder (cwd). To read a session's doc, pass that doc id and cwd to get_doc. Pass cwd to see only sessions in your project, and your own sessionId to leave yourself out.

An agent need not ask. When another agent works in the same project, Slate says so once at the start of a turn, with that session's own words: what it was asked and the last thing it said. A doc id comes with it.

Two agents talk by leaving notes: handoff with a to is a message, and a reply is another handoff addressed back. There is no channel, inbox or queue. A note with no to is for everyone working here. Slate carries the notes and assigns nothing.

Decisions and artifacts

ToolPurpose
record_decisionRecord a decision: title, reasoning and confidence (high, medium or low; all required), plus optional alternatives, outcome, source_ref. Writes a decision memory (confidence 0.95, 0.8 or 0.6) and a decision doc with the full reasoning. Returns the doc id and the memory's id under memory. recall returns decisions first when a question asks why.
publish_artifactPublish a doc for the person to look at, in the Artifacts tab. Send it as content (the whole doc), file_path (a file the tool wrote, inside its cwd or the system temp folder), or edits (a list of {old, new} changes to the newest version; each old must appear exactly once). A dot file, or a file in a dot folder below your home folder such as .ssh, is refused even when cwd is that folder. A cwd of the home folder or / is too wide. A new artifact needs title and kind (html or markdown). A new version passes the artifact_id a previous call returned and keeps both unless given. Optional description, and live: true so the artifact reads this workspace with slate.query (docs, a doc, memories and sessions of its project, read-only, up to 5,000 rows each). A live artifact is served with no network: no fetch, no remote images, scripts only from cdnjs, jsDelivr or unpkg. Turning live on or off adds a version. The same content again adds none. Returns artifact_id, version and link, a slate:// address that opens it in Slate, switching to its workspace. Refused with invalid_artifact: an empty title or content, a doc over 5,000,000 characters, a file outside the two folders, a dot file, a cwd that is too wide, or an edit whose old text is missing or appears more than once.
get_artifactRead an artifact before changing it: artifact_id, plus an optional older version. Returns title, kind, description, the version read, the newest version number and the full content. Without artifact_id it lists every artifact, newest first, without content. Unknown id: artifact_not_found.

An app is a different thing from a published doc, so it has two tools. Given an app's id, get_artifact and publish_artifact answer is_an_app ("This is an app. Use get_app / publish_app."). Given a doc's id, the app tools answer not_an_app and name the artifact tools.

ToolPurpose
publish_appBuild and publish an app, a folder of React files Slate builds and runs in Apps. A new app takes files ([{path, content}]) and title. A new version takes app_id and only the changed files; the rest are kept, and delete_paths removes files. A build error answers build_failed with each error's file, line and text, and saves nothing. Optional description. For an app kept in a folder, files: [] builds what the folder holds, and files sent are written into the folder too. Returns app_id, version, built_ms, published (false when no file changed), link and render: whether Slate's window ran the new version without an error or refused call (status ok, failed or pending, with problems and a one-line next on failure).
get_appRead an app before changing it: app_id, plus an optional older version. Returns title, description, the version read, the newest version number, files, folder (for an app kept in a folder), render, playbook (the steps and rules for building an app), sdk (the API the app may import, as the TypeScript declarations every build is checked against) and examples: curated (Slate's own) and yours (the workspace's other apps as { app_id, title, description }, quoted as data). Without app_id it lists every app. Unknown id: app_not_found.

Project setup

ToolPurpose
propose_setup_changeSuggest a change to the project's AI setup: kind (fix, copy, create, improve or remove), item_kind (skill, command, subagent or mcp), the item's name and evidence (the sentence the person reads). Optional tool (for a copy, the tool to add it for), file, and draft (the whole file for a create of a skill or subagent). It waits in Toolkit › Suggestions, marked with the proposing tool, and writes nothing until accepted. Refused: not_a_project when cwd is not a folder on this computer; invalid_proposal for a change that could never apply (a copy with no tool, a draft on anything but a skill or subagent create, a name that is not lower-case letters, digits, - and _); already_offered when the project had the same suggestion, waiting or answered.

Agent runs

Only for a session a Slate agent run started. Its first prompt starts "Slate task … (token)" and carries the run's token. The tools are listed in every session, as MCP requires one list per server. Outside an agent run get_agent_run answers no_task.

ToolPurpose
get_agent_runThe run's current step, its attempt and the step's instructions. Takes cwd and the token from the first prompt, or a task_id. A blocked run returns why, and tells the agent to stop and wait.
report_agent_run_stepReport the step get_agent_run gave: task_id, step and attempt from it, an outcome (done, blocked, needs_input or failed), a short summary, and an optional body as JSON text. A report for an old step is refused and names the current step.

Contract

ToolPurpose
slate_capabilitiesContract version, tools, access levels, approval policies, schema hash. Read-only, no arguments. A tool's access level is its readOnlyHint label, so the two cannot disagree.

Resolving a target

get_doc and append_to_doc take a target instead of an id:

FieldMeaning
kindbranch for the branch overview, knowledge_doc for a typed child under it.
cwdYour working directory. It anchors to the project, and to its active branch when branch is omitted.
branchThe branch to scope to.
doc_typeThe knowledge doc's type, such as plan, design, bug-report.
titleThe doc title, when doc_type is not enough.

Slate writes only when the target resolves to exactly one doc. An ambiguous target is refused.

Why this is not the only tool list

Slate exposes its operations on two surfaces: MCP, for your agents, and an in-process one that Home's commands call. The lists differ on purpose. slate_capabilities means nothing in-process, and Home's commands keep a few finer tools (recent_activity, search_content and others). packages/shared/src/tools/operations.ts declares each concept once with its surfaces, so that file says whether an absence was a decision.
