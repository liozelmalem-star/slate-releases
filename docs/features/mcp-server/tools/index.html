Tool Reference

This is the complete tool surface Slate's MCP server exposes, grouped by concern.

Pages

ToolPurpose
create_documentCreate a typed document (pre-filled by doc_type).
create_pageCreate a page in the tree.
get_pageRead one page.
list_pagesList pages, filtered.
search_pagesSearch page titles and bodies.
resolve_targetResolve a target descriptor to a concrete page.
append_to_pageAppend content to a page.

Renaming, moving, duplicating and trashing are done in the app

A connected AI tool can create a page and add to one. It cannot rename, reparent, duplicate, trash or find-and-replace inside one. Those are direct-manipulation gestures: you do them in one drag in Slate, and you can undo them. Over MCP there is no undo, and the tool cannot see what it did.

Slate's own in-app agent still does all five for you, with an undo on each.

Memory

ToolPurpose
rememberSave one typed knowledge atom (kind: decision \preference \state \fact), scoped by cwd and deduped against what's known — a near-duplicate strengthens, an update supersedes.
recallRetrieve context; returns the branch brief on a feature branch, plus repo conventions and project facts, ranked lexically (keyword coverage × recency × confidence), silent when nothing is relevant.
log_mission_progressAppend a session summary to the branch Plan page.

Workspaces

ToolPurpose
recall_workspacesSearch what other people published, across every workspace you belong to. Returns two halves: memory — their recorded decisions, facts and preferences, one sentence each with an author — and pages, with title, doc type, author and a text excerpt.
workspace_pageRead one shared page in full.

These read the cloud, not your local file. They need a cloud sign-in and are read-only — a shared page belongs to its author. When you are not a member of a workspace, Row Level Security returns an empty result rather than someone else's rows; signed out, they say so plainly instead of returning nothing, since an empty result would read as "nobody has shared anything".

Activity

ToolPurpose
recent_activityRecent sessions and events.
search_contentFTS5 full-text search over titles and bodies.
list_projectsList known projects.
activity_statsPer-project session count, tokens, and streak.
parked_workBranches left carrying UNCOMMITTED changes and not returned to. Cannot be derived from git — a commit records what landed, so work still in the index or working tree is invisible to git log.

Decisions

ToolPurpose
record_decisionRecord a decision — title, reasoning, alternatives, confidence, outcome.
list_decisionsList recorded decisions.

Tickets

ToolPurpose
get_ticket_contextResolve a Jira-style ticket id to its linked pages and branch.

Contract

ToolPurpose
slate_capabilitiesContract version, supported tools, access levels, approval policies, schema hash. Read-only discovery.

Resolving a target

Most tools don't need an explicit page id. Instead they accept a target descriptor and resolve the page from it:

FieldMeaning
kindThe kind of page to resolve.
cwdYour working directory — anchors to the right repo/branch.
branchThe branch to scope to.
doc_typeThe typed-document kind.
titleThe page title.

Pair a target with dry_run to have the tool resolve and validate the target first, before any write is applied.

Why this isn't the only tool list

Slate exposes its operations on two surfaces. This one — MCP over stdio — is what your own AI tools reach. The other is in-process: the tools Slate's Console commands and its scheduled routines call directly, without any protocol in between.

They can't share an implementation. The MCP server imports @slate/server as a library; the in-app surface speaks HTTP to it. So the two lists differ, and some of that is deliberate: slate_capabilities has no meaning in-process, and the tools that navigate Slate's own UI or schedule background runs are deliberately not an outside tool's to call.

The rest of the difference is gaps rather than boundaries — operations one surface can reach and the other simply hasn't been given yet. Every concept is declared once in packages/shared/src/tools/catalog.ts with the surfaces it belongs on and, when it's on only one, why; a test per package holds each registry to it. If a tool you expect isn't here, that file says whether it was a decision.
