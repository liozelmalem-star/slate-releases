Connecting Your Agents

Any MCP-capable tool can connect to Slate and share its memory. What the tool can then do is in the Tool Reference.

From the app: Connect → Agents

Connect → Agents lists the 16 tools. Pick the tool and the account, then switch Slate on. Slate registers itself for that config directory, so it holds for every project on this machine. Toolkit can also project MCP configs to every tool at once.

Every session talks over HTTP to the Slate app that is already running (http://127.0.0.1:47366/mcp). The entry carries a private key in a header, so Slate writes it into the tool's config file and makes the file readable by you only. Existing setups switch over on the next launch of Slate.

Slate must be running. With Slate closed, the tool lists the slate server as failed, and Slate's session-start hook says so. Open Slate and start a new session. In Claude Code, /mcp also reconnects.

By hand

The app's entry is the supported way. To write it yourself, read the key from slate-server-token, the file beside your workspace database, and keep the config file private (chmod 600). In Claude Code's ~/.claude.json:

{
  "mcpServers": {
    "slate": {
      "type": "http",
      "url": "http://127.0.0.1:47366/mcp",
      "headers": { "x-slate-token": "<the key>" }
    }
  }
}

Other tools spell it their own way: Cursor {url, headers}, Gemini {httpUrl, headers}, OpenCode {type: "remote", url, headers}, Codex url and http_headers under [mcp_servers.slate].

Claude Desktop and other stdio-only clients

Run the binary inside the app bundle, with no args:

command: /Applications/Slate.app/Contents/MacOS/slate-mcp
args:    []

That is one process per client, which is why the agents use the HTTP entry.

Verify it works

Ask your agent:

"Use the slate_capabilities tool to check the Slate contract, then use recall with query 'test' to check if Slate is connected."

An answer that mentions your workspace means it works. Empty results are fine: no matching content exists yet.

A tool can save a typed document and add to a doc, and nothing else. Renaming, moving and removing are done in the app. Saving a document of a type the branch already has rewrites that doc. Every tool carries the standard MCP labels (reads only, a write can replace, never reaches outside Slate), so a client can skip asking before a read.

A failed call answers JSON with error.code and error.message:

  • approval_required — create_doc without user_approved:true.
  • target_not_found, target_archived, ambiguous_target — a doc or branch that does not resolve to exactly one live doc.
  • invalid_request, not_found — a bad update_my_task call, or an item that is not there.
  • proposal_refused — a propose_memory_change the project's memories cannot take.
  • not_a_project, invalid_proposal, already_offered — a propose_setup_change for a folder that is not there, a change that could never apply, or one the project already had.
  • artifact_not_found, invalid_artifact, is_an_app — the artifact tools.
  • app_not_found, invalid_app, build_failed, not_an_app — the app tools.
  • wrong_workspace — the cwd belongs to another workspace than the session's (Tools).
  • no_task (get_agent_run outside an agent run); stale, closed, invalid — a refused report_agent_run_step.
  • slate_not_running — connected_tools or read_connected while Slate is closed.
  • store_unavailable — the workspace file is behind this build, so this process cannot change it.
  • internal_error — anything else, with its message.

A refused remember or record_decision is not an error. The answer says saved: false with the reason.

Memory lands in the workspace the call's cwd belongs to: your Personal workspace unless the folder belongs to a shared one. Read, edit or retire entries under Memory.

Troubleshooting

"command not found" or "no such file". Slate is not in /Applications. Install it with the command in Getting Started. From source, bash scripts/install.sh does it.

Tools appear but calls fail. The workspace database may not exist yet. Open the Slate app once. It creates ~/Library/Application Support/app.slate.workspace/workspace.db on first launch. If you moved Personal, the MCP server opens the moved file.

Running from a cloned git repository. Use node with packages/mcp/dist/index.js, built by yarn workspace @slate/mcp build.
