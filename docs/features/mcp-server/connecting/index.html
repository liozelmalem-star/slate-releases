Connecting Your AI Tools

Any MCP-capable tool — Claude Code, Cursor, Codex, Gemini, OpenCode, GitHub Copilot — can talk to Slate's MCP server and share the same long-term memory. What each of them can then do is the Tool Reference.

The easy way: Connect → AI tools

Connect → AI tools lists the six tools. Pick the tool and the account, switch Slate on, and it is registered — for that config directory, so it holds for every project on this machine.

Every session talks to the Slate app that is already running, over HTTP on your own machine (http://127.0.0.1:47366/mcp). No session starts a process of its own. The entry carries a private key in a header, so Slate writes it into the tool's config file and makes that file readable by you only. Existing setups switch over on the next launch of Slate.

Slate must be running. With Slate closed, the tool lists the slate server as failed, and Slate's session-start hook tells the agent so. Open Slate and start a new session; in Claude Code, /mcp also reconnects.

Let Toolkit project the config

You do not have to wire each tool by hand. Toolkit can project MCP configs for you: write your setup once and Toolkit materializes per-tool adapters for all five. See Toolkit.

Connecting by hand

The app writes the entry for you, and that is the supported way. To write it yourself, read the key from slate-server-token, the file beside your workspace database, and keep the config file private (chmod 600). In Claude Code's ~/.claude.json:

{
  "mcpServers": {
    "slate": {
      "type": "http",
      "url": "http://127.0.0.1:47366/mcp",
      "headers": { "x-slate-token": "<the key>" }
    }
  }
}

Each tool spells the same entry its own way: Cursor {url, headers}, Gemini {httpUrl, headers}, OpenCode {type: "remote", url, headers}, and Codex url and http_headers under [mcp_servers.slate].

Claude Desktop and other stdio-only clients

A client that takes only stdio servers runs the binary inside the app bundle, with no args:

command: /Applications/Slate.app/Contents/MacOS/slate-mcp
args:    []

That is one process per client, which is why the five AI tools use the HTTP entry instead.

Verify it is working

Ask your AI tool:

"Use the slate_capabilities tool to check the Slate contract, then use recall with query 'test' to check if Slate is connected."

You should get a response referencing your workspace. Empty results are fine — it means the connection worked and no matching content exists yet.

A tool can save a typed document and add to a page, and nothing else: renaming, moving and removing are done in the app. Saving a document of a type the branch already has rewrites that one page. Every tool also carries the standard MCP labels your AI tool reads — whether it only reads, whether a write can replace what is there, and that it never reaches outside Slate — so a client can skip asking before a read.

When a call fails, the answer is JSON with error.code and error.message. The codes are:

  • approval_required — create_document without user_approved:true.
  • target_not_found, target_archived and ambiguous_target — a page or branch that does not resolve to exactly one live page.
  • invalid_request and not_found — a bad update_my_work call, or an item that is not there.
  • proposal_refused — a propose_memory_change the project's memories cannot take.
  • not_a_project, invalid_proposal and already_offered — a propose_setup_change for a folder that is not there, a change that could never be applied, or one the project already had.
  • artifact_not_found, invalid_artifact and is_an_app — the artifact tools.
  • app_not_found, invalid_app, build_failed and not_an_app — the app tools.
  • wrong_workspace — the call's cwd belongs to another workspace than the one this session works in (Tools).
  • no_task (get_task outside an AI run), and stale, closed or invalid from report_task_step for a report it refused.
  • store_unavailable — the workspace file is behind this build, so this process cannot change it.
  • internal_error — anything else that went wrong, with its message.

A refused remember or record_decision is not an error: the answer says saved: false with the reason.

Memory is stored in the workspace the call's cwd belongs to: your local Personal workspace unless that folder belongs to a shared one. You can read, edit or retire entries in the app, under Memory.

Troubleshooting

"command not found" or "no such file" — Slate is not installed in /Applications. Install it with the command in Getting Started. If you build from source, bash scripts/install.sh does it.

Tools appear but calls fail — the workspace database may not exist yet. Open the Slate app at least once; it creates ~/Library/Application Support/app.slate.workspace/workspace.db on first launch. If you moved Personal, the MCP server opens the moved file instead.

Running from source — if you are running from a cloned git repository rather than the installed app, use node with packages/mcp/dist/index.js, built by yarn workspace @slate/mcp build.
