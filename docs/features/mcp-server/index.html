Features

Slate as an MCP Server

Slate is a workspace you edit by hand and a Console you chat with — but it has a second identity. It ships a Model Context Protocol (MCP) server that exposes your workspace and memory to any AI tool you use. Claude Code, Cursor, Codex, Gemini, OpenCode — connect them to Slate, and they all read and write the same long-term memory.

This is what "cross-tool memory" means in practice: the notes and decisions one tool writes are recalled by the next.

What it is, technically

The server is the @slate/mcp package — a Node stdio MCP server backed by @slate/server imported directly as a library (no HTTP hop). It ships as a Node SEA sidecar binary, so there is no Node install required on the machine using it. It speaks JSON-RPC over stdio, the standard MCP transport.

The recall / remember contract

The tools are built around a simple usage contract that AI clients are expected to follow:

  • Start of a task — call recall({ query, cwd }) to load prior decisions, repo conventions, project facts, and the active branch brief.
  • End of a task — call remember once with a one-line summary, the source (the calling tool's name), and cwd.

recall ranks results lexically and locally (keyword coverage × recency × confidence — no embeddings, no model call) and stays silent when nothing is relevant. remember writes one typed knowledge atom (kind: decision \| preference \| state \| fact), scoped by cwd and deduped against what's already known — a near-duplicate strengthens it, an update supersedes it.

The shared half

recall searches only what is yours. recall_workspaces and workspace_page search what your colleagues chose to share into a shared workspace — so a client can answer "has anyone here already solved this?" without anyone being asked in person.

They are deliberately separate verbs rather than a widened recall: private and shared knowledge have different trust and different blast radius, and a tool that quietly mixed them would make it impossible to tell which you got. Both are read-only, and Row Level Security in Postgres — not this server — decides what they can see.

Capability discovery

The contract is versioned. Each contract carries an id of the form slate-mcp-contract/DATE (for example slate-mcp-contract/2026-07-01). A client can call slate_capabilities to inspect the contract version, supported tools, access levels, approval policies, and schema hash before doing anything.

Clients must never call a mutating tool just to discover capabilities. Use slate_capabilities for that — it's the read-only discovery entry point.
