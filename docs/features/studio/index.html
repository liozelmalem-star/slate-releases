Features

Studio

Every AI coding tool wants its instructions in its own place and its own format. Claude Code reads CLAUDE.md and .claude/; Cursor reads AGENTS.md and .cursor/; Codex and Gemini each have their own layout. Keep them by hand and they drift.

Studio fixes that. You write your instructions and skills once, in one place, and Studio projects them out to every tool. Change the source, run one command, and every adapter is regenerated in sync.

The source of truth

Two things, both checked into the repo, are the only things you edit:

SourceRole
STUDIO.mdThe cross-tool entry point — how to work in this repo.
.studio/Everything else: studio.toml (the manifest) and skills/ (each skill's SKILL.md).

Repo owners edit only STUDIO.md and .studio/. Everything else is generated.

Generated adapters

yarn studio sync reads the manifest and materializes a per-tool adapter for each connected tool. These outputs are generated and gitignored — you never hand-edit them:

ToolGenerated paths
Claude Code.claude/skills/, .mcp.json, CLAUDE.md
Cursor.cursor/skills/, .cursor/mcp.json, .cursor/rules/studio-agents.mdc
Codex.agents/skills/, .codex/config.toml
Gemini CLI.gemini/skills/, .gemini/settings.json
OpenCode.opencode/skills/, .opencode/opencode.json, AGENTS.md

Each adapter carries the same skills and the same MCP configuration, translated into the shape that tool expects.

Commands

yarn studio sync     # materialize adapters from STUDIO.md + .studio/
yarn studio check    # fail on drift (run pre-push)
yarn studio status   # per-tool table of what's projected
yarn studio prove    # POC gate

yarn studio check is the guardrail: it fails if a generated adapter has drifted from the source, so a stale CLAUDE.md or .cursor/ can't slip into a push.

Studio is also a page in the app. The in-app Studio page lets you edit STUDIO.md and skills directly, then run Sync to tools or Prove POC without dropping to a terminal.
