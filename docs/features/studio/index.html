Features

Studio

Every AI coding tool wants its instructions in its own place and its own format, so five copies kept by hand are five copies that drift. Studio keeps one and projects it into all of them. Change the source, run one command, and every adapter is rewritten.

The source of truth

Two things, both checked into the repo, are the only ones you edit:

SourceRole
STUDIO.mdThe cross-tool entry point — how to work in this repo.
.studio/studio.toml, the manifest, and skills/ — one SKILL.md per skill.

Generated adapters

yarn studio sync reads the manifest and writes a per-tool adapter. These outputs are generated and gitignored — you never hand-edit them:

ToolGenerated paths
Claude Code.claude/skills/, .mcp.json, CLAUDE.md
Cursor.cursor/skills/, .cursor/mcp.json, .cursor/rules/studio-agents.mdc
Codex.agents/skills/, .codex/config.toml
Gemini CLI.gemini/skills/, .gemini/settings.json
OpenCode.opencode/skills/, .opencode/opencode.json, AGENTS.md

CLAUDE.md and AGENTS.md are symlinks to STUDIO.md, so the entry point stays one file however a tool asks for it. Each adapter carries the same skills and the same MCP configuration, in the shape that tool expects.

Commands

yarn studio sync     # write the adapters from STUDIO.md + .studio/
yarn studio check    # fail on drift (runs pre-push)
yarn studio status   # per-tool table of what is projected
yarn studio prove    # the full gate: sources, adapters, symlinks, live CLI probes

yarn studio check is the guardrail: a stale CLAUDE.md or .cursor/ cannot slip into a push.

In the app

The Studio page has two tabs, STUDIO.md and Skills. Save an edit on either and Slate syncs for you. The Tool status strip on the Skills tab says what each tool holds right now, with Prove and Retry sync beside it.
