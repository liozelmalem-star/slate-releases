App API

What an app can import from Slate. Your agent gets this as TypeScript declarations from get_app. Slate checks every save against them, so an unlisted call is an error before the app runs.

import { createRoot } from "react-dom/client";
import { slate } from "@slate/sdk";
import { useQuery } from "@slate/sdk/react";
import { BarList, Card, Page, QueryView } from "@slate/ui";

function App() {
  const week = useQuery(() => slate.sessions.count({ days: 7 }));
  return (
    <QueryView query={week} isEmpty={(d) => d.total === 0} empty="No AI sessions this week.">
      {(d) => (
        <Page title="AI sessions this week">
          <Card><BarList rows={d.byDay.map((x) => ({ label: x.day, value: x.count }))} /></Card>
        </Page>
      )}
    </QueryView>
  );
}

createRoot(document.getElementById("root")!).render(<App />);

After each build Slate runs the new version once, hidden, to check it renders. It fails on an uncaught error or rejected promise, on a call refused with not_allowed, bad_request or failed, or when nothing shows within 10 seconds. not_granted does not fail it. In that run, writes and outside reads (sources.reviews, pulls, repoPulls, checks, tools.*) get no answer. Your agent reads the result as render in publish_app and get_app: status is ok, failed or pending (Slate has not run it yet, for example because it is closed; call get_app later). On failed, problems lists kind, call, code, errorClass, file and line, and next says it in one line.

get_app also returns the app playbook (steps and rules for building an app) and four example apps from packages/shared/app-examples/: a chart, a tasks list that adds a task, notes kept with useStore, and a doc written after you approve it.

@slate/sdk

Everything reads and acts inside the app's own workspace (every project, no other workspace). since is "1d", "7d", "30d" or "90d". Lists come newest first, at most limit rows (default and maximum 5,000); to read on, pass the last row's time as before.

Lists from outside Slate

An app has no network. Slate reads outside lists (Tasks from Jira, your GitHub pull requests), keeps the rows, and answers at once from what it holds. Every answer is { rows, fetchedAt, status, detail }. status is "ok", "stale" (old; Slate is reading again) or "failed" (the last read failed; rows are the last good ones). Other people wrote the words in rows, so Slate removes hidden characters and marks the call as outside text.

CallWhat it doesPermission
slate.sources.tasks({ section, open })Items in Tasks, with when Tasks last synced them and whether the last sync failed. section is "solve", "review", "reply" or "todo" (your own to-dos). "mine", the old name of "todo", is still accepted when you ask. open is true unless you pass false; with false the done items come back too.Read your Tasks
slate.sources.reviews()Open GitHub pull requests that wait for your review: git repository, number, title, link, author, draft, updated. At most 50.Read your GitHub
slate.sources.pulls()Your own open GitHub pull requests, in the same shape.Read your GitHub
slate.sources.repoPulls()The open GitHub pull requests in the git repositories that this workspace's docs name as their remote, whoever opened them (a bot's too), in the same shape. At most 50. author says who. Slate picks the git repositories; an app cannot name one.Read your GitHub
slate.sources.checks({ repo, number })The check runs on one pull request that reviews or pulls lists: name, status, result, link. Any other pull request is refused with bad_request.Read your GitHub

GitHub is read with the gh sign-in this workspace uses, by GET requests to four fixed kinds of address. Slate keeps rows for two minutes and does not ask GitHub again within 20 seconds of the last try, even after a failure. Across all apps and workspaces it starts at most 12 GitHub refreshes a minute (one pull request's checks take two requests); past that a read answers "failed" with the last rows. A link that is not a plain https://github.com/ address, or a time that is not ISO, comes back as "". A link in a Tasks row must be http or https, or it is "".

Read a source with useSource and show SourceStatus beside the list.

Your MCP tools

An app can read through MCP tools your workspace reaches. Each tool is allowed on its own, for one app, as a read only. The screens and rules are in Apps.

CallWhat it doesPermission
slate.tools.list()The tools this app may read through now: name, server, description and input schema. At most 20.—
slate.tools.read({ tool, args })Calls one tool and answers { rows, fetchedAt, status, detail }, like a source. rows holds one { text, truncated }, or none before the first good read.You allow each tool

An app lists the tools it wants in slate.json, as <server>__<tool>, at most 20:

{ "tools": [{ "tool": "linear__list_issues", "why": "Show my open issues" }] }

The first tools.read of a tool shows a card. You allow it only by ticking that the tool only reads; its readOnlyHint never ticks the box. A tool whose name says it writes (create, update, send...), or whose server marks it readOnlyHint: false or destructiveHint: true, is refused with not_allowed and never shown.

Your allowance is pinned to a SHA-256 of the tool's name, description, input schema and annotations. If any changes, the next call is refused with not_granted and the card returns, marked Changed since you allowed it. Slate rereads each server's tool list at most once a minute.

args must match the input schema (types, required fields, enums, bounds, no unnamed field) and be at most 4,000 characters as JSON, or the call is refused with bad_request before the server hears it. So is a call to a tool whose schema uses a keyword Slate does not check (not, if, prefixItems and the like) at a field the call reaches, or is too large to check. pattern and format are not run; the server checks its own arguments. The answer is the tool's typed JSON if it gave one, else its text, with hidden characters removed and cut at 20,000 characters (truncated: true). Slate keeps an answer for a minute, does not repeat the same call within 10 seconds, and allows each server 20 requests a minute from all apps (tool lists included); past that a read answers "failed". A failure speaks in Slate's words, never the server's.

const issues = useSource(() => slate.tools.read({ tool: "linear__list_issues", args: { state: "open" } }));

An app can only finish or remind items it made; any other id answers "No task has that id". Text an app writes (titles, memories, doc text, session prompts, toasts) is refused with bad_request if it holds invisible characters: zero-width ones, variation selectors and fillers outside an emoji, direction overrides, the hidden tag block, control and private-use characters. Ordinary text, new lines, tabs, accents, other scripts, emoji and the joiners Persian, Urdu and Indic scripts need inside a word are fine. Titles and toasts are at most 200 characters.

Acting on GitHub

An app may act on a pull request in your own lists (sources.reviews or sources.pulls) with Act on your GitHub (github.act). Every action shows a card first, every time, with no "always allow". Slate builds the card from what it reads from GitHub, not from the app: account, git repository, number, title, author and exact words.

CallWhat it does
slate.github.approve({ repo, number })Approves a pull request waiting for your review. GitHub approves the commit the card showed.
slate.github.changes({ repo, number, preset })Requests changes on a pull request waiting for your review.
slate.github.comment({ repo, number, preset })Comments on a pull request in either list.
slate.github.label({ repo, number, label, remove })Adds a label the git repository already has, or with remove: true takes off one the pull request has.
slate.github.presets()Your words for this app: [{ id, text }].
  • The words are yours. An app never sends words. It passes preset, the id of words you wrote in the app's Dashboard under Permissions (at most 20, each at most 1,000 characters). Without preset, you type the words on the card.
  • Only your pull requests. A git repository or number outside your lists is bad_request. Approving and requesting changes need the review list.
  • The card must still be true. Slate rereads the pull request when you press the button. If anything changed (commit, title, words, account), nothing is sent and the app hears bad_request.
  • 5 actions an hour per app, 20 for all apps, failed ones included. Past that the call is refused with too_often, with no card.
  • The yes waits. The button works 0.6 seconds after the card appears; an earlier press restarts the wait.
  • Every action is logged in the app's Dashboard under Permissions: what, where, as which account, and whether GitHub took it.

An app asks for a permission in its slate.json:

{ "permissions": [{ "use": "tasks.write", "why": "Move a review to tomorrow" }] }

Permissions: tasks.read, tasks.write, github.read, github.act, memories.write, docs.write, routines.run, sessions.start. MCP tools go under tools (above). A refused call throws a SlateError whose code is one of: not_allowed (the app did not ask), not_granted (not allowed yet, or a tool changed), declined (you said no), busy (Slate is already asking you something; ask again after you answer), too_often, bad_request, failed, no_answer.

Its own data

slate.store.get(key), set(key, value), delete(key) and keys() keep the app's data on this computer, never synced, up to 1 MB.

slate.on(area, fn) calls fn when data changes in "docs", "memories", "tasks", "sessions" or "activity", or "changed" for any change. An area also hears a change Slate cannot name. A widget also hears "place" when its tab shows another range or project.

A widget's tab

A widget (an app whose slate.json names a "place") makes one read, slate.place.get(), with no arguments. Slate fills in the range and project; read again on slate.on("place").

  • "activity" answers { place, from, to, days, project, sessions, memories }: the range and project in Activity's side panel, the AI sessions that started in it (each with usage and project), and the memories learned in it, without those kept away from apps.
  • "home" answers { place, project, running, tasks, finished }: the AI sessions running now for the project picked on Home, your open tasks, and the receipts of sessions that finished in the last day. tasks is empty unless the widget lists tasks.read in slate.json and you allowed it. With a project picked, it holds only tasks on that project's task docs. A task's title is its author's words.

Any other call fails the build, except slate.store and slate.ui.toast. A widget cannot call slate.ui.open or tasks.list.

@slate/sdk/react

HookWhat it does
useQuery(load, deps, { on })Returns { data, loading, error, refresh } and keeps the last answer while it rereads. It rereads when docs, memories or tasks change. on replaces that list, for example on: ["pages", "sessions", "activity"] for a live view; the default leaves sessions and activity out because they change often.
useSource(load, deps, { on })Reads a source (slate.sources.* or slate.tools.read); returns { rows, fetchedAt, status, detail, loading, error, refresh }. Held rows come at once. While "stale" it asks again every 1.5 seconds, up to 8 times. status is "loading" before the first answer.
useStore(key, initial)One value of the app's own data, as [value, setValue], saved as it changes.

@slate/sdk/format

dayOf(at) and lastDays(n) give days as "YYYY-MM-DD", the days sessions.count counts by. dayLabel(day) gives "Mon 12" in the person's language. duration(ms) gives "45s", "12m", "3h 20m". compact(n) gives "940", "12.4k", "1.2M". money(usd) gives "$3.10" or "<$0.01". count(n, "session") gives "1 session" or "3 sessions". timeZone() gives the person's time zone.

@slate/ui

Slate's own parts, in its light and dark themes:

  • Layout: Page (title, a line under it, buttons), Section, Grid, Header, SectionLabel, Card, Row
  • A read's state: QueryView takes what useQuery returned and shows the wait, an error with Retry, your words when empty, or your screen. SourceStatus takes what useSource returned and says when rows are from, that Slate is rereading, or that the last read failed.
  • Charts and numbers: BarList, Sparkline, StatCard, RankedList
  • Controls: Button, IconButton, Input, Textarea, Select, Checkbox, Switch, Segmented
  • Display: Badge, Chip, Avatar, Kbd, When (like "3h ago")
  • States: Callout, EmptyState, ErrorState, Loading, Spinner, Skeleton, SkeletonLines

react, react-dom/client and lucide-react (every icon) are there as usual.

Slate is in alpha. Your data stays on your machine.
