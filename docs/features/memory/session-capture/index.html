Session Capture

Memory is only useful if it fills itself. Slate captures your AI sessions automatically: a watcher reads the conversation files coding tools already write to disk, detects completed sessions, and stores each one as a page in your workspace.

Claude, Codex, Gemini and Cursor write JSONL transcripts, and the watcher recognizes them on its own. OpenCode writes none — it keeps its sessions in SQLite — so Slate reads ~/.local/share/opencode/opencode.db read-only and renders each session into the same shape. One set of rules then applies to every tool: the same digest, the same noise filtering, the same branch attribution. There is nothing to configure for any of them.

New tools and non-default configs

Those five are a seed, not a fixed list. The watcher also discovers any AI tool that writes JSONL transcripts under your home directory: it looks for a hidden config folder holding a subdirectory (projects, sessions, chats, tmp, …) whose files parse as a role-tagged transcript. Two things fall out of that:

  • A brand-new tool you install is captured with no registration.
  • A non-default config directory — running Claude under ~/.claude-personal, say — is picked up as well as the default ~/.claude.

Nothing is registered by hand. Folders that never hold transcripts, ~/.config and ~/.ssh among them, are skipped.

What a captured session looks like

Each session becomes a page with structured properties:

PropertyMeaning
promptThe originating request for the session.
summaryA one-line summary of what happened.
toolWhich AI tool produced the session.
tokensToken count for the session.
sessionIdStable id linking the session back to its conversation.
kindsession when a sessionId is present, note when it is not — derived, never asserted.
modelThe model that ran.
branchThe git branch the work happened on.

The page body carries the session's digest — every real human turn (the asks and the mid-session course-corrections, where decisions live) plus the final outcome. A session's important decisions are usually made in the middle, so recall needs more than the opening prompt to find them. For a session on a git branch, the digest page is filed under the branch and linked from its session log.

The branch comes from the transcript when the tool records one (Claude Code does). For the tools that don't, a freshly captured session falls back to the repository's current branch. Historical back-fill stays repo-level rather than stamp an old session onto today's checkout.

remember writes each atom's readable page through the same writer, and such a page has no conversation behind it — no sessionId, no tool. That is why kind is derived from the sessionId: a conversation has an id you resume it by, and a note does not.

A captured session opens as a read-only record of what happened, not a page you edit.

Other tools' own memory

Claude Code, Gemini CLI and Codex each keep a memory folder of their own, and none of them reads another's. The watcher reads those folders too, so what one tool learned reaches the others:

ToolFolderFiled under
Claude Code<config>/projects/<project>/memory/*.mdThe project the session transcripts beside it name.
Gemini CLI<config>/tmp/<name>/memory/*.mdThe folder projects.json maps to <name>.
Codex<config>/memories/*.mdGlobal: Codex keeps these per user, not per project.

Each file becomes one memory, written by that tool, citing the file. A changed file replaces its memory, and a deleted file retires it. Index files (MEMORY.md and Codex's summaries) are skipped. Slate only reads these folders; it never writes to them, because each tool rewrites its own files.

Keeping the watcher running

Capture runs inside Slate and stops when you quit. Sessions you run while it is closed are picked up the next time you open it — a historical scan catches what the live watchers missed. The switch is in Connect → Automations.

The watcher reads files already on your machine and writes only to your local workspace. Session capture sends nothing to the network.
