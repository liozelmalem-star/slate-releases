Session Capture

Slate captures the AI sessions of the tools you turned on. A watcher reads the conversation files those tools already write, detects completed sessions and stores each as a doc in your workspace.

A tool is read only after you turn it on, in setup or Connect → Agents. An installed tool that is not on is not read, and its sessions do not appear in Sessions. Turning one on later brings in its sessions on the next pass, a few minutes at most.

Claude, Codex, Gemini, Cursor and GitHub Copilot write JSONL transcripts, and the watcher recognizes them. Copilot writes one folder per session, ~/.copilot/session-state/<session id>/events.jsonl, and Slate names the session by its folder. OpenCode keeps sessions in SQLite, so Slate reads ~/.local/share/opencode/opencode.db read-only and renders each session into the same shape. One set of rules then applies to every tool: the same digest, noise filtering and branch attribution. Beyond turning a tool on, nothing needs configuring.

Hermes Agent, Goose, Kilo Code and Kiro also keep sessions in SQLite, and Slate reads those databases read-only. Capture is measured on Claude Code, Codex, Cursor, GitHub Copilot, OpenCode, Gemini, Hermes Agent and Goose. For the other eight it is unverified or not built yet: Features by Agent has the cell for each.

New tools and non-default configs

Those five are a seed. The watcher also finds any agent that writes JSONL transcripts under your home directory: a hidden config folder holding a subdirectory (projects, sessions, chats, tmp, …) whose files parse as a role-tagged transcript. So:

  • A new tool you install is captured with no registration.
  • A non-default config directory, such as Claude under ~/.claude-personal, is picked up as well as ~/.claude.

Folders that never hold transcripts, such as ~/.config and ~/.ssh, are skipped.

A cloud session brought back

A cloud session runs on the vendor's computer, where the watcher cannot see it. When you bring it back and send it a message, Claude Code writes its whole conversation into a normal transcript under the worktree it came back into, and the watcher captures it. Claude writes nothing before that first message, so a task brought back and never used is not captured. The cloud part had none of Slate's hooks, so it arrives as a record of what was said, not as saved memories. A Codex cloud session brings back changes, not a conversation. Applying it notes the task on its project's doc, with how many files and lines changed.

What a captured session looks like

Each session becomes a doc with these properties:

PropertyMeaning
promptThe originating request.
summaryA one-line summary.
toolThe agent that produced the session.
tokensFresh input, cache writes and output, each model response counted once.
sessionIdStable id linking the doc to its conversation.
kindsession when a sessionId is present, else note. Derived, never asserted.
modelThe model that ran.
branchThe git branch the work happened on.

The doc body is the session's digest: every real human turn (the asks and mid-session course-corrections, where decisions live) plus the final outcome. For a session on a git branch, the doc is filed under the branch and linked from its session log.

branch comes from the transcript when the tool records one (Claude Code does). For the others, a freshly captured session uses the project's current branch. Historical back-fill stays project-level, so an old session is not stamped onto today's checkout.

remember writes each memory's readable doc through the same writer. Such a doc has no conversation, so no sessionId and no tool. That is why kind comes from the sessionId: a conversation has an id you resume it by, and a note does not.

A captured session opens read-only. Under its title it says Session — read only.

Other tools' own memory

Claude Code, Gemini CLI and Codex each keep a memory folder, and none reads another's. The watcher reads those folders too, so what one tool learned reaches the others:

ToolFolderFiled under
Claude Code<config>/projects/<project>/memory/*.mdThe project the session transcripts beside it name.
Gemini CLI<config>/tmp/<name>/memory/*.mdThe folder projects.json maps to <name>.
Codex<config>/memories/*.mdNot read: Codex keeps these per user, with no folder to add.

A project's memory file is read only once its folder is inside a project or group you added. Until then it is skipped, and the next pass after you add the folder reads it. Memories already read stay.

Each file becomes one memory, written by that tool, citing the file. A changed file replaces its memory, and a removed file retires it. Index files (MEMORY.md and Codex's summaries) are skipped. Slate never writes to these folders, because each tool rewrites its own files.

Keeping the watcher running

Capture runs inside Slate and stops when you quit. Sessions run while it is closed are picked up at the next launch: a historical scan catches what the live watchers missed. The switch is Auto-capture in Automations › Built-in. Off stops capture at once and stays off after a restart. The capture hook and the local capture port that scripts can post to follow the same switch.

The watcher reads files already on your machine and writes only to your local workspace. Session capture sends nothing to the network.

Turning capture off for one project

A project's Memory settings can turn Capture sessions off. Sessions in that project's folder are then not saved as docs, whichever way they arrive (watcher, capture hook or local capture port), and the agents' own memory files there are not read. Turning it back on resumes where it stopped. See What a project keeps.
