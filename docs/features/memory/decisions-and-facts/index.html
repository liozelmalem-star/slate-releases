Decisions & Facts

Slate's long-term memory holds two distinct kinds of knowledge. A decision is a choice you made, recorded with its reasoning. A fact is a durable piece of knowledge that stays true across tasks. Keeping them separate matters: you recall facts to know what is so, and you review decisions to know why you chose what you did.

Decisions

A decision is a logged choice with rationale. Record one with record_decision:

FieldMeaning
titleWhat was decided.
reasoningWhy.
alternativesThe options that were considered and rejected.
confidenceHow sure you are.
outcomeHow it turned out.

List them back with list_decisions. Decisions are also where remember routes anything it detects as a decision — onto a Decision page and the branch's Decisions section.

Facts

A fact is persistent knowledge — not tied to a single session, and not a choice, just something durable about the project or your preferences. Each fact carries:

AttributeMeaning
textThe knowledge itself.
kinddecision, preference, state, or fact.
confidenceHow strongly it's held; strengthened by near-duplicates.
statusactive or superseded.
subjectThe slot it asserts about, when it has one — see Slots.

Facts are ranked lexically when recall runs — keyword coverage weighted by recency and confidence, no embeddings and no model call — so the ones most relevant to your query surface first. The status field is how facts age: knowledge that no longer holds is superseded by whatever replaced it, and overlapping facts can be merged, without deleting the record.

Slots — how a fact replaces another

A preference and a state are single-valued: you hold one preference per axis, and a thread is in one state. So when a new one arrives, the old one should not sit beside it — it should be retired. Deciding that by similarity does not work: "dark theme" and "light theme" share no words at all, and a contradiction often looks more similar than a restatement.

A slot settles it without guessing. It is a stable dotted key naming the axis — ui.theme, deps.db-boundary, branch.slate.main.state — and a later fact on the same slot retires the earlier one, deterministically.

Slate works the key out for you. It is not something you or your AI tool has to supply. A subject that is not a well-formed dotted key — a branch name, a dated snapshot, a title with spaces — is discarded rather than stored, because a key that can never recur can never supersede anything; the fact is simply deduped by similarity instead, which is the ordinary path. Where a fact clearly belongs in a slot the workspace already uses, Slate places it there; where it is ambiguous, it leaves it alone. Decisions and plain facts never take a slot at all — they accumulate, because superseding them would throw away knowledge that is still true.

Decision vs. fact, in one line

  • Decision — "We chose X over Y because Z." A choice, preserved with its rationale.
  • Fact — "The project uses X." A durable statement, ranked and recalled by relevance.

Facts Slate writes for itself

Almost every fact is written by an AI tool calling remember. One is not: Slate derives a state fact for each branch that is carrying uncommitted work, from the same activity log behind Parked work — one per branch, on a slot named branch.<repo>.<branch>.state, refreshed whenever the server starts. (The key carries the branch name exactly as git spells it, a / in feat/foo included — a slot key is an identity, and rewriting it would point the next boot at an empty slot.)

It writes only that case on purpose. A branch whose work has all landed would produce "stands at <sha> \<message\>" — which git log -1 already answers, and a memory store earns nothing by restating git. Work still sitting in your index or working tree is the opposite: no commit records it, so nothing else can tell you it is there.

Because the slot is named, the newest reading supersedes the previous one rather than accumulating beside it, and a branch you return to and commit simply stops producing a fact. State facts also expire from ranking after 14 days, so a branch you abandon fades out on its own.

Is the corpus still worth trusting?

Facts accumulate for as long as you use Slate, and two ways of going bad are invisible from the outside. Corpus health — a widget on the Activity dashboard — measures both and can repair them.

An atom filed under a page you deleted. A fact's scope is a page, and recall reaches facts by walking the page tree. Delete the page and the fact is not wrong, it is unreachable: no search will return it again, and nothing says so. The repair moves it to the same fallback scope a session with no recognised project writes to, which puts it back in reach.

A citation that stopped resolving. A fact can carry a source_ref like path/to/file.ts:98, and the whole point of that citation is that your AI tool checks it before trusting the claim — the repo is the source of truth, the memory is not. Once the file moves or goes, that check costs a lookup and teaches nothing; worse, paths get reused, so an old ref eventually resolves against a file with nothing to do with the claim. The repair drops the citation and keeps the claim, which is what an uncited fact always was.

The check is deliberately cautious about what it calls broken. A citation whose project folder is not on this machine is reported as not judged, never as stale — that is a fact about this computer, not about the atom. Press Show what would change before repairing; it lists the files it could not find, which is what tells you the check is right.

The panel also reports things it will not touch, because each is a judgement rather than a fault: facts recall has never returned, facts longer than a sentence, facts with no tags, and exact duplicates. That last one is the health check on the write path — dedup runs on every write, so a duplicate count that starts climbing means something stopped working.

Nothing here runs on its own. Whether a citation resolves depends on what is checked out right now, so a repair that swept at startup would strip good citations the first time you worked from a different checkout.
