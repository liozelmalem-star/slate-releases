Recall & Remember

Slate's memory loop is two verbs. At the start of a task an AI tool calls recall to load context; at the end it calls remember once to save what it learned. Everything else — capture, routing, ranking — is built around those two calls.

recall — load context at task start

recall({ query, cwd })

Given a query and your working directory, recall returns the context that matters for the task ahead:

ReturnedWhen
Branch briefWhen cwd is on a feature branch — what this branch is for and its progress.
Repo conventionsAlways — the conventions Slate has learned for this repository.
Project factsAlways — durable facts about the project.

Results are ranked lexically and locally — keyword coverage between your query and each atom, weighted by recency (a 30-day half-life) and confidence. There are no embeddings and no model call; the ranking is deterministic. A coverage threshold keeps recall silent when nothing is genuinely relevant, so it never pads the context with noise.

remember — save what you learned at task end

Call remember once, at the end of a task, with a concise one-line summary. Each call writes one typed knowledge atom — the unit every AI tool shares:

kindWhat it captures
decisionA choice you made ("chose X over Y because Z").
preferenceA durable working preference.
stateA durable fact about where things stand.
factA durable piece of project knowledge.

The atom is scoped to your project via cwd and deduped against what's already known — a near-duplicate strengthens the existing atom, an update supersedes it. You don't route anything by hand: the atom is the destination, and it's recalled first by every tool. remember also appends to the branch's human-readable page so you can read the memory back.

kind is optional — omit it and Slate infers it from the text. Preferences and states additionally get placed in a slot when the workspace already has one that clearly fits, which is what lets a new preference retire the one it contradicts instead of sitting beside it. That is worked out for you; there is nothing to pass.

Logging progress mid-mission

Between the start and end of a longer piece of work, log_mission_progress appends a session summary to the branch's Plan page, so a mission accumulates a running record of what happened.

The contract usage pattern

The tools expect a simple, disciplined loop:

START a task  → recall({ query, cwd })
… do the work …
END the task  → remember(one-line summary, source, cwd)

source is the calling tool's name and cwd is your working directory. Call remember once per task, not per step — one summary when the work is done.

Because every AI tool follows the same contract, work done in one tool is recalled by the next. That shared loop is what makes Slate's memory cross-tool.
