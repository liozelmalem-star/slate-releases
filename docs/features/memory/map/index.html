Memory Graph

Memory opens on the graph: every memory of the projects on screen, on the files it is about, coloured by whether your sessions use it. The list beside it is where you read, search, correct and retire them.

With no memory yet, Memory says Nothing saved yet (Memories appear here as sessions end) with a Connect an agent button.

Memory opens on All projects. Once you pick a project, it opens on that one next time. When memories wait for review, the Memory icon on the rail shows how many.

Under the project picker, Graph | Rules switches the view. On Rules, the list shows your memory rules (which memories your agents get), grouped by where each holds. The main area shows the one you pick, to change it. + in the side panel's title adds a rule. See Rules.

The graph

Each folder is a country, a tinted region with its name, memory count and the share sessions used: server 213 · 3% used. The name sits mid-country, or at its coast when a memory sits in the middle. A folder that holds most of the project opens into its own folders, so packages shows as ui, server, desktop and so on. Memories citing the folder itself keep a town of their own. Folders with fewer than 12 memories share one country, Other. Memories that cite no file live on one island with a dashed coast, General. On All projects each project is one country, never opened and never put into Other. A country's area grows with its memory count. Every country is drawn in the open workspace's colour; its label tells it from its neighbours.

  • Each memory is a dot in its country, gathered by the file it cites. A solid, bright dot was used by a session this month or is new this week. A faint hollow ring was never used. A country full of hollow rings is dead weight you can clean up.
  • No lines. What sits inside what is the whole structure.
  • Click a country to go in. The map redraws with that country alone, and every file with three or more memories is named and ringed. The list shows only that country's memories and follows them: a memory a session writes there joins the list. If a retire or project switch makes the country disappear, map and list both go back out. The path at the top left (slate › server), a click on empty space, or Escape leads back out. Escape first closes whatever is in front, such as ⌘K or a field you are editing.
  • The counts are lenses. Click one in "80 used this month · 984 never used · …" to light only those memories and keep only them in the list. Click again to see all.
  • One session's memories. A session in Sessions says how many memories it was given, used and wrote. Click that line and Memory shows exactly those, with a row naming the session: "Showing “…” — 3 given · 1 used · 2 written". Clear, or picking a use filter, shows everything again.
  • Graph and list are one selection. A row in the list goes into that memory's country and opens its card. A dot on the graph scrolls the list to its row.
  • Pick a memory to open its card. It shows how the memory travels ("Given to 57 sessions, used in 0 · used 1× · last 2026-09-26"), the file it cites, what your merges, reverts, discards and edits said about it (each dated, with an undo; see What agents know about the file), what it replaced, other memories on the same file in the project, and any likely duplicate with Merge. From the card you can:
  • Pin it, so every session in its project starts with it.
  • Hide from sessions (undone with Give to sessions again). It stays in Memory, but no reply a connected agent reads carries it: not recall, briefs or the index, nor remember's neighbours, get_memory, list_memories, lessons or handoff notes.
  • Protect it, so AI memory care never reads it and Retire all never takes it.
  • Retire it, and Bring back.

Each can be undone from the same place. List rows offer the same actions as icons and show "hidden from sessions" or "protected".

The map holds still: no zoom, pan or scroll. It shows the whole map or one country, fitted to the panel. On the whole map a click goes into a country, even over a dot, because a dot that small cannot be aimed at. Inside a country a click on a dot opens its card. The same memories always land in the same place, and the map does not move while sessions write new ones.

The list beside it

The search at the head of the list needs every word you type to appear in the memory's text, tags, cited file or m: ref. The graph lights the matches.

Both the graph and the list follow one scope: the project picker at the head of the side panel. The Kind menu over the graph counts each kind (577 facts, 389 decisions, 40 status notes, a status note being kind state) and keeps only that kind in the list. Every kind clears it. It filters the list only, not the graph.

Each row shows a memory's kind, about two lines of text and the day it was last confirmed. It marks cited file gone when recall is holding the memory back. Click a row to open its card on the graph with the whole text and every action. Edit changes it in a growing text box, then Save (⌘Enter) or Cancel (Esc). The card also shows:

  • its ref (the m:… a session cites it by);
  • who wrote it (you or the agent);
  • how often it was confirmed and by whom ("confirmed 2× by Codex");
  • how often sessions used it, and in which tools ("used 3× in Gemini, Claude Code");
  • what it replaced.

Pin puts the memory in its project's index for every session. Retire session retires everything the session behind it wrote, after a preview. Bring back on a retired memory makes it active again unless a newer memory replaced it. That includes a memory AI memory care retired.

Retire a whole list at once. Under never used or not used this month, Retire all first says how many memories it will retire. Pinned and protected memories always stay and are counted apart ("· 1 protected stays"). Undo brings them all back in one step. Retired memories stay in the store. The retired chip over the graph shows what was retired in the last 30 days that nothing replaced (up to 50), in the picked project, each with Bring back. A status note that lapsed after 14 days was never retired and stays in the main list. The chip is for a retirement whose Undo is gone, or one AI memory care made overnight.

Likely duplicates. When two memories say nearly the same thing, the line above the graph says so. Click it to list only those. Click one to open its card with Merge.

Filters. Every filter that narrows the list (use count, country, kind, search words, likely duplicates) is a chip on one Filters: line. Click a chip to drop it, or Clear all. With no match the list says "No memory matches these filters." and, inside one project, offers Search all projects.

Claims that contradict a firmer memory, and the merges and retirements a tidy session proposed, wait at the top under Needs review. See Needs review and Repairing memory by hand.

Needs review

Above the card, Learned this week says in one line what Slate learned in the last seven days: memories you accepted, lessons that became skills, decisions an agent run closed, and declines it kept, with how many were said more than once. Bring that number down: the same no said twice means a lesson did not reach the agent, agent run or app that needed it. The line also says what your own acts taught, for example 3 memories confirmed by your merges, 1 contradicted by a revert: your merges confirmed, your reverts and discards contradicted, and your edits asked about again. An act you undid is not counted. A quiet week draws no line.

Memory care sits above Needs review: one line saying whether AI memory care is on in this workspace and, after a night, how many memories it retired ("Memory care · 16 retired last night"). Click it for its card, with the switch, what a night costs, the monthly token cap and how much is used. It is the one automation each workspace chooses for itself, because it spends that workspace's agent tokens. The rest are in Settings → Automations.

Needs review is the next row when something waits: one amber line with the count ("15 to review"). Click it to open it. One line says what waits and who proposed it ("12 merges and 3 retirements, proposed by Claude Code (14) and memory care (1).") and how many claims disagree with a surer memory. Accept all applies every waiting proposal at once, and Undo takes the batch back. A lesson that became a skill is named, and the name opens the skill in Toolkit. Each proposal and disagreement has its own buttons. Click the row again to close it.
