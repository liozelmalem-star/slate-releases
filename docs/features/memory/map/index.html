Memory Map

The Memory Map is a visual view of what Slate remembers: the whole corpus at once, every atom placed by what it says, dense areas raised into contours, and the busiest regions named after the words that distinguish them.

The map is the stage and the list is the pane beside it, both on screen together, driven by one scope picker. The list is where you read, correct and retire an atom; the map is where you see the shape. Each row in the list shows its ref (the m:… a session cites it by), who wrote it (you, or the AI tool), how often it was confirmed and by whom ("confirmed 2× by Codex"), how often sessions cited it and in which tools ("cited 3× in Gemini, Claude Code"), what it replaced and until when ("was “…” until 2026-08-03"), and marks cited file gone when recall is holding it back. The pin on a row puts the fact in its project's index for every session. Retire session retires everything the session behind a row wrote, after a preview. Claims that contradict a firmer memory, and the merges and retirements a tidy session proposed, wait at the top under Needs review. See Repairing memory by hand. It draws the same facts and decisions that recall reads and remember writes — change the data and the view follows.

How to read it

  • Position is meaning. Two atoms sit near each other because their text is similar — weighted so that words the whole corpus repeats stop counting as evidence — or because they cite the same place in your code. A shared citation counts even when the wording shares nothing.
  • The outer ring is everything unconnected. Atoms that relate to nothing else Slate knows are placed in a band around the edge, drawn smaller and fainter. Two of them side by side means nothing, and they raise no contours. A large ring means much of what you have written stands alone, and usually wants a citation or a rewrite.
  • Contours are density. The nested rings mark where Slate knows the most. Open ground is where it knows little.
  • Colour and shape are kind. A fact is a circle, a decision a filled slab, a preference a hollow one, state a pair — the same vocabulary as the chips above the map. Those chips filter the list only: the map draws each kind as its own form, so hiding a kind would leave shapes that no longer match the legend.
  • Size is recall. An atom grows with how often it has actually been used.
  • Retired atoms stay, faintly. Where the corpus used to be dense is part of what the map has to say.

Zoom in past a certain point and every atom takes its own label; below that, the region names are the right level of detail. Click an atom to pin its card — edit the text, retire it, open the session that taught it, or merge a duplicate.

Positions are stable

An atom keeps its place. Open the tab tomorrow and the sync material is still over on the left. That is what makes the map navigable from memory instead of re-read from scratch.

Slate recomputes the layout whenever the corpus changes, then turns, flips and resizes it onto the previous one, so the same knowledge lands in the same place. An atom still moves a long way when it stops being alone: add a citation, or write a second atom about the same file, and it leaves the outer ring for its new neighbours.

The other case is an update to Slate that improves how atoms are placed. Old positions cannot be carried over then, because fitting the new layout onto the old one would reproduce what the update was meant to fix. The first time you open Memory after such an update the map recomputes once and everything moves; after that it is stable again.

When it is catching up

Placing a thousand atoms takes about a second, so Slate never does it while you wait. Opening the tab shows the coordinates it already has and recomputes behind you; a small "placing new atoms" note appears while that happens, and the map sharpens when it lands. Atoms written since the last layout are not drawn yet — Slate would rather leave one out for a moment than guess a position and move it later. A memory saved while the map is open joins the list at once and asks for a new layout, so it is placed when that lands.
