Memory Graph

Memory opens on the graph: every memory of the project on screen, on the files it is about, coloured by whether your sessions use it. The list beside it is where you read, search, correct and retire them.

The graph

The graph is a map. Each folder is a country — a softly tinted region with its name, its memory count and the share sessions used: server 213 · 3% used. A folder that holds most of the project is opened into its own folders, so packages shows as ui, server, desktop and so on, and folders with fewer than 12 memories share one country, Other. Memories that cite no file live on one island with a dashed coast, General. A country's area grows with the number of memories in it; its colour only tells it apart from its neighbours.

  • Each memory is a dot in its country, gathered by the file it cites. A solid dot was used by a session this month (green) or is new this week (blue); a hollow ring was never used. A country full of hollow rings is dead weight you can clean up.
  • No lines. What sits inside what is the whole structure, so nothing crosses and no label is drawn on top of another.
  • Click a country to go in. The map is redrawn with that country alone, fitted to the panel, and every file with three or more memories is named and ringed. The list beside it shows only that country's memories. The path at the top-left (slate › server), a click on empty space, or Escape leads back out to the whole map.
  • The counts are lenses. "80 used this month · 984 never used · …" above the graph: click one to light only those memories on the graph and keep only them in the list, click it again to see them all.
  • One session's memories. A session in Sessions says how many memories it was handed, used and wrote; click that line and Memory opens with exactly those memories lit, and the row above the graph names the session. Clear, or picking a use filter, lights everything again.
  • The graph and the list are one selection. on graph on a list row goes into that memory's country and opens its card; picking a dot on the graph scrolls the list to its row.
  • Pick a memory to open its card. It says how the memory travels — "Handed to 57 sessions, used in 0 · cited 1× · last 2026-09-26" — what file it cites, what it replaced, the other memories about the same file, and any likely duplicate with Merge. From the card you can Pin it (every session in its project starts with it), Stop handing to sessions — it stays in Memory, but recall, briefs and the index never give it to a session — Protect it, so AI memory care never reads it and Retire all never takes it, and Retire it (and Bring back). Each can be undone from the same place. The list row offers the same actions as icons, and shows "not handed to sessions" or "protected".

The map holds still. There is no zoom, pan or scroll: it shows the whole map or one country, always fitted to the panel. On the whole map a click goes into a country, even over a dot, because a dot that small cannot be aimed at; inside a country a click on a dot opens its card. Picking a memory in the list goes into its country. Escape closes an open card first, then goes back out. The map always lands in the same place for the same memories, so you can learn where things are, and it does not move while sessions write new memories.

The list beside it

Find one memory with the search at the head of the list: every word you type must appear in the memory's text, its tags, the file it cites or its m: ref, and the graph lights the matches.

Retire a whole list at once. Under never used or used before, the list offers Retire all. It first says how many memories it will retire, and memories you pinned or protected always stay. Undo brings them all back in one step. Retired memories stay in the store; the Memory screen lists only live ones.

Likely duplicates. When Slate sees two memories that say nearly the same thing, the line above the graph says so; click it and the list shows only those memories. on graph on one opens its card with Merge.

The graph is the stage and the list is the pane beside it, both on screen together, driven by one scope: the project picker at the head of the pane (All projects, or one project). The kind counts at the head of the list, each named — "577 facts", "389 decisions" — are also the kind filter: click one to keep only that kind in the list, click it again to clear. They filter the list only; the graph is not narrowed by kind. The list is where you read, correct and retire a memory; the graph is where you see the shape. Click a memory's text in the list to edit it. Each row in the list shows its ref (the m:… a session cites it by), who wrote it (you, or the AI tool), how often it was confirmed and by whom ("confirmed 2× by Codex"), how often sessions cited it and in which tools ("cited 3× in Gemini, Claude Code"), what it replaced and until when ("was “…” until 2026-08-03"), and marks cited file gone when recall is holding it back. The pin on a row puts the fact in its project's index for every session. Retire session retires everything the session behind a row wrote, after a preview. Where a retired memory is still on screen, its card offers Bring back, which makes it active again unless a newer memory replaced it — including a memory AI memory care retired. Claims that contradict a firmer memory, and the merges and retirements a tidy session proposed, wait at the top under Needs review. See Repairing memory by hand. It draws the same facts and decisions that recall reads and remember writes — change the data and the view follows.
