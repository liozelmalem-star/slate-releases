Features

Memory

Most "AI memory" is a black box: your context disappears into opaque embeddings that only one tool, in one session, can use. Slate inverts that. Its memory is a shared cross-tool layer — the same knowledge is available to every AI tool you use, and it's stored as something you can actually read.

Three things make it work together:

  • Slate is itself an MCP server. Any AI tool that speaks MCP — Claude Code, Cursor, Codex, Gemini, OpenCode — can recall context at the start of a task and remember what it learned at the end. One workspace, many tools.
  • A session watcher populates it automatically. A filesystem watcher captures your AI sessions as they happen, so memory grows without you managing it.
  • Memory is literally your pages. Captured sessions, decisions, and facts are stored in the same SQLite workspace as everything else. When something is wrong, you open the page and fix it — no re-indexing ritual.

There are no embeddings-of-your-whole-life, and no account is required. Memory lives in a local SQLite file, and nothing leaves your machine without an explicit action — a shared workspace is a different file that your private work never enters, and cross-project atoms with no page of their own never leave Personal at all.

The read/write surface itself — the tools every AI client calls — is documented in Slate as an MCP Server.

Memory has a shared half too. Anything you mark for a shared workspace becomes readable by your colleagues and by their AI, through recall_workspaces. recall stays private and local; the shared half is a separate, explicit verb.

Why this matters

You can't trust a memory you can't read. Because Slate's memory is your pages, you can browse it, edit it, and correct it by hand — and the next recall reflects the change. It's also the cleanest possible export: it's just a SQLite file you own.
