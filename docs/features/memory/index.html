Memory

View as markdownOpen the .md copy of this page

Memory is what Slate remembers from your agents' work: decisions, lessons, preferences, lasting knowledge and where things stand. Every agent you connect shares it, so what one agent learns reaches the next session in any agent.

How memory fills#

  • Agents save it. A session saves one memory at a time with Slate's remember tool (Search and save).
  • Slate captures sessions. It reads the conversation files your agents already write and keeps each session (Session capture).
  • Slate reads your agents' own memory. Claude Code and Gemini each keep a memory folder the other agents do not read. Slate reads them for the folders you added as projects, so one agent's learning reaches the rest.
  • You import it. Import, the down arrow in the Memory panel's title row, reads Claude Code, Codex, Gemini, claude-mem, agentmemory, mem0, Basic Memory and Cline Memory Bank. It shows what it would add before it adds anything. A memory from a folder that is no project in this workspace is left out (Import).

How memory reaches a session#

  1. At the start, a session gets a short brief with the project's most useful memories (What a session is given).
  2. While it works, it searches with recall for what its task needs (Search and save).
  3. On a tool call, a lesson about that command or file arrives with the call (Lessons).

When the session uses a memory, it names it. That is how Slate learns which memories help.

Read and fix it#

The Memory place shows every memory on a map of the files it is about, with a list beside it to read, search, correct and retire (The Memory screen). Fix a wrong memory there and the next session reads the correction.

Where it is kept#

Memory lives in the workspace on this computer that holds the project. recall reads it there and does not leave the computer. What you put in a shared workspace is readable by its members and their agents.
