Missions

A mission doc was Slate's first container for one piece of work. The branch doc replaced it: sessions, plans and decisions now file under a branch. Slate makes no new mission docs, and an old one still opens.

An old mission doc has doc_type = mission, so it keeps nesting, breadcrumbs and the editor. It also keeps three things:

  • The type chip under its title shows its status: draft, active, done or canceled.
  • A new empty one starts from the old outline: Goal, Checklist, Session log, Decisions, Notes.
  • A list above the text shows the docs filed under it. A project may hold one without a warning in the tree.

The Doc ▾ menu does not offer mission. See Typed Docs & Hierarchy.

Progress on a branch

A branch doc keeps a running record, so the next session, yours or an agent's, starts with context.

The MCP tool log_mission_progress takes a branch doc and adds a dated entry to its Progress section: a heading with the date and tool name, then the summary, decisions and open items.

recall  →  work the task  →  log_mission_progress(summary, …)
  • Where it goes. Into the branch's Plan doc when it has one, else into the branch doc. It never creates a doc. A call with an id that is not a branch doc is refused.
  • On a trunk branch (main, master, develop) the entry always goes on the branch doc, never a Plan doc, and only the latest 20 entries are kept.
  • Where you read it. On a branch doc, the Progress tab. With a Plan doc, the entries live there, and the tab shows them read-only under the branch's text, headed Logged on the Plan doc.

Slate offers the doc at each milestone

At a milestone (a plan, review, test plan, bug report or design), Slate has your agent ask in the chat whether to keep it as a doc. Slate does not write the question. It tells the tool to use the tool's own click-to-answer question tool, so where that tool shows choices, you click one. The wording is the tool's.

Choose save and the tool saves the doc under the branch. Choose not to and nothing is saved. If the branch already has that doc, the choice is to add to it, keeping what is there. Every tool also carries a standing instruction to ask before saving a plan, review, test plan, bug report or design. Nothing is saved without asking you.

The app is the backup. A plan written in plan mode and not saved in chat waits at the top of the branch doc's Docs tab: Claude Code wrote a plan, with Create Plan doc, Dismiss and Show plan. Create makes the Plan doc and opens it. On a branch with a Plan doc you wrote, the button reads Add to Plan doc and puts the new plan above your text. Dismiss removes the offer, and that plan is not offered again. A Plan doc Slate made is updated by the next plan. One you wrote is never changed without asking.

You can always create a doc yourself from the New buttons at the bottom of the panel.

A branch's Sessions tab lists the sessions themselves: one entry per conversation with its tool, title and time, so you can reopen any. It shows the latest ten and says how many there are.

log_mission_progress is one of Slate's memory tools, exposed to every connected agent. It appends, so history stays intact. See Recall & Remember.
