Missions

A mission doc was Slate's first container for one piece of work. Slate makes no new mission docs, and an old one still opens. Today work files under its project: a session, a plan or a decision made on a git branch carries the branch as a label, and no doc stands for the branch.

An old mission doc has doc_type = mission, so it keeps nesting, breadcrumbs and the editor. It also keeps three things:

  • The type chip under its title shows its status: draft, active, done or canceled.
  • A new empty one starts from the old outline: Goal, Checklist, Session log, Decisions, Notes.
  • A list above the text shows the docs filed under it. A project may hold one without a warning in the tree.

The Doc ▾ menu does not offer mission. See Typed Docs & Hierarchy.

Progress on a branch

The next session on a branch, yours or an agent's, starts with what the branch is for. Slate derives it from the project's records labelled with the branch, and from git; no doc of its own holds it.

The MCP tool log_mission_progress takes cwd (and branch, when the work was on a branch other than the one checked out, which git must know):

recall  →  work the task  →  log_mission_progress(summary, goal, open_items, decisions)
  • The goal and the open items become the branch's goal and open items: the next session's brief shows them. A newer report replaces the older one, and they fade after the shelf life of a state memory.
  • Each decision is saved as a decision memory, labelled with the branch.
  • The summary is a session entry of the project, labelled with the branch, in its Sessions tab.
  • It makes no doc. On a trunk branch (main, master, develop) the goal is not changed.

Slate offers the doc at each milestone

At a milestone (a plan, review, test plan, bug report or design), Slate has your agent ask in the chat whether to keep it as a doc. Slate does not write the question. It tells the tool to use the tool's own click-to-answer question tool, so where that tool shows choices, you click one. The wording is the tool's.

Choose save and the tool saves the doc in the project, labelled with the branch. Choose not to and nothing is saved. If the branch already has that doc, the choice is to add to it, keeping what is there. Every tool also carries a standing instruction to ask before saving a plan, review, test plan, bug report or design. Nothing is saved without asking you.

A plan from plan mode is kept. A plan written in plan mode becomes the branch's Plan doc, in the project and labelled with the branch. A later plan on the same branch replaces the one Slate made. A Plan doc you wrote is never changed: Slate leaves it as it is.

log_mission_progress is one of Slate's memory tools, exposed to every connected agent. See Recall & Remember.
