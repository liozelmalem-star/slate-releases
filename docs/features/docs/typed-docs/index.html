Typed Docs & Hierarchy

Every doc is one row in one table. doc_type says what kind it is and status says where it stands. Together they give the AI memory tools a structure to navigate.

Doc types

A new doc starts as a plain Doc. The chip under the title, Doc ▾, changes its type at any time. The menu lists the seven types a person writes: Doc, Plan, Design, Review, Meeting, Test Plan and Bug Report. A change adds the new type's template headings after the existing text, once only. Group, project and branch are made by Slate from folders and sessions, so they are not in the menu. The DocType enum is in @slate/schema (doc-type/types.ts):

DocTypePurpose
generalA plain knowledge doc.
designA design doc.
planAn implementation or work plan.
reviewA review write-up.
meetingMeeting notes.
test-planA test plan.
bug-reportA bug report.
groupA folder that holds projects.
projectOne folder, usually a git repository, in a group or on its own.
branchA feature branch under a project: the doc a piece of work runs on.
missionLegacy. The branch doc replaced it. See mission docs.

Status

status comes from DOC_STATUSES: draft (started, not active), active (in progress), done (completed), canceled (abandoned).

The hierarchy

Structural types nest as the memory layer expects (@slate/schema, doc-type/rules.ts):

group
└── project
    └── branch
        └── knowledge docs
            (plan | design | test-plan | bug-report | review | meeting | general)

A project may also stand at the top level with no group. Knowledge docs may sit directly under a group or project. ALLOWED_DOC_CHILDREN says what can nest under what. For groups, projects and branches it is enforced on move: dropping a project inside a branch is refused. A knowledge doc in an unusual place shows a warning in the tree.

The hierarchy lets memory tools work without a doc id. When an agent calls recall or remember, Slate resolves a target by walking from the current branch, project and group. A memory belongs to the branch or project it concerns: a lesson from a feature branch to that branch, a convention to its project. A decision on a feature branch also adds one line under the Decisions heading of the branch doc, when it has one, and its full reasoning is a decision doc under the branch. A project-level decision is a decision doc under the project. The tree counts these in a Decisions row.

Filling one in

Slate never creates a knowledge doc without asking: at a milestone, your agent asks whether to save it (mission docs). To have an AI tool write into a doc, use Start session on the doc's header or its Sessions tab. The launcher hands the CLI the doc, its lineage (group → project → branch), the branch's goal and next open item, and the decisions already recorded in that project. See Sessions → Starting a session from a doc.
