Features

Docs & the Block Editor

A doc is Slate's one unit. A note, a design doc, a project, a captured AI session are all rows in one doc table, so nesting, reordering, icons and Trash work the same for everything.

Each doc has an id, a parent_id, a title, an icon, a fractional position, block content and a few metadata columns (doc_type, status, archived, timestamps).

The line under a title ends with who can read it: Private in Personal, or Shared · <workspace> in a shared workspace.

The open screen stays current. When an agent writes over MCP (appends to the doc you read, renames it, files a doc, saves a memory), the screen shows it within a few seconds. If you are typing on that doc, Slate keeps your text and shows a "changed elsewhere" notice with Copy my text, Keep my version (asks once, then saves over the newer one) and Reload doc.

The block editor

The editor is BlockNote. Content is stored as BlockNote JSON in the doc's content column.

Blocks: paragraph, six heading levels (and toggle headings), bullet, numbered, to-do and toggle lists, quote, code, table, image, video, audio, file and divider. Slate adds a callout and a doc card that embeds another doc as a preview. A callout is a plain note. Only the ⚠️ emoji draws it in the warning colour, and clicking the emoji steps through the ten it offers.

Keyboard first:

  • / opens the slash menu. Its first item, Write with AI, asks an agent to draft text into the doc. If a draft fails, the prompt stays open with the reason and Retry. Callout, Link to doc and Doc card sit with the other items.
  • @ links a doc inline. /Link to doc opens the same list: loose matching, recent docs first, arrows and Enter.
  • Drag blocks by their handle, or move them with the keyboard.
  • Pasted Markdown replaces a selection, fills an empty block, or splits a paragraph at the cursor.
  • Right-click menus open with their corner at the pointer.

Right-to-left docs

A doc in Hebrew, Arabic or another RTL script lays out right-to-left: body, title, tab, breadcrumb and sidebar row. Slate reads the direction from the text. Nothing to set.

It counts words by the script each starts in, and a tie goes to RTL. A Hebrew paragraph often opens with a ticket id or package name, and one long Latin identifier should not outvote five Hebrew words. A doc has one direction, so an English heading inside a Hebrew doc stays with the doc. A title declares its own direction.

Projects: made in the workspace menu, narrowed to in a feature

Click the workspace mark at the top of the rail, on any tab:

  • New project…: choose a folder, and the name comes from it.
  • Manage projects…: the workspace's projects by group. Rename one, Open project doc (where its agent is set), or Move to Trash.

⌘K and the foot of every project picker's list offer both.

In Projects, Automations, Activity, Artifacts and Memory, a project picker under the side panel's title narrows that feature to one project. It reads All projects at rest. Pick a project to see its name, with × to go back. Each feature keeps its own choice, and every feature opens on All projects. Memory remembers yours. Home and Toolkit keep their own controls. Sessions lists the whole computer, so it picks a workspace first (see Sessions).

The doc tree

Overview. Under the project picker, above the Docs and Code tabs, Overview shows every project as a card, grouped as the tree groups them: On their own, then each group by name (a group with no projects is hidden). A card's picture is the project's README (first heading and paragraph), else its doc, else its icon on the workspace's colour. Below are the name, the branch its folder is on, the worktree count when more than one (still one card), and when it was last worked in. A green dot means a session is working in it now. Clicking a card picks that project in the picker, on Docs and on Code: Overview keeps its one card, drawn larger, and the side panel lists only it. Clicking that card opens the project's doc. The picker narrows Overview the same way. Entering Projects with no doc open lands here. A workspace with no project says No projects yet and points at the side panel's +.

Docs or Code. The tabs under the picker choose what the side panel lists. A project opens on its doc. Code on the doc puts the panel on Code, on Files, with that project's files open. On Code, the doc icon at the end of a project's row returns to Docs. The choice lasts while the app is open, and every launch starts on Docs. Code lists every project with a git folder on this computer (the picked one, or all), with two views on its left edge: Files and Changes. A project with no folder here has no code to list, and Code says so.

Files is a tree like an editor's explorer. A project with one folder is one row (name and branch) with its files under it. With one project picked, that row goes: the files start at the top, as the project's docs do on Docs, under a bar with the branch and the row's buttons. A project with two or more git worktrees is a group headed like slate · 2 worktrees, with a row per worktree named by its branch (hover for its folder). The group starts open with each worktree shut. Everything stays as you left it. Files changed since the last commit are marked M, A or D, with a dot on their folders. Find a file by name with ⌘K. Hover a checkout's row for New file, New folder, Refresh and Collapse all. Right-click a file, a folder or the space below for New file, New folder, Open terminal here, Start session here, Copy path, Reveal in Finder, Rename and Move to Trash. A new name is typed in place. These wait while an agent is working in that project. A rename or trash can be undone from its message or from Turns, and a trashed file is in the macOS Trash too.

Changes has one section per checkout with files waiting to be committed, named by project and branch, the branch named once on that row. Each is source control laid out as VS Code's: a one-line message, a full-width Commit with Commit & Push in its ▾, and the files waiting, each committed unless unticked, the same as a session's Changes (see Sessions). The icon strip is narrow and the rows are tight. Its icon counts all waiting files. A worktree removed in a terminal leaves the list within about half a minute, or at once when you return to the window.

A file opens in a tab. The line under the cursor shows, after its end, when it last changed and in which commit. Blame shows that for every line. Show changes appears when the file differs from where its branch began, and Back to the file or Esc leaves it. The bottom bar names the branch, says worktree when relevant, and gives the path from the project folder. The rail stays on Projects. A file picked in ⌘K comes here too, with its tree unfolded.

The Docs tree nests groups and projects, with docs as leaves. Any doc can hold children, to any depth. With a project picked it starts inside that project. On All projects it shows every group and project. While the workspace has no project, a line at the top explains: A workspace holds your projects. A project is a folder you open. A group collects related projects. The side panel's one +, in its title row, on Docs and Code, offers Blank doc (⌘N, caret in the title), Write it with AI… (⌘⇧G, an agent drafts from your description) and New project…. A doc goes in the picked project. On All projects Blank doc is off and says why: a doc lives in a project, so pick one at the top first. The tooltip names where the new doc or project goes: "New doc in slate". Each row's icon says its type, and you can change it later (see Typed Docs).

  • Breadcrumbs show the path as Grandparent / Parent / Title.
  • Icon is a Lucide name or an emoji.
  • Captured sessions are not rows. A project collects them for months and they buried the tree. The project lists them under Sessions · N, and Sessions lists all.
  • Notes are counted. A doc an agent wrote as a note is not a row. A doc holding some shows a Notes row with the count. Clicking it lists them in the main area, newest change first, with a title filter. They open, link and edit like any doc. A note that holds docs of its own stays a row.
  • Decisions are not in Docs. Each decision is a memory, and Memory lists it. A decision that holds docs of its own stays a row.
  • Order. Docs keep the order you gave them, by position.
  • Two projects with one name show the end of their folders: lq Documents/lq and lq Private/lq.
  • Drag to reorder uses a fractional position (a REAL), so a drop between two siblings rewrites one row. About 52 drops into the same narrowing gap exhaust a float. Then that parent's children are renumbered once. position is local and never pushed to the cloud.
  • Move / nest by dragging under a new parent. A group goes at the top, a project at the top or in a group. Another drop is refused with the reason and nothing moves. Other docs go anywhere.
  • Move to Trash keeps the doc recoverable. A message says "Moved “Title” to Trash." with Undo, and the open tab closes.
  • Trash lists each doc with when and from where: "Moved to Trash 2 days ago · from slate". A title filter narrows it. Each row has Restore and a Delete forever… icon. Tick rows for Restore (N) and Delete forever (N). With nothing ticked the toolbar offers Empty Trash, or Delete forever · N shown while the filter hides some. Delete forever always asks first. Apps in Trash have their own Apps heading with Restore and Delete forever…. Click a doc to read it, read-only, with a Restore bar. A link to a doc that no longer exists says so and offers Open Trash.
  • No branch is a doc. A git branch is a label: a doc, a session or a memory made on it says which branch, and the project holds it. A branch's worktree is read from git, and Sessions can start a session in it.
  • A removed worktree files with its project. Slate makes a worktree beside its git repository as <repo>-<branch> (Slate's own tooling uses <repo>.noindex/, filed the same way). A session captured after that folder is removed files under the project it came from. A folder that still exists keeps its own name.
  • A project's docs, by type. Docs and Code draw one skeleton: a group you made, holding its projects, and each project on its own. In Docs an open project holds one folder per doc type it has a doc of, with a count, in this order: Plans, Designs, Meetings, Reviews, Test Plans, Bug Reports, Notes, then General Docs. A folder starts closed and stays as you left it; the doc you have open opens its folder. Inside, the docs are newest first: the ten most recent, then Show N older. Every doc written in the project is there, whichever branch it was made on, whether git still has it or not. Hover a doc for the branch it was made on. Code keeps its Files and Changes strip, with a group's projects under the group's row.
  • Group projects. Shift-click two or more projects that stand on their own, then Group… on the row's ⋯ or right-click menu. Name the group, and the projects move into it.
  • Ended branches. When git removes a branch, nothing in Slate changes: the docs written on it stay in their project's type folders, and its sessions in the project's Sessions tab, labelled with the branch. If Trash cannot be read, it says so with Try again.
  • A group's or project's Settings. A group doc, or a standalone project, has a Settings button in its header (a project in a group uses its group's). One sheet holds its folder, the AI tools and accounts it uses, the worktree commands (Set up, Preview, On remove, Carry over), the Check command that decides a task is done, Autopilot, and a Memory section. Each field saves when you leave it, and tools save with Save agents. Settings are saved on this computer, because they name local accounts and commands, and never travel with a shared workspace. Only the Memory section is saved in the workspace. Accounts and models are set in Connect → Agents. A group's or project's tools override the workspace's. A new project asks for none.
  • A refused action says so. If a move, rename, duplicate, Move to Trash or restore fails (doc gone, workspace read-only, somebody else's doc), a message at the bottom names the doc and the reason, and the tree stays as it was. It closes after 8 seconds (it waits while you point at it), or with its ✕. The same message reports what you did elsewhere, with Undo when possible.

The tree holds metadata only (title, icon, kind, parent, position, status). A body is fetched when the doc opens, and "Linked from" is a server query (GET /docs/:id/backlinks) made then.

A group's or project's doc

These open on a doc that holds others rather than text. It shows the name, one line of description and a row of tabs, each with a count. A project's line under its name also has Code, which opens its files in the side panel.

DocTabs
GroupProjects · Docs · Sessions · Memory
ProjectDocs · Sessions · Memory · Projects (only when another project was moved under it)
  • The first tab is what the doc holds, and it opens on it. A tab with nothing is left out, except the first tab. The tab you pick is kept per kind of doc while the app is open.
  • A project's Docs and Sessions hold everything written in it. Docs lists the same docs and type folders as the project in the Docs tree, with the same count, Notes included, and filters by folder, status and title. Sessions lists every session of the project, newest first; each row names the git branch it ran on in grey, and with two or more branches a select above the list shows one branch's sessions. A project has no Branches tab: git owns branches, and in Slate a branch is only a label on a doc or a session.
  • A group's tabs list one level down. A group's Docs are those directly in the group, not in its projects. The same holds for Sessions and Memory. Decisions are not in Docs.
  • The description is the line under the name: click, write one line, press Enter or click away. Escape restores it. A group or project has no other doc text, and text an older version put there is kept in the store but not shown.
  • Memory lists up to 20 memories saved to that doc, most used first, with a link to all in Memory.
  • Accounts line. On a group or standalone project, a line above the tabs says how many captured sessions ran under the accounts it assigns. See Project environments.

Every other doc (a plan, a design, a plain doc) keeps the editor.

Markdown in, Markdown out

Blocks convert to and from Markdown through pure helpers in @slate/shared (blocksToMarkdown, markdownToBlocks, parseBlocks). Pasted Markdown lands as real blocks, and blocks render back to Markdown for the AI agent and MCP tools.
