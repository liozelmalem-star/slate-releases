Curated MCP Commands

A curated command routes a request straight to one of Slate's own workspace tools — create a page, search your notes, ask a shared workspace — without the model choosing anything. It is how a small model reliably calls the right tool with the right arguments: by not asking it to do most of that work.

The pipeline

request
  → keyword routing      (match the request to a curated command)
  → resolve the tool     (the workspace tool the command names)
  → prefill known args   (the app injects everything it already knows)
  → model fills the rest (structured output — only the unknown fields)
  → single tool call

Each stage narrows the model's job. By the time the model is invoked it is filling a few blanks in a schema the app already half-completed. "Create a plan about retries" resolves to create_page with doc_type already set, so the only thing left for the model is the title.

Naming one of your own workspaces outranks the keyword table. "What data do I have in my Apollo workspace" routes to recall_workspaces with the workspace id prefilled.

Structured output does the constraining

The last step asks the model for JSON matching a schema of the missing fields only, and the app merges what comes back with the arguments it injected. A read-only tool then runs straight away; a tool that writes asks you to approve the call first.

The model never has to emit valid tool-call JSON from scratch. It fills a shape.

The fallback

Anything the curated table does not match is handed to the brain's own CLI, which loops over its own MCP tools and decides when it is done. Slate runs no generic tool loop of its own.
