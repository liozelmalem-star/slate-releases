Curated MCP Commands

A curated MCP command is Slate's answer to the question "how do you make a small model reliably call the right tool with the right arguments?" The trick is to not ask the model to do most of that work.

The pipeline

request
  → keyword routing            (match the request to a curated command)
  → resolve a connected tool   (find the actual MCP tool it maps to)
  → prefill known args         (the app injects everything it already knows)
  → model fills the rest       (structured output — only the unknown fields)
  → single tool call

Each stage narrows the model's job. By the time the model is invoked, it isn't choosing a tool or assembling a whole argument object — it's filling a few blanks in a schema the app already half-completed.

Structured output does the constraining

The "model fills the rest" step is a structured-output call, not free-form text. The app hands the model a JSON schema for the missing fields and asks for JSON via ChatOptions.jsonSchema, parsing it from the CLI brain's response. The app then merges the known args it injected with the fields the model returned, producing one well-formed tool call.

This is the piece that makes the Console work on a very light model. The model never has to emit valid tool-call JSON from scratch; it fills a shape.

The fallback

Anything the curated table doesn't match is handed to the brain's own CLI, which loops over its own MCP tools and decides when it is done. Slate runs no generic tool loop of its own. The curated path is preferred precisely because it doesn't depend on the model being smart.
