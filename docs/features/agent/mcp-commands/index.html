Curated MCP Commands

A curated command routes a request straight to one of Slate's own workspace tools (create a doc, search your notes, ask a shared workspace) without the model choosing. A small model calls the right tool with the right arguments because it is not asked to do most of that work.

The pipeline

request
  → keyword routing      (match the request to a curated command)
  → resolve the tool     (the workspace tool the command names)
  → prefill known args   (the app injects everything it already knows)
  → model fills the rest (structured output, only the unknown fields)
  → single tool call

Each step narrows the model's job. "Create a plan about retries" resolves to create_doc with doc_type already set, so the model only supplies the title.

Naming one of your workspaces outranks the keyword table. "What data do I have in my Apollo workspace" routes to recall_workspaces with the workspace id prefilled.

Structured output does the constraining

The last step asks the model for JSON matching a schema of the missing fields only. The app merges the answer with the arguments it injected. The model never writes valid tool-call JSON from scratch. It fills a shape.

A read-only tool then runs at once. A tool that writes asks you to approve first. Under Auto-edit and Full auto a write runs without asking, except the two that start an automation (create and run), which always ask. See Home.

The fallback

Anything the table does not match goes to the agent's own CLI, which loops over its own MCP tools and decides when it is done. Slate runs no generic tool loop.
