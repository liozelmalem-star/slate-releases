Features

The AI Console

Slate has an agent built into the app. It lives on the Console page, and it can do two things most chat boxes can't: it reads and writes your own workspace — nested pages, memory, activity — and it reaches out to any MCP tools you connect. It is provider-agnostic; the same Console works whichever brain you point it at.

The Console is packages/ui/src/pages/Console/Console.tsx. What makes it interesting is not the chat UI but the design principle underneath it.

Push intelligence into code, not the model

The usual way to make an agent capable is to hand a large model a big pile of tools and hope it picks the right one with the right arguments. That works on frontier models and falls apart on light local ones.

Slate takes the opposite approach: do the reasoning in code, and leave the model the smallest possible decision. A request is matched by keyword routing to a curated MCP command, which resolves the connected tool, prefills every argument the app already knows, and asks the model to fill only the remaining fields — via structured output, so the result is a single, well-formed tool call.

Anything the curated table doesn't match is handed to the brain's own CLI, which runs its own tool loop over its own MCP connections. Slate itself no longer runs a tool loop in the app: a turn is either one curated tool call or a CLI handoff.

Because Slate doesn't drive the loop, it doesn't cap its steps either — the brain's CLI decides when it's done. The one cap that exists belongs to the one agent Slate runs itself: the scheduled agent runner behind Loop.

Both halves of memory

The Console reads the memory of the workspace you are standing in (recall_memory) and what colleagues wrote in every workspace you belong to, including ones this machine has not materialised (recall_workspaces, then workspace_page for a full body). "What does the team know about retries", "has anyone solved this before" and "who worked on the sync layer" reach the shared half; the private phrasings — "what do I know about…" — stay local. A shared answer always names its author, because a colleague's decision is not your own memory.

The shared verbs live in the one tool registry (packages/ui/src/lib/agent/tools/), so scheduled agents and page generation get them too: a generated Design checks whether somebody already designed the same thing rather than starting over.

Naming a workspace in the question is enough — "what data do I have in my Apollo workspace" routes straight to the shared verbs, scoped to Apollo, with no model choosing a tool and no MCP connection required. A mention only counts alongside a team cue (workspace, team, shared), so "fix the Apollo timeout bug" stays an ordinary request.

Every conversation, beside the one you are in

The left pane lists your past conversations grouped by day — Today, Yesterday, then the weekday or date — with New chat and a filter box at its head. Each day heading carries its own count, and the rows under it show a clock time rather than "1 day ago", which is only readable because the heading has already settled the day. Clicking one resumes it exactly as the Continue card does — the transcript loads and the brain picks the thread back up.

Only the newest day is open. A busy day holds forty-odd conversations, which is more than a screen for a single day, so an older day is one line saying it exists and how much is in it; click the heading to open it. Typing in the filter opens every day it found something in, and clearing the filter gives you back whatever you had opened by hand.

Under each title is a second line: the conversation's distilled summary, or the repo · branch it ran in when the summary is the tail of the conversation rather than a description of it. A title is the first thing you happened to type, so it is often not an identifier — three conversations can all read "Is the way i run all…" — and the second line is what tells them apart. The filter matches both lines, so a conversation is reachable by what it concluded and not only by how it opened.

It exists because the Console's history used to live only on the welcome screen, which is what you see before the first message. Once you were talking, the stage was the conversation and there was no way back to an older one except starting a fresh session to get the welcome screen back. The pane follows the composer's scope like everything else on the page, and it renders a page of 30 at a time with the rest offered by count — a machine that has captured hundreds of sessions should not mount hundreds of rows to show a dozen.

The list holds conversations only. A page is a conversation when it carries a sessionId — the id it is resumed by — which is also what a remembered atom's page does not have.

Drag a file onto the composer and it becomes an attachment, the same way a paste does: an image is sent as an image to a brain that can see, and a text or code file is inlined under its name. Dropping anywhere else in the app still imports a folder as pages — the composer is the one place a drop means "give this to the agent". Slate reads the file because you handed it over; a path a session merely printed is held to a stricter rule and is only read when it sits inside a folder the app already has business in.

Dropping on a running session is a third thing, and deliberately the smallest: the path is typed at that session's prompt, quoted, with no newline. Nothing is read and nothing is sent — the CLI in that terminal keeps its own context and reads its own files, and the one thing it cannot know is where you just pointed. You see the line before anything runs on it, and you press Enter or you do not.

The composer's scope control sets it explicitly, and it is the only scope control: one dropdown of your projects, resting at Everything. Whatever you pick, the whole page follows it — the Recents list, the Continue card, the starter chips and the brain's own searches. It lists projects and not workspaces because the Console is already in a workspace: which one is the switcher's job, permanently visible in the top bar, and offering the same choice twice is how two controls end up disagreeing. It isn't persisted either, so a scope from last week can't quietly hide an answer.
