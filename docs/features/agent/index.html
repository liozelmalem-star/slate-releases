Slate has an agent built into the app. It lives on the Home page. It does two things most chat boxes cannot: it reads and writes your own workspace — nested pages, memory, activity — and it reaches any MCP tools you connect. The same Home works whichever AI tool you point it at.

What Home shows

Home shows one thing that needs you at a time. Under the mark and the day, a headline counts what waits ("Two things need you.") and a single card shows the first of them.

  • A session that stopped to ask you something comes first. The card shows its question. When Slate runs that session in its own terminal and the session's turn has ended, you type the answer on the card and press Send. Otherwise the card offers Open session: a permission prompt, or a terminal Slate does not own, cannot take typed text.
  • An Inbox item that needs you comes next, with Open in Inbox and, when the item has one, Open link.
  • Later sets a card aside until you restart Slate. A session set aside comes back by itself when it asks something new.

Sessions that are working and need nothing show as small pills, and each opens its session. Only the open workspace's sessions are listed; when sessions run in other workspaces, one pill says how many and links to Sessions.

When nothing waits, the headline says All clear., the composer moves to the middle of the page, and the pills sit under the line that counts them. Home lists no past sessions and has no side pane: past sessions live in Sessions, under All past sessions.

A chat opens over Home. Home, at the top left of the chat, brings Home back and keeps the chat; Back to the chat returns to it.

Push intelligence into code, not the model

Handing a large model a pile of tools and hoping it picks the right one works on frontier models and falls apart on light ones. Slate does the reasoning in code and leaves the model the smallest decision it can.

A request is first matched by keyword against a curated table. A match names one of Slate's own workspace tools, the app prefills every argument it already knows, and the model fills only the fields that are left. A read tool runs straight away; a write asks you first. A command that writes — a page, a project, a routine, a memory — is matched only when your message opens like it ("new project for…", "draft a plan…", "remember that…", after an optional "please" or "can you"). A question that merely contains its words, such as "what's new in this project", is never read as one.

Anything the table does not match is handed to the AI tool's own CLI, which loops over its own MCP tools and stops when it is done. A turn is therefore either one Slate tool call or a CLI handoff.

Both halves of memory

Home reads the memory of the workspace you are standing in (recall_memory) and what colleagues wrote in every workspace you belong to, including ones this machine has not materialised (recall_workspaces, then workspace_page for a full body). "What does the team know about retries", "has anyone solved this before" and "who worked on the sync layer" reach the shared half; the private phrasings — "what do I know about…" — stay local. A shared answer always names its author, because a colleague's decision is not your own memory.

Naming a workspace in the question is enough — "what data do I have in my Apollo workspace" routes straight to the shared tools, scoped to Apollo, with no MCP connection required. The name only counts alongside a team word (workspace, team, shared), so "fix the Apollo timeout bug" stays an ordinary request.

Resuming a past session

Home keeps no list of past sessions. Open Sessions and choose All past sessions, or open a session from its project's page, and pick Resume: Home opens with that session's transcript loaded, and the AI tool picks the thread back up.

The AI tool asks before it acts

Home runs on a real CLI, and that CLI has tools of its own beyond Slate's — it can read a file, edit one, and run a shell command in the project you scoped the turn to. It now asks you first, in the same amber card the app already uses for a workspace write.

The card shows the call the AI tool actually named and the argument it actually wrote — the whole shell command, not a summary of it — with three answers:

What it does
ApproveRuns this one call. Nothing is remembered.
Always allowRuns it, and saves the rule to the project's own .claude/settings.local.json, so the next identical call is not asked about. The card prints the exact rule before you click.
SkipRefuses, and tells the AI tool why — so the reply says the call was declined rather than silently doing nothing.

Always allow only appears when the CLI offered a rule for that call. Slate never invents one, so the button can only ever promise what the CLI itself would save.

When the AI tool asks about several calls at once, the cards wait in line and show one at a time; each gets its own answer. An answer belongs to the card it was given on, so a double click cannot approve the next card before you have seen it.

Slate's own tools — reading your pages, writing memory — are not put behind this card. Home is Slate: a prompt to let Slate read its own workspace is a question with no decision behind it. Everything else asks, including MCP servers you connected yourself.

The autonomy pill in the ⌘J panel decides how much never reaches the card at all: Ask first asks before every file edit and command, Auto-edit applies file edits without asking and still asks before a shell command, and Full auto asks about nothing. It now takes effect on the conversation you are already having — before, it was fixed when the AI tool started, so switching it either did nothing until your next message or restarted it and made every connected tool sign in again.

Background work — a scheduled routine, the watcher's enrichment pass — never shows a card, because nobody is watching it. Those runs keep the pre-approved tool list they have always had and cannot be stalled waiting for an answer that is not coming.

Two more things the AI tool can ask

A plan. Ask for a plan and the AI tool writes one, then puts it in front of you whole before it touches anything. Approve it and it starts; skip and it keeps planning.

A question. When the AI tool needs a decision it cannot make for you, it asks — and each answer it offers is a button. Picking one is the answer; there is no separate Approve, because the choice is the approval.

Both only exist because Slate can now answer: the CLI hides its plan and question tools entirely from a host that cannot be asked.

Stop ends the turn, not the AI tool

Stop used to kill the whole process, which threw away every connected tool's signed-in session — so your next message made them all authenticate again. It now ends the turn and leaves the AI tool running warm, with its connections intact. An AI tool that runs one process per turn, like Gemini, has that process ended instead. A message sent right after Stop waits up to ten seconds for the stopped turn to let go, then starts a fresh one if it has not.

Stop also declines every card still waiting, and a step it interrupts reads Stopped. rather than done or still running.

Home has one warm AI tool. A chat started with Chat in the Sessions tab gets a warm AI tool of its own, in its own folder. Stop, the mode and the model there reach only that chat's AI tool, and closing its tab ends it. See A chat instead of a terminal.

What Home shows about the AI tool

The reply now appears as it is written rather than arriving in one block.

Beside the token count is a context meter: how full the AI tool's window is, as a share of its total. The numbers are the CLI's own, so the meter and /context in a terminal cannot disagree. It refreshes every turn, and turns amber past 75%.

Typing / lists Slate's own skills first and then the AI tool's — the real ones the CLI carries, plugins included, with the arguments each expects. Slate used to list only its own and never ask; Claude alone brought 58. Picking one of Slate's fills in its prompt; picking one of the AI tool's types the command for you, because the text behind it belongs to the AI tool, not to Slate.

A hook that blocks a turn now says so. Only the ones that fail are reported — an ordinary turn fires four and they all pass.

Codex additionally asks before escalating out of its sandbox, and passes on questions from its own connected MCP servers — two shapes Claude has no equivalent of.

Cursor, Gemini and OpenCode are not wired to these cards, and the autonomy control says so — on those it is disabled with the reason in its tooltip, rather than offering three settings the AI tool ignores. Cursor's is not "not yet": its CLI has no approval callback at all, so it runs pre-approved whatever any control says.

An approval left on screen no longer costs you the turn on the same ten-minute clock that bounds an AI tool which has gone quiet. Waiting on a person buys one more window; a card nobody ever answers still ends, and Stop is always the way out.

Scope, and dropping a file in

The composer's scope control is one dropdown of your projects, resting at Everything. Whatever you pick, the whole page follows it — the conversation list, the Continue card, the starter chips and the AI tool's own searches. It lists projects and not workspaces because Home is already in a workspace, and the switcher at the top of the rail is where that is chosen. It is not persisted, so a scope from last week cannot quietly hide an answer.

Drag a file onto the composer and it becomes an attachment, the same way a paste does: an image is sent as an image to an AI tool that can see, and a text or code file is inlined under its name. Dropping anywhere else in the app still imports a folder as pages.
