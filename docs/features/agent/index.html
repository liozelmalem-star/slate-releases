Home is the doc Slate opens on. It has an agent built in. The agent reads and writes your own workspace (nested docs, memory, activity) and reaches any MCP tools you connect. It runs on whichever coding agent you point it at.

What Home shows

Home shows one thing that needs you at a time. Under the mark and the day, a headline counts what needs you ("Six things need you."). Sessions that only finished a turn are not counted. The line under it names them ("One more finished — look when you can."). When only finished sessions wait, the headline says so calmly ("One session finished.").

Each card has a badge naming its kind. The deck is ordered by it, blocking cards first. The dot before the badge is amber when the card blocks on you now and grey when it can wait. The dots under the deck use the same colours.

OrderBadgeWhat it isWhat the card offers
1Needs permission (amber)The agent wants to run a tool call and waits for your yesThe command in a code box, Open to allow, Later
2Asks you (amber)The session's last turn ends on a questionIf Slate runs the session: a Reply box, Send, Open, Later. For a terminal Slate does not own: Open session, Later, and a line saying the answer is typed there
3Automation asks (amber)A call an automation's rules held (Automations)The call, Yes, do it, No with an optional reason, Open the thread, Later
4Review asked or Task (grey)A task in Tasks that needs youOpen in Tasks, Open in {app} (such as GitHub), Later
5Reminder (amber)A reminder you set on a taskOpen in Tasks, Done, Later
6Finished (grey)The session's turn is a report: nothing blocksOpen session, Mark seen, Later

The card's title is one plain line: the question the reply ends on, or its first sentence, without markdown. Under it the rest of the reply shows as markdown, about four lines, and Read the whole reply opens the session. Only Claude Code's transcripts show a pending tool call today, so other tools' sessions are Asks you or Finished, never Needs permission.

Press Send on an Asks you card and the card leaves while you stay on Home. Some agents are not proved to send a line on Enter. For those, the answer is typed into the session's prompt and not sent, and the card says Typed — press Enter in the session to send it.

Later sets a card aside until you restart Slate. A session set aside comes back by itself when it says something new. Mark seen does the same for a finished session. An answered card does not count as set aside.

The cards sit side by side, the front one with its neighbours faded. Move with the arrows beside the dots, the dots, ← and →, a sideways trackpad swipe, or a drag. A line under the dots says where you are ("4 of 7 · Automation asks").

Sessions that are working and need nothing show as small pills, each opening its session. Only the open workspace's sessions are listed. When sessions run in other workspaces, one pill gives the count and links to Sessions.

When nothing waits, the headline says All clear., the composer moves to the middle, and the pills sit under the line that counts them. Home lists no past sessions and has no side panel. Past sessions live in Sessions, under All past sessions.

A chat opens over Home. Home, top left of the chat, brings Home back and keeps the chat. Back to the chat returns to it. A reply that keeps streaming does not pull you back. Only sending a new message does.

⌘J opens the Ask AI panel beside a doc. Anywhere else it shows The AI panel opens on a doc. Open a doc first. The slash menu's Write with AI is a different thing: it drafts text straight into the doc.

Changes waiting for your setup wait in Toolkit › Suggestions, not here.

Under the deck, your widgets for Home sit in a row. They are cards you described in Apps, and they read what Home shows (running AI sessions and your open tasks, for the project picked here). A new one appears as soon as it is built. Each one's ⋯ menu opens it in Apps or takes it off Home. Add widget puts it back.

The Set up Slate card

In a workspace with no agent set, Home is a doc of its own: {workspace} is ready for an agent. One card shows the agents and what connecting one unlocks (Ask here, Memory, Activity, Automations, Apps), with Open Connect and what works without AI: Tasks, Projects and Artifacts. See Connect.

Once a tool is set, Home starts with a Set up Slate card. It has three steps, each with one button:

StepButtonDone when
Connect an agentConnect an agent (opens Connect → Agents)This workspace has an agent set
Start a sessionNew session (runs your tool in a folder)A session has been captured
See your first memoryOpen MemoryA memory is saved

Ticks come from what is in the workspace, not from clicks, so a step done elsewhere ticks itself. The first open step carries the main button. The header counts progress ("1 of 3 done"). The card goes away when all three are done or when you press Skip setup, and does not come back in that workspace. Skipping in one workspace does not hide it in another.

Under the card, one line says what a workspace is: A workspace holds your projects. A project is a folder you open. It names the workspace you are in.

Push intelligence into code, not the model

A large model with a pile of tools picks well. A light model does not. Slate does the reasoning in code and leaves the model the smallest decision it can.

A request is first matched by keyword against a curated table. A match names one of Slate's own workspace tools. The app prefills every argument it knows, and the model fills only what is left. A read tool runs at once. A write asks you first, except under the autonomy settings below. A command that writes (a doc, project, agent or memory) matches only when your message opens like it ("new project for…", "draft a plan…", "remember that…", after an optional "please" or "can you"). A question that merely contains those words, such as "what's new in this project", is never read as a command.

Anything the table does not match goes to the agent's own CLI, which loops over its own MCP tools and stops when done. A turn is therefore one Slate tool call or a CLI handoff. See Curated MCP Commands.

Both halves of memory

Home reads the memory of the workspace you are in (recall_memory) and what colleagues wrote in every workspace you belong to, including ones this machine has not materialised (recall_workspaces, then workspace_doc for a full body). "What does the team know about retries", "has anyone solved this before" and "who worked on the sync layer" reach the shared half. "What do I know about…" stays local. A shared answer always names its author.

Naming a workspace is enough: "what data do I have in my Apollo workspace" routes straight to the shared tools, scoped to Apollo, with no MCP connection needed. The name counts only beside a team word (workspace, team, shared), so "fix the Apollo timeout bug" stays an ordinary request.

Resuming a past session

Open Sessions and choose All past sessions. A click on a row opens the session's record. Resume, a button on the row, opens Home with that session's transcript loaded, and the agent picks the thread back up. The chat starts with what you first asked and, under a Summary label, what Slate saved of the session. The summary is Slate's record, not a new reply from the tool.

The agent asks before it acts

Home runs on a real CLI with tools of its own: it can read a file, edit one and run a shell command in the project you scoped the turn to. It asks you first, in the same amber card the app uses for a workspace write.

The card shows the call the tool named and the argument it wrote, the whole shell command and not a summary, with three answers:

What it does
ApproveRuns this one call. Nothing is remembered.
Always allowRuns it and keeps a rule so the next identical call is not asked. On Claude Code the rule goes to the project's .claude/settings.local.json, and the card prints the exact rule first. Codex remembers it for the session. Cursor and OpenCode keep it in their own allowlist.
SkipRefuses and tells the agent why, so the reply says the call was declined.

Beside Skip is an optional box for a reason. A reason can become a memory proposal you may accept.

Always allow appears only when the CLI offered a rule for that call. Slate never invents one. A question card has no Approve: each answer is a button.

When the tool asks about several calls at once, the cards wait in line and show one at a time. An answer belongs to the card it was given on, so a double click cannot approve the next card unseen.

Slate's own tools (reading your docs, writing memory) are not put behind this card. Everything else asks, including MCP servers you connected yourself.

The autonomy pill sets how much never reaches the card. The ⌘J panel and Home's composer share one setting. Ask first asks before every file edit and command. Auto-edit applies file edits and still asks before a shell command. Full auto asks about nothing. A click moves one step. The step into Full auto needs a second click to confirm. New chat returns to Ask first. A change takes effect in the conversation you are in, with no restart, so no connected tool signs in again.

Two Slate commands ignore the pill: Create an automation and Run an automation. They start work that spends money, so they ask even under Auto-edit and Full auto. Other Slate writes, such as a new doc, run without asking under those two settings.

Background work, such as an automation's run, never shows a card while it runs, because nobody is watching. The run is held to its rules instead. A call that changes something is held and waits on Home as an Automation asks card after the run ends (Automations).

Two more things the agent can ask

A plan. Ask for a plan and the tool writes one and shows it whole before it touches anything. Approve and it starts. Skip and it keeps planning.

A question. When the tool needs a decision it cannot make for you, each answer it offers is a button. Picking one is the answer.

The CLI hides its plan and question tools from a host that cannot answer them. Slate can.

Stop ends the turn, not the agent

Stop ends the turn and leaves the agent running, with its connections intact, so your next message does not make every connected tool sign in again. A message sent right after Stop waits up to ten seconds for the stopped turn to let go, then starts a fresh one if it has not. A tool that runs one process per message has that process ended: the fallback in Agents & Model Providers.

Stop also declines every card still waiting. A step it interrupts reads Stopped.

Home has one warm agent. A chat started with Chat in Sessions gets its own, in its own folder. Stop, the mode and the model there reach only that chat's tool, and closing its tab ends it. See A chat instead of a terminal.

What Home shows about the agent

The reply appears as it is written.

Beside the token count is a context meter: how full the tool's window is, as a share of its total, with a small bar. The numbers are the CLI's own, so the meter and /context in a terminal agree. It refreshes every turn, and the bar and text darken from 75%. Where the window size is unknown, it shows the token count alone.

The top bar has a tools chip. While the first turn connects it shows connecting agents… with a spinner. After that it shows how many MCP servers the tool reported, their names on hover, and · 1 failed in amber for any that did not connect.

A hook that blocks a turn says so in the chat, naming the hook and the reason. Only a failing hook is reported.

Typing / lists skills and commands: see Skills and mentions.

Which agents this covers

Claude Code and Codex speak their own protocols. Cursor, OpenCode, Gemini, GitHub Copilot and the ten newest tools (Antigravity, Cline, Grok Build, Kiro, Qwen Code, Droid, Hermes Agent, Goose, Kilo Code and Auggie) speak the Agent Client Protocol. The approval cards work on Claude Code, Codex, Cursor and OpenCode. For the ten newest tools, Home, Stop, the model picker and the approval card are unverified: Slate has checked their ACP handshake, not a live turn. The cells are in Features by Agent. The full per-tool table is in Features by Agent.

Codex also asks before escalating out of its sandbox and passes on questions from its own connected MCP servers. Claude has neither.

Cursor and OpenCode show the approval card with Approve, Always allow and Skip, but have no plan or question card. Always allow goes in the tool's own allowlist, not a Slate rule. Slate answers by the autonomy pill:

  • Cursor asks for anything outside your own Cursor allowlist. Ask first shows a card for each call. Auto-edit allows file edits, reads and searches and shows a card for the rest. Full auto allows all.
  • OpenCode normally allows every tool. Slate starts it with shell commands and edits set to ask, and answers by the pill the same way. When OpenCode does not answer the protocol, Slate runs one process per message: Ask first refuses shell commands and edits, Auto-edit refuses shell commands, and Full auto leaves OpenCode's default. That process cannot show a card, so an ask is a refusal.

Gemini is marked unverified for asking, because Gemini CLI stops before any turn on a consumer Google account (see Features by Agent). The autonomy pill is disabled on Gemini, with Slate cannot yet ask Gemini for permission, so it runs pre-approved whatever this says in its tooltip.

The ten-minute limit on a quiet agent gets one more window while an approval waits on you. A card nobody answers still ends, and Stop is always the way out.

Scope, and dropping a file in

The composer's Scope control (folder icon) is a dropdown of your projects, resting at All projects. Whatever you pick, the tool's own searches, the memories Home hands it (What it knows), the tool picker and the widgets under the box follow it. It lists projects, not workspaces: the switcher at the top of the rail picks the workspace. Scope is not saved, so last week's scope cannot hide an answer.

Drag a file onto the composer and it becomes an attachment, as a paste does. An image shows as a thumbnail in the box and in your sent message. On send, Slate saves it in an attachments folder in its app-data folder and gives the tool its path, because the tools open an image from a file. An image no message has used for 30 days is removed. A text or code file is inlined under its name. The same works in a session's Conversation prompt. Dropping a file elsewhere in the app imports a folder as docs.

Skills and mentions

Type / at the start of the composer to list the skills the agent will load here: the project's own skills from the folders that tool reads, its commands, and the personal and plugin skills of the account the project runs it as. The list is read from disk, so it is there before your first message, for every tool whose skill folders Slate knows. It matches name first, description second, and an exact name comes first. A pick waits as a chip before your words. On send, the tool is told to read that skill's file and follow it. Once Claude Code has answered, the commands it reports are listed after the skills. Picking one types /name into the box, because its text belongs to the tool. Claude Code is the only tool that reports commands.

Type @ anywhere to name something in the workspace: a doc, session, memory, task, automation or report. The menu shows up to five of each kind whose name holds what you typed, most recent first, grouped by kind. Each pick is a chip. On send, its content goes in front of your message as plain text: a doc's text (cut at 8,000 characters, and marked when cut), a session's tool, folder, branch and id, a memory's claim with reasoning and source, a task's state and link, an automation's steps, a report's text. If Slate cannot read one, the conversation says so instead of sending without it.

/ and @ also work in a session's Conversation prompt and in Run with AI's What to type in.
