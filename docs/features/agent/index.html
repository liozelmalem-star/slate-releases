Slate has an agent built into the app. It lives on the Home page. It does two things most chat boxes cannot: it reads and writes your own workspace — nested pages, memory, activity — and it reaches any MCP tools you connect. The same Home works whichever AI tool you point it at.

What Home shows

Home shows one thing that needs you at a time. Under the mark and the day, a headline counts what waits ("Two things need you.") and a single card shows the first of them.

  • A session that stopped to ask you something comes first. The card shows its question. When Slate runs that session in its own terminal and the session's turn has ended, you type the answer in the Reply… box and press Send. The card then leaves, and you stay on Home. Open on the same card opens the session instead. Some AI tools are not proved to send a line on Enter. For those, the answer is typed into the session's prompt and not sent, and the card stays and says Typed — press Enter in the session to send it. Otherwise the card offers only Open session: a permission prompt, or a terminal Slate does not own, cannot take typed text.
  • A call an agent's rules held comes next: an Ask first card with what the agent wanted to do, Yes, do it, No and Open the thread. Yes starts one short run that makes exactly that call. See Agents.
  • A task that needs you comes after, with Open in Tasks and an Open in {app} button, such as Open in GitHub.
  • Later is on every card. It sets the card aside until you restart Slate. A session set aside comes back by itself when it asks something new. A card you answered is not counted as set aside.

Sessions that are working and need nothing show as small pills, and each opens its session. Only the open workspace's sessions are listed; when sessions run in other workspaces, one pill says how many and links to Sessions.

When nothing waits, the headline says All clear., the composer moves to the middle of the page, and the pills sit under the line that counts them. Home lists no past sessions and has no side panel: past sessions live in Sessions, under All past sessions, which ends with the workspace's name.

A chat opens over Home. Home, at the top left of the chat, brings Home back and keeps the chat; Back to the chat returns to it. A reply that keeps streaming does not pull you back to the chat. Only sending a new message does.

⌘J opens the Ask AI panel beside a page. It opens only on a page. Anywhere else, ⌘J shows a short note, The AI panel opens on a page. Open a page first. In a page, the slash menu's Write with AI is a different thing: it drafts text straight into the page.

Under the box, your widgets for Home sit in a row: cards you described in Apps, which read what Home shows (the AI sessions running now and your open tasks, for the project picked here). A new one is there as soon as it is built. Each one's ⋯ menu opens it in Apps or takes it off Home; Add widget puts it back.

The Set up Slate card

Slate always opens on Home. In a workspace with no AI tool set, Home is a page of its own instead: {workspace} is ready for an AI tool, one card with the five tools and what connecting one unlocks (Ask here, Memory, Activity, Agents, Apps), Open Connect, and what already works without AI — Tasks, Projects and Artifacts.

Once a tool is set, a workspace's Home starts with a Set up Slate card above everything else. It has three steps, each with one button:

StepButtonDone when
Connect an AI toolConnect a tool — opens Connect → AI toolsThis workspace has an AI tool set
Start a sessionNew session — runs your tool in a folderA session has been captured
See your first memoryOpen MemoryA memory is saved

The ticks come from what is really in the workspace, not from clicks, so a step you did somewhere else ticks itself. The first open step carries the main button. The header says how many are done ("1 of 3 done"). The card goes away when all three are done, or when you press Skip setup. It does not come back in that workspace. Each workspace keeps its own answer, so skipping it in one workspace does not hide it in another.

Under the card one line says what a workspace is: A workspace holds your projects. A project is a folder you open. It names the workspace you are in.

Until this workspace has an AI tool, Home shows the ready for an AI tool page described above in place of this card and the chat. See Connect.

Push intelligence into code, not the model

Handing a large model a pile of tools and hoping it picks the right one works on frontier models and falls apart on light ones. Slate does the reasoning in code and leaves the model the smallest decision it can.

A request is first matched by keyword against a curated table. A match names one of Slate's own workspace tools, the app prefills every argument it already knows, and the model fills only the fields that are left. A read tool runs straight away; a write asks you first, with the autonomy exception described below. A command that writes — a page, a project, an agent, a memory — is matched only when your message opens like it ("new project for…", "draft a plan…", "remember that…", after an optional "please" or "can you"). A question that merely contains its words, such as "what's new in this project", is never read as one.

Anything the table does not match goes to the AI tool's own CLI, which loops over its own MCP tools and stops when it is done. A turn is therefore either one Slate tool call or a CLI handoff.

Both halves of memory

Home reads the memory of the workspace you are standing in (recall_memory) and what colleagues wrote in every workspace you belong to, including ones this machine has not materialised (recall_workspaces, then workspace_page for a full body). "What does the team know about retries", "has anyone solved this before" and "who worked on the sync layer" reach the shared half; the private phrasings — "what do I know about…" — stay local. A shared answer always names its author, because a colleague's decision is not your own memory.

Naming a workspace in the question is enough — "what data do I have in my Apollo workspace" routes straight to the shared tools, scoped to Apollo, with no MCP connection required. The name only counts alongside a team word (workspace, team, shared), so "fix the Apollo timeout bug" stays an ordinary request.

Resuming a past session

Home keeps no list of past sessions. Open Sessions and choose All past sessions, which ends with the workspace's name. A click on a row opens the session's record. Resume, a button of its own on the row, opens Home with that session's transcript loaded, and the AI tool picks the thread back up. The chat starts with what you first asked and, under a Summary label, what Slate saved of the session. That summary is Slate's record, not a new reply from the AI tool.

The AI tool asks before it acts

Home runs on a real CLI, and that CLI has tools of its own beyond Slate's — it can read a file, edit one, and run a shell command in the project you scoped the turn to. It now asks you first, in the same amber card the app already uses for a workspace write.

The card shows the call the AI tool actually named and the argument it actually wrote — the whole shell command, not a summary of it — with three answers:

What it does
ApproveRuns this one call. Nothing is remembered.
Always allowRuns it, and keeps a rule so the next identical call is not asked about. On Claude Code the rule goes to the project's own .claude/settings.local.json, and the card prints the exact rule before you click. Codex remembers it for the session. Cursor and OpenCode keep it in their own allowlist.
SkipRefuses, and tells the AI tool why — so the reply says the call was declined rather than silently doing nothing.

Beside Skip is a short box for a reason. It is optional. A reason can become a memory proposal you may accept.

Always allow only appears when the CLI offered a rule for that call. Slate never invents one, so the button can only ever promise what the CLI itself would save. A question card has no Approve: each answer is a button.

When the AI tool asks about several calls at once, the cards wait in line and show one at a time; each gets its own answer. An answer belongs to the card it was given on, so a double click cannot approve the next card before you have seen it.

Slate's own tools — reading your pages, writing memory — are not put behind this card. Home is Slate: a prompt to let Slate read its own workspace is a question with no decision behind it. Everything else asks, including MCP servers you connected yourself.

The autonomy pill — in the ⌘J panel and on Home's composer, one setting for both — decides how much never reaches the card at all: Ask first asks before every file edit and command, Auto-edit applies file edits without asking and still asks before a shell command, and Full auto asks about nothing. A click moves one step; the step into Full auto needs a second click to confirm, and New chat returns to Ask first. It takes effect on the conversation you are already having, with no restart, so no connected tool has to sign in again.

Two Slate commands ignore the pill. Create agent and Run agent start work that spends money, so they ask first even under Auto-edit and Full auto. Other Slate writes, such as a new page, run without asking under those two settings.

Background work — an agent's run, the watcher's enrichment pass — never shows a card while it runs, because nobody is watching it, and cannot be stalled waiting for an answer that is not coming. An agent's run is held to its rules instead: a call that changes something is held, and waits on Home as an Ask first card once the run ends (Agents).

Two more things the AI tool can ask

A plan. Ask for a plan and the AI tool writes one, then puts it in front of you whole before it touches anything. Approve it and it starts; skip and it keeps planning.

A question. When the AI tool needs a decision it cannot make for you, it asks — and each answer it offers is a button. Picking one is the answer; there is no separate Approve, because the choice is the approval.

Both only exist because Slate can now answer: the CLI hides its plan and question tools entirely from a host that cannot be asked.

Stop ends the turn, not the AI tool

Stop ends the turn and leaves the AI tool running warm, with its connections intact, so your next message does not make every connected tool sign in again. A message sent right after Stop waits up to ten seconds for the stopped turn to let go, then starts a fresh one if it has not. Only an AI tool that runs one process per message has that process ended. That is the fallback described in AI Tools & Model Providers, not Gemini's normal way.

Stop also declines every card still waiting, and a step it interrupts reads Stopped. rather than done or still running.

Home has one warm AI tool. A chat started with Chat in the Sessions tab gets a warm AI tool of its own, in its own folder. Stop, the mode and the model there reach only that chat's AI tool, and closing its tab ends it. See A chat instead of a terminal.

What Home shows about the AI tool

The reply appears as it is written rather than arriving in one block.

Beside the token count is a context meter: how full the AI tool's window is, as a share of its total, with a small bar. The numbers are the CLI's own, so the meter and /context in a terminal cannot disagree. It refreshes every turn, and the bar and text turn darker from 75%. Where the window size is not known, it shows the token count alone.

The top bar also has a tools chip. While the first turn connects it shows connecting tools… with a spinner. After that it shows how many MCP servers the AI tool reported, their names on hover, and · 1 failed in amber for any that did not connect.

Typing / lists the skills and commands the AI tool loads here, as described under Skills and mentions.

A hook that blocks a turn says so in the chat, naming the hook and the reason. Only a hook that fails is reported.

Which AI tools this covers

Claude Code and Codex speak their own protocols. Cursor, OpenCode and Gemini speak the Agent Client Protocol. The approval cards below are live on Claude Code, Codex, Cursor and OpenCode.

Always allowsaves a rule to the projectremembers it for the session

Its own slash commands in /, after the first replyyes— its commands live in its terminal UI, not in the protocol

Codex additionally asks before escalating out of its sandbox, and passes on questions from its own connected MCP servers — two shapes Claude has no equivalent of.

Cursor and OpenCode show the approval card for a tool call, with Approve, Always allow and Skip, but have no plan or question card. Always allow is kept in the tool's own allowlist, not in a Slate rule. Slate answers by the autonomy pill:

  • Cursor asks for anything outside your own Cursor allowlist. Ask first shows a card for each call. Auto-edit allows file edits, reads and searches and shows a card for the rest. Full auto allows all.
  • OpenCode normally allows every tool. Slate starts it with shell commands and edits set to ask, and answers by the pill the same way. When OpenCode does not answer the protocol, Slate runs one process per message with the same rule: Ask first refuses shell commands and edits, Auto-edit refuses shell commands, and Full auto leaves OpenCode's own default. A one-message process cannot show a card, so an ask there is a refusal.

Gemini is marked unverified for asking, because Gemini CLI stops before any turn on a consumer Google account (see Features by AI Tool). Until that is checked, the autonomy pill is disabled on Gemini, with Slate cannot yet ask Gemini for permission, so it runs pre-approved whatever this says in its tooltip. The pill is never shown doing nothing on a tool that cannot be asked.

An approval left on screen no longer costs you the turn on the same ten-minute clock that bounds an AI tool which has gone quiet. Waiting on a person buys one more window; a card nobody ever answers still ends, and Stop is always the way out.

Scope, and dropping a file in

The composer's scope control is labelled Scope, with a folder icon. It is one dropdown of your projects, resting at All projects. Whatever you pick, the AI tool's own searches, the memories Home hands it (What it knows), the tool picker and the widgets under the box follow it. It lists projects and not workspaces because Home is already in a workspace, and the switcher at the top of the rail is where that is chosen. It is not persisted, so a scope from last week cannot quietly hide an answer.

Drag a file onto the composer and it becomes an attachment, the same way a paste does: an image is sent as an image to an AI tool that can see, and a text or code file is inlined under its name. Dropping anywhere else in the app still imports a folder as pages.

Skills and mentions

Type / at the start of the composer to list the skills the AI tool will load here: the project's own skills from the folders that tool reads, its commands, and the personal and plugin skills of the account its project runs it as. The list is read from disk, so it is there before your first message and for all five AI tools. It matches the name first and the description second, and an exact name comes first. Pick one and it waits as a chip in front of your words; on send, the AI tool is told to read that skill's file and follow it, which every tool can do. Once Claude Code has answered, the commands it reports itself are listed after the skills. Picking one of those types /name into the box for you, because its text belongs to the AI tool, not to Slate. Claude Code is the only tool that reports its commands.

Type @ anywhere in the text to name something in the workspace: a page, a session, a memory, a task, an agent or a report. The menu shows up to five of each kind whose name holds what you typed, most recent first, grouped by kind. Each pick is a chip. On send, its content goes in front of your message: a page's text (cut at 8,000 characters, and marked when cut), a session's tool, folder, branch and session id, a memory's claim with its reasoning and source, a task's state and link, an agent's steps, a report's text. It is plain text, so every AI tool reads the same thing. If Slate cannot read one, the conversation says so instead of sending without it.

The same / and @ work in a session's Conversation prompt and in Run with AI's What to type in.
