Connected MCP Tools

Home is not limited to Slate's own workspace tools. Whatever MCP servers your AI tool's CLI can reach, Home can reach.

Where servers come from

Home keeps no MCP server list of its own. When a turn is given to the AI tool's CLI, that CLI loads the servers declared in its own config — the account's, and the project directory's — and reports back which of them connected. Which account a tool runs under is Connect → AI tools, and a group, or a project on its own, may override it. Which servers that account declares is the CLI's own config, edited where that CLI keeps it.

Home's top bar shows a tools chip. While a turn is running and the CLI has not yet reported, it shows a spinner and connecting tools…. Then it shows how many servers the CLI reported, their names on hover, and · 1 failed in amber for any that did not connect. The count stays after the turn ends.

Apps you connected in Slate

An app you connected in Connect → Integrations — Linear, Notion, Jira and the rest — is readable from every session too, even when the AI tool's own config has no server for it. Slate's own MCP server carries two tools for it: connected_tools lists the apps and the tools of each that only read, and read_connected reads through one. Slate makes the call with the sign-in it holds, so it works the same in all five AI tools, in Home, an agent and your own terminal, while Slate is open. Tools that write are never offered. The full description is in Slate's MCP tools.

Two directions — don't conflate them

Slate sits on both sides of MCP.

DirectionWhat it means
Slate as an MCP serverSlate exposes your workspace to other AI tools (Claude Code, Cursor, Codex, Gemini, OpenCode). Those tools call into Slate.
Home reaching other serversThe in-app agent calls out to the servers its CLI declares. Slate is the client.

This page is about the second direction.
