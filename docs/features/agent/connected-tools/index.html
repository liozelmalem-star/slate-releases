Connected MCP Tools

Home reaches whatever MCP servers your agent's CLI can reach.

Where servers come from

Home keeps no MCP server list. When a turn goes to the tool's CLI, the CLI loads the servers in its own config (the account's and the project directory's) and reports which connected. Connect → Agents sets the account a tool runs under, and a group or project may override it. The servers that account declares are edited where the CLI keeps its config.

Home's top bar shows a tools chip. While the CLI has not yet reported, it shows a spinner and connecting agents…. Then it shows how many servers the CLI reported, their names on hover, and · 1 failed in amber for any that did not connect. The count stays after the turn ends.

Apps you connected in Slate

An app you connected in Connect → Integrations, such as Linear, Notion or Jira, is readable from every session, even when the tool's own config has no server for it. Slate's MCP server has two tools for this: connected_tools lists the apps and their read-only tools, and read_connected reads through one. Slate makes the call with the sign-in it holds, so it works the same in every agent, in Home, an agent and your own terminal, while Slate is open. Tools that write are never offered.
