Brains & Model Providers

Slate calls its model providers brains. A brain isn't a raw API integration — it's a thin driver over an AI CLI you already have installed and authenticated on your machine. That means there is no API key to paste into Slate, and nothing leaves through a raw API endpoint: the brain's own CLI makes its model calls, using the auth you already set up for that tool.

Every tool Slate supports is a brain. There are five.

Google stopped serving Gemini CLI for Gemini Code Assist for individuals, Google AI Pro and Google AI Ultra on that date, and directs those users to Antigravity instead. The CLI still works on an API key or a Code Assist Standard/Enterprise licence, and Slate's driver is unchanged — but on a consumer account gemini now exits with IneligibleTierError before it reaches Slate, so the Gemini brain cannot answer. Verified on this machine 2026-09-02 against Gemini CLI 0.55.1. The other four brains are unaffected.

Each drives the matching CLI you already have installed. Which brains a workspace uses — and the account and default model for each — is set in Connect → AI tools, and a project may override it. Settings keeps only what belongs to the machine.

Cursor and Codex were the two that used to be "supported but not runnable": Slate governed them, captured their sessions and wrote their MCP config, and then could not ask either one a question — so a project on Cursor answered Slate's own prompts using somebody else's account. Both have had a headless mode all along (cursor-agent -p --output-format stream-json, codex exec --json), which is what closed it.

Two of the five have no config-directory variable — OpenCode (only OPENCODE_CONFIG, a single file) and Cursor (none documented) — so each has one account rather than several and the profile picker has nothing to offer them. That is a property of those CLIs, not a gap in Slate, and Slate says so rather than showing a field that would do nothing.

Transport

The actual model calls are proxied through Rust — src-tauri/src/ai/claude/, ai/gemini_cli.rs, ai/opencode_cli.rs, ai/cursor_cli.rs and ai/codex_cli.rs. Routing through the Rust host dodges the webview's CORS restrictions and keeps auth out of the renderer entirely.

Cursor's driver has no stream parser of its own: cursor-agent's stream-json is the Claude Code protocol event for event, so both read their turns through ai/stream_json.rs. Codex speaks a different vocabulary (thread.started, item.completed, turn.completed) and parses its own.

Only the Claude brain keeps a warm process across turns — it is the one CLI with a --input-format stream-json stdin mode. The other four take a prompt and exit, so Slate's console owns the history and re-sends the whole dialog each message (ai/dialog.rs). The practical cost is that their MCP servers cold-start per message, so Claude is still the brain to pick when connected MCP tools matter.

A Cursor turn is spawned with --force, which is what pre-approves the MCP servers Slate wired into .cursor/mcp.json. --approve-mcps is the flag whose name says that, and it does nothing in cursor-agent 2026.08.11 — measured, with slate/recall coming back rejected. --force is broader than the equivalent for Claude, so it is worth knowing what it does and does not change: shell commands already ran without it, so it is not what gives Cursor the filesystem.

Every brain's turn is bounded at ten minutes (ai/turn_reader.rs). A CLI that connects and then goes quiet — waiting on an auth callback nobody will complete, or on a model endpoint that took the request and will never answer — ends the turn with a timeout you can read, instead of a Console that shows work in flight forever. Four of the five drivers had no bound at all until 2026-08-22; only Claude's did.

Who runs the tool loop

The brain does. When a request isn't one of the curated commands, Slate hands the whole turn to the brain's CLI, which loops over its own MCP tools and stops when it's finished — so there is no step cap in Slate for a Console turn, and none that varies by provider.

The two agents Slate does drive itself are bounded, because nobody is watching them: the scheduled agent runner behind Loop stops after 6 steps.

Steps are not the only way an unwatched run goes wrong, so a run with nobody watching also carries a spend ceiling and a fallback model when the brain is Claude. The ceiling is $5 per run — a runaway catcher, not a quota: one turn costs cents, so it never interrupts real work, and what it stops is a loop that keeps re-asking. The fallback list is the rest of the Claude catalog, tried in order when the primary is overloaded, because a routine that fails because a model was busy is a routine that silently did not run. Both are set when the process starts, which is why they apply to routines, workflow steps and grounding passes and not to the Console: the Console's brain is one warm process reused across turns, and it is the one place somebody is looking.

Generating a workflow also hands the brain a JSON schema rather than only describing the shape in the prompt. Claude Code enforces it (--json-schema); every other brain is still held to the prose description and its reply is parsed out of the text.

Which account a brain runs under

A brain's CLI keeps its configuration — and its login — in a directory, and you may have several: a work Claude and a personal one. Which of them a brain uses is decided by the workspace it is running in, not by the machine: open Connect → AI tools and give each tool the one account it runs under there. A project may override the answer for itself.

That is also what governs sessions you start in a terminal, and what Slate captures. See Project environments.
