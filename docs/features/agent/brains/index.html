Agents & Model Providers

Slate calls its model providers agents. Each is a thin driver over an AI CLI you already have installed and signed in to. There is no API key to paste into Slate. The tool's own CLI makes the model calls, with the auth you set up for it.

The table follows the order Connect lists the tools. Features by Agent shows which tool has which feature.

The first six tools are measured end to end. The ten newest are not. Antigravity, Cline, Grok Build, Kiro, Qwen Code, Droid, Hermes Agent, Goose, Kilo Code and Auggie were checked against their CLIs on 2026-11-06: their version, help, MCP setup and the Agent Client Protocol handshake. A feature nobody has run on them, such as a Home turn, interrupting, asking before acting or reading token use, is marked unverified or not yet in Features by Agent. Where a tool's model list is short, it is a fallback: Slate asks the CLI first.

Connect → Agents sets which tools a workspace uses, and the account and default model for each. A group, or a project on its own, may override it.

OpenCode has no config-directory variable, so it has one account and no profile picker. OPENCODE_CONFIG_DIR only adds agents, commands, modes and plugins to that one config. Slate shows no field that would do nothing.

Gemini needs paid access since 2026-06-18. Google stopped serving Gemini CLI for Code Assist for individuals, Google AI Pro and Google AI Ultra on that date. The CLI still works on an API key or a Code Assist Standard or Enterprise licence. On a consumer account gemini exits with IneligibleTierError before it reaches Slate, so the Gemini tool cannot answer. The other tools are unaffected.

Transport

Rust proxies the model calls: packages/desktop/src-tauri/src/ai/ (driver.rs picks the driver from the tool's record in agentsAndHosts.json: claude/, codex_cli.rs, opencode_cli.rs, and acp_cli.rs for every tool that speaks the Agent Client Protocol). That avoids the webview's CORS limits and keeps auth out of the renderer.

Every tool keeps a warm process across turns in Home. A warm process is sent only your new message. A fresh one (the first turn, after a restart, or after you resume a past conversation) is given the history first. Resuming always starts a fresh process, so connected tools may sign in once more.

Claude Code and Codex speak their own protocols. Cursor, OpenCode, Gemini, GitHub Copilot and the ten newest tools speak the Agent Client Protocol (cursor-agent acp, opencode acp, gemini --acp, copilot --acp, grok agent stdio, droid exec --output-format acp, and so on: each tool's record in agentsAndHosts.json holds its arguments), in ai/acp/. Through it, Stop ends the turn without killing the process, the model can change mid-conversation, and the approval card appears when the tool asks. Cursor asks for anything outside your Cursor allowlist. OpenCode normally allows every tool, so Slate starts it with shell commands and edits set to "ask". Slate answers both by your autonomy setting.

If a tool does not answer the protocol within 20 seconds, Slate runs it one process per message for the rest of that app session. An automation's unattended turn on Gemini uses this path too. There is nobody to answer a card, so an ask is a refusal. OpenCode keeps its rule: Ask first refuses shell commands and edits, Auto-edit refuses shell commands, Full auto leaves OpenCode's default. Cursor's one-message process runs pre-approved. GitHub Copilot's (copilot -p) runs every tool only on Full auto. On Ask first and Auto-edit it may use only what your own Copilot settings allow.

An automation runs with nobody watching, one process per run. Claude and Codex reach the connected MCP tools you set up, and the automation's rules decide each call: reads go on, a call that changes something is held for your answer, and merging, removing and file changes are refused (Automations). Commands and anything needing more access are refused.

Every turn is bounded at ten minutes. A CLI that connects and then goes quiet, for example waiting on an auth callback nobody will complete, ends the turn with a timeout you can read.

Who runs the tool loop

The agent does. When a request is not a curated command, Slate hands the whole turn to the tool's CLI, which loops over its own MCP tools until done. A Home turn has no step cap in Slate.

An automation makes a fixed set of turns: a pass per place its brief checks, one turn that writes the report, one per prompt step. The tool loops over its own tools inside each.

A run with nobody watching has one spend ceiling of $5 for the whole run. Slate adds up the cost the tool reports and gives each new turn only what is left. When nothing is left, the next turn does not start and the run stops with a message. The ceiling catches runaways. One turn costs cents, so it never interrupts real work.

Only Claude Code receives the ceiling as a flag, with a cap of 30 tool turns per process and the rest of the Claude catalog as fallback models, tried when the primary is overloaded. A tool that reports no cost cannot be added up, so Slate counts its turns: at most 12 per run. These limits apply to automations, skill steps and grounding passes, not to Home, where you are looking.

A step is bounded by silence, not age. Every token, tool call, tool result or usage report restarts a 240-second clock. A step still answering keeps going. One that has stopped is ended.

Generating a skill also hands the tool a JSON schema. Claude Code, Codex and OpenCode enforce it, each through its own one-shot call (--json-schema, turn/start's outputSchema, opencode serve's session.prompt). Gemini and Cursor get the shape in prose, and their reply is parsed from the text.

Which account an agent runs under

A CLI keeps its configuration and login in a directory, and you may have several (a work Claude and a personal one). The workspace decides which one a tool uses. In Connect → Agents, give each tool the account it runs under there. A group, or a project on its own, may override it.

That also governs sessions you start in a terminal, and what Slate captures. See Project environments.
