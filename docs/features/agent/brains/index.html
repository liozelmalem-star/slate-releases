Brains & Model Providers

Slate calls its model providers brains. A brain is a thin driver over an AI CLI you already have installed and authenticated on your machine. So there is no API key to paste into Slate, and nothing leaves through a raw API endpoint: the brain's own CLI makes its model calls, with the auth you already set up for that tool.

There are five.

Not every brain offers the same features. Features by AI Tool shows which one has what, and why a gap is there.

Which brains a workspace uses — and the account and default model for each — is set in Connect → AI tools, and a project may override it.

OpenCode has no documented config-directory variable, so it has one account rather than several and the profile picker has nothing to offer it. OPENCODE_CONFIG_DIR only adds agents, commands, modes and plugins onto that one config — it does not relocate the account. Cursor gained CURSOR_CONFIG_DIR on 2026-09-20 and has a profile picker like Claude and Codex now. That is a property of the CLI, not a Slate limit. Slate says so rather than showing a field that would do nothing.

Gemini needs paid access as of 2026-06-18. Google stopped serving Gemini CLI for Gemini Code Assist for individuals, Google AI Pro and Google AI Ultra on that date, and directs those users to Antigravity instead. The CLI still works on an API key or a Code Assist Standard/Enterprise licence, and Slate's driver is unchanged — but on a consumer account gemini exits with IneligibleTierError before it reaches Slate, so the Gemini brain cannot answer. Verified on this machine 2026-09-02 against Gemini CLI 0.55.1. The other four brains are unaffected.

Transport

Model calls are proxied through Rust — src-tauri/src/ai/claude/, ai/gemini_cli.rs, ai/opencode_cli.rs, ai/cursor_cli.rs and ai/codex_cli.rs. Routing through the Rust host dodges the webview's CORS restrictions and keeps auth out of the renderer entirely.

Every brain keeps a warm process across turns in the Console. A warm process is sent only your new message; a fresh one — the first turn, after a restart, or after you resume a past conversation — is given the history first. Resuming a conversation always starts a fresh process, so connected tools may sign in again once.

Claude and Codex speak their own protocols. Cursor, OpenCode and Gemini speak the Agent Client Protocol (cursor-agent acp, opencode acp, gemini --acp), in ai/acp/. Through it, Stop ends the turn without killing the process, the model can change mid-conversation, and the approval card appears when the tool asks. OpenCode normally allows every tool without asking, so Slate starts it with shell commands and edits set to "ask" and answers by your autonomy setting. If a tool does not answer the protocol within 20 seconds, Slate runs it the older way — one process per message — for the rest of that app session.

A routine runs with nobody watching, one process per run. There, Claude and Codex use connected MCP tools you set up without asking, and still refuse commands, file changes and anything that needs more access.

Every brain's turn is bounded at ten minutes. A CLI that connects and then goes quiet — waiting on an auth callback nobody will complete, or on a model endpoint that will never answer — ends the turn with a timeout you can read, instead of a Console that shows work in flight forever.

Who runs the tool loop

The brain does. When a request is not one of the curated commands, Slate hands the whole turn to the brain's CLI, which loops over its own MCP tools and stops when it is finished. There is no step cap in Slate for a Console turn, and none that varies by provider.

The one loop Slate drives itself is the scheduled routine runner behind Loop, and it stops after 6 steps, because nobody is watching it.

A run with nobody watching also carries a spend ceiling of $5, and — when the brain is Claude — the rest of the Claude catalog as fallback models. The ceiling is a runaway catcher rather than a quota: one turn costs cents, so it never interrupts real work, and what it stops is a loop that keeps re-asking. The fallbacks are tried when the primary model is overloaded, because a routine that fails because a model was busy is a routine that silently did not run. Both are set when a process starts, so they apply to routines, workflow steps and grounding passes, and not to the Console, where somebody is looking.

Generating a workflow also hands the brain a JSON schema rather than only describing the shape in the prompt. Claude Code, Codex and OpenCode enforce it — each through its own one-shot call (--json-schema, turn/start's outputSchema, opencode serve's session.prompt); Gemini and Cursor are held to the prose description and their reply is parsed out of the text.

Which account a brain runs under

A brain's CLI keeps its configuration — and its login — in a directory, and you may have several: a work Claude and a personal one. Which of them a brain uses is decided by the workspace it is running in, not by the machine. Open Connect → AI tools and give each tool the one account it runs under there. A project may override the answer for itself.

That is also what governs sessions you start in a terminal, and what Slate captures. See Project environments.
