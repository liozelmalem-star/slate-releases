Features

Your Data & Export

Everything in Slate (docs, captured sessions, memories, decisions, automations, settings) lives in SQLite files on your machine: workspace.db for Personal, one more per shared workspace, and machine.db for what describes this computer. There is no proprietary container. There is no cloud copy unless you share a workspace or join one. Sharing publishes what is in that workspace, except what Privacy & Security says is never sent. Personal publishes nothing unless you switch its sharing on.

Where the file lives

PlatformPath
macOS~/Library/Application Support/app.slate.workspace/workspace.db
Linux$XDG_DATA_HOME/app.slate.workspace/ (~/.local/share/ when unset)
Windows%APPDATA%\app.slate.workspace\

To keep Personal elsewhere, such as an external drive or a synced folder, move it in Settings → Workspaces → (the workspace) → Storage. Its backups go with it, and the app, the MCP server your agents start and the capture hooks all follow. SLATE_DB_PATH points a single launch at another file, mostly for testing.

Where to find all of this

Open Settings → Workspaces, click the workspace, then Storage in its dialog. The dialog has up to three tabs: General (sharing, name, colour and the buttons that remove things, Delete workspace forever among them), Members (for a shared workspace) and Storage.

Only Personal can be relocated. Every shared workspace is a replica in Slate's data folder.

How big it is

The row under the path shows the workspace's size on disk and how much is space removed rows left behind. SQLite never shrinks a file on its own, so a workspace that churns only grows. Slate rewrites the file at launch when enough dead space is worth returning. Reclaim does it now. The button appears only when there is enough to return.

Exporting

Settings → Workspaces → (the workspace) → Storage exports the workspace in one click: a copy of the file whose row you opened, workspace.db for Personal or workspaces/<id>.db for a shared one. There is no conversion. The export is your database. The same screen opens the folder holding the file.

The format is open

The file is plain SQLite. Open workspace.db in any SQLite browser:

TableHolds
pageThe universal unit: docs, documents, mission docs, captured sessions
memoryPersistent knowledge with status and text
routineAutomations: what runs on a schedule or on an event, with its steps
artifact, artifact_versionPublished docs and apps, with every version
task, task_stepAgent runs and their steps
taskThe lines on your Tasks list
settingWorkspace settings
activityCommits, branch events and session records captured for this workspace
auditThe append-only log of workspace events

Doc bodies are block JSON, and Slate converts docs to and from Markdown.

Durability

  • WAL mode. Reads continue while the server writes.
  • Pre-migration backup. Slate backs up the database before any schema migration.
  • Stray workspace files are moved, never removed. Older versions could leave an empty workspaces/<id>.db that belongs to no workspace you joined. At startup Slate moves such a file into backups/, only when it belongs to no workspace and holds nothing beyond a brand-new database. Any other file stays.

Your data survives Slate. The file is standard SQLite at a known path, so you can back it up, move it, inspect it or read it years from now with other tools.

What the export does not contain

Your cloud session, if you signed in for sharing, sits outside the database. It is a 0600 file in Slate's app-data folder and stays there when you move Personal, so an export never hands someone a live refresh token.

Everything else is in the file. Before you share an export, know that:

  • A shared workspace's export contains your teammates' work too. Sync pulls their docs, memories, activity and artifacts into your copy.
  • Moving a doc into a shared workspace is a move, not a copy. It leaves your Personal file.
  • A project's memory settings travel with it. They, and where you said a memory goes, are in the same file.
