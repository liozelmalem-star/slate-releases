Features

Your Data & Export

Everything in Slate — pages, captured sessions, facts, decisions, agents, workflows, settings — lives in SQLite files on your machine — workspace.db for Personal, one more per shared workspace, and machine.db for what describes this computer. There's no proprietary container, and no cloud copy unless you create or join a shared workspace, which is a separate file: everything in it is published, and nothing in Personal ever is. If you can find the file, you own your data outright.

Where the file lives

Slate stores the database at a per-platform path:

PlatformPath
macOS~/Library/Application Support/app.slate.workspace/workspace.db
Linux$XDG_DATA_HOME/app.slate.workspace/
Windows%APPDATA%\app.slate.workspace\

You can point Slate at a different location by setting the SLATE_DB_PATH environment variable — handy for keeping the workspace on an external drive or in a synced folder of your choosing.

Where to find all of this

Settings → Workspaces, then Manage on the workspace you mean, then Storage. It sits on the workspace's own row beside Members and Delete, because a workspace's file is a property of that workspace — and because a list is the only thing that can answer which of yours is taking the disk. It was a Settings tab called Data until 2026-08-30.

Personal is the one you can relocate; every shared workspace is a replica that lives in Slate's data folder.

How big it is

The row under the path says what the workspace costs on disk, and how much of that is space deleted rows left behind. SQLite never shrinks a file on its own — removed rows leave their pages on a freelist the database happily reuses and the operating system never sees again, so a workspace that churns only ever grows. Slate rewrites the file on every launch when there is enough dead space to be worth it; the number here is what it found, and Reclaim does it now rather than waiting for the next start. The button only appears when there is enough to return.

Exporting

From Settings → Workspaces → Manage → Storage you can export your workspace in one click. Export is exactly what it sounds like: a copy of the workspace whose row you opened — workspace.db for Personal, workspaces/<id>.db for a shared one, and the row names which. There's no transformation and no lossy conversion — the export is your database.

The same pane can open the folder holding the file if you'd rather grab it yourself.

The format is open

The file is plain SQLite. You don't need Slate to read it. Open workspace.db in any SQLite browser and you'll find your content directly:

TableHolds
pageThe universal unit — pages, documents, missions, captured sessions
factPersistent knowledge with status and text
agentScheduled background agents
workflowMulti-step workflows
settingApp and workspace settings
activityCommits, branch events and session records captured for this workspace

Page bodies are stored as block JSON, and Slate can convert pages to and from Markdown — so your writing isn't locked inside a binary blob either.

Durability

Two things protect the file while you use it:

  • WAL mode. The database runs in write-ahead-logging mode, allowing concurrent reads while the server writes.
  • Pre-migration auto-backup. Before Slate applies any schema migration, it backs up the database first. An upgrade can't leave you without a fallback.

Your data survives Slate. Because the file is standard SQLite at a known path, you can back it up, move it, inspect it, or read it years from now with tools that have nothing to do with this app.

What the export does not contain

Two things sit deliberately outside the database:

  • Your cloud session, if you signed in for sharing. It's a 0600 file beside workspace.db, kept out on purpose — an exported workspace must never hand someone a live refresh token.
  • Nothing, actually. A shared workspace is its own SQLite file on your machine, and the sync pulls your teammates' pages, atoms and activity into it — so exporting that workspace exports theirs too. Moving a page into a shared workspace is a move, not a copy: it leaves your Personal file.
