Built-in automations

Slate runs thirteen things on its own. Automations › Built-in says what each does and what turning it off costs. Eleven have a switch. The other two are Slate's own upkeep and always run: clearing the queue a finished session leaves behind, and the startup repairs.

Built-in is a section of Automations: in its side panel, the row Built-in under Overview. Automations holds your own automations and these built-in ones side by side. Until 2026-11-06 this list was a Settings tab (ADR 0116).

One answer for every workspace

Ten switches are in Automations › Built-in. Each is for the whole app: off stops it in every workspace. Most pause something you already choose one by one (each automation has its own switch, each reminder is set on one task, each workspace is shared or not). This switch pauses all of them at once.

AI memory care is the exception. It spends your agent's tokens on the account of the workspace it reads, so each workspace chooses it. Its switch is in Memory, on the Memory care row above Needs review.

Auto-capture shows twice in Automations › Built-in, as a card at the top and as a row in the list. It is one switch.

Capture one agent, not another. Auto-capture is the master switch. Under it, each agent whose transcripts Slate reads has a Capture switch on its row in Connect → Agents. Off, and that tool's sessions are not recorded; it stays connected and other tools are unaffected. Cursor has no such switch: its capture is the hook on the same row.

A switch takes effect on the next tick, not the next launch: within a minute for the automation tick, within two for sync and the merge check. Auto-capture stops or starts at once.

What reaches the network

Two reach it on Slate's own account, both named in Privacy & Security: the update check asks for a release manifest, and shared-workspace sync mirrors the workspaces you joined.

Four more reach it only through something you set up. Scheduled automations, the automations a session ending starts, agent runs and AI memory care run through your agent's CLI, under its auth. The agent run merge check and revert search run your own gh or glab against your code host; the revert search is GitHub only.

The rest are local. Capture, reminders, startup repairs and the menu bar icon read files on your disk and write to your own database. Keep-awake only asks the operating system not to sleep. macOS shows the session notification on this computer alone.

Turning something off never removes anything. Capture off keeps sessions already captured. Sync off does not withdraw docs already shared; that is leaving a workspace.

Keeping the computer awake

An automation that starts at 7:00 does not run if the computer slept at 6:45. This switch stops that, only while there is work.

Work is a session whose status is working, a running automation, and a turn of Slate's own agent. A session only waiting for you does not count. When the last piece ends, the computer may sleep on its usual schedule. In safe mode the switch does nothing.

Turn it on in either place; both are the same switch:

  • the coffee-cup button in the top bar, on every screen. It turns green with a live dot while holding the computer awake. Click it for the switch and what is holding it, such as "Holding now — 1 session working, 1 automation running";
  • the Keep the computer awake row in Automations › Built-in.

It never keeps the screen on. It never stops you sleeping the computer from the menu, and on a Mac on battery closing the lid still sleeps it. It ends when Slate quits or crashes. On macOS it is the request caffeinate -i makes, and pmset -g assertions lists it under Slate.

The repairs at startup

Each start, Slate fixes rows that earlier versions wrote wrongly, such as a doc indexed with empty search text or left under a parent that no longer exists. Some fixes run every start, others once. The same pass tidies up: log entries older than 400 days, and apps you have not opened for 60 days (after a 7-day warning). It has no switch.
