Features

Automations

Slate runs thirteen things on its own. Each is invisible while it works, which is fine until you want to know what the app is doing right now, or make it stop.

Connect → Automations answers both. Every automation says what it does and what turning it off costs, and each has a switch. The one exception is an automation that needs an AI tool, in a workspace that has none set. It sits in Connect, beside what this workspace runs and what it can reach.

Whose background it runs in

The page is in two groups, and the heading a switch sits under answers the question people actually have: does turning this off affect my other workspace?

This workspace. Seven of them act on one workspace's own rows — its agents, its pages, its sessions, its tasks. Turning one off in Personal leaves Tasks running.

Four of them work through the workspace's AI tool: Scheduled agents, Notice a session ending, AI runs and AI memory care. In a workspace with no AI tool set they are dimmed and have no switch. The three that are on by default say they start on their own once you connect an AI tool; AI memory care says you can turn it on after. Shared workspace sync and Reminders keep working.

This computer. The other six govern something there is only one of on this computer: the app that updates itself, the notification a waiting session sends, the menu bar icon, opening Slate at login, the capture that reads your transcripts, and whether the computer may sleep. Turning one off turns it off everywhere.

Startup repairs sits apart, in a folded Maintenance group under This workspace. Auto-capture is shown twice in This computer: as a card at the top, and as a row in the list. Both are the same switch.

Capture one AI tool, not another. Auto-capture is the master switch. Under it, each AI tool whose transcripts Slate reads has its own Capture switch on its row in Connect → AI tools. Turn it off and that tool's sessions are not recorded; the tool stays connected, and other tools are not affected. Cursor has no such switch: its capture is the hook on the same row.

A switch takes effect on the next pass, not the next launch. Each loop asks whether it is allowed to run every time it ticks, so turning something off stops it before its next tick — within a minute for the agent tick, within two for sync and the merge check. Auto-capture stops or starts at once.

What none of them do

Two of these reach the network on Slate's own account, and both are named in Privacy & Security: the update check asks for a release manifest, and shared-workspace sync mirrors the workspaces you joined. Four more reach it only through something you already set up. Scheduled agents, the agents a session ending starts, AI runs and AI memory care run through your AI tool's CLI, under the auth you gave that tool, and the memory-care readings use that tool's tokens. The AI run merge check and the revert search run your own gh or glab against your code host. The revert search is GitHub only. The rest are local: capture, reminders, repairs and the menu bar icon read files on your disk and write rows to your own database, keep-awake only asks the operating system not to sleep, and the session notification is shown by macOS on this computer alone.

Turning something off never removes anything. Capture off does not remove sessions already captured; sync off does not withdraw pages already shared (that is leaving a workspace); startup repairs off does not undo repairs already made.

Keeping the computer awake

An agent that starts at 7:00 does not run if the computer went to sleep at 6:45, and a long agent session stops when the lid of an idle machine is left open long enough. This switch stops that — only while there is work.

It counts as work: a session in Sessions whose status is working, an agent that is running, and a turn of Slate's own agent. A session that is only waiting for you does not count. When the last piece of work ends, the computer may sleep again on its usual schedule. In safe mode it does nothing.

You can turn it on in two places, and both change the same switch:

  • the coffee-cup button in the top bar, on every screen. It turns green, with a live dot, while it is holding the computer awake. Click it to open a small panel with the switch and, while it holds, what is holding it, such as "Holding now — 1 session working, 1 agent running";
  • the Keep the computer awake row here, under This computer.

What it does not do:

  • It never keeps the screen on. The display turns off on its usual schedule.
  • It never stops you putting the computer to sleep from the menu. On a Mac on battery, closing the lid still sleeps it.
  • It never outlives Slate. The request ends when Slate quits, or even crashes, so the computer is never left stuck awake.

On macOS this is the same request caffeinate -i makes, and pmset -g assertions lists it under Slate.

Startup repairs, honestly

This is the one switch that can leave you worse off. The repairs exist because earlier versions of Slate wrote data that later versions know how to fix — a page indexed with empty search text, a page left under a parent that no longer exists. Some run on every start and write only the rows that are wrong. Others run once per fix. It also holds the sweeps that tidy up after use: log entries older than 400 days, and apps you have not opened for 60 days.

Turn them off and Slate stops correcting itself. Anything a past version broke stays broken, and a repair shipped in a future release will not reach your data until this is switched back on. The switch is here because a thing that rewrites your database on launch should be something you can see and stop, not because turning it off is a good idea.
