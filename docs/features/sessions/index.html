The Sessions tab lists every AI-CLI session on this machine, live, for the 16 agents. Nothing to install. If the capture watcher can see a tool's transcripts, the tracker sees its sessions, including non-default config directories. Claude Code lists its own sessions (claude agents --json), so its rows carry the real session id, the process behind it and whether a background job has finished. The other tools are read from their transcripts and the process table. That is measured on Codex, Cursor, GitHub Copilot, OpenCode, Gemini, Hermes Agent and Goose, and unverified on the others (Features by Agent). A row shows the session's name when it has one (Naming a session).

Sub-agents are not sessions. The parent's row says how many are live beneath it and expands to name them; on the map each is a pip around its session. Only recently active ones are listed, and nothing offers to stop one, because it runs inside its parent's process.

What you see

The list is the live sessions on the whole computer. A session that ends folds into Just finished and Earlier today. Each live session has one of three states:

  • Needs you: the tool finished a turn and is blocked on you. ⌘⇧J goes to the one that has waited longest, and again to the next. The count sits in the tab's header. Three kinds: Needs permission (a tool call waits for your yes), Asks you (the turn ends on a question) and Finished (the turn is a report). When a session starts waiting on a permission or a question and Slate is not in front, macOS shows one notification with the question, once per wait, never for what was already waiting when Slate opened. A finished turn posts nothing; it waits on Home. Tell me when a session needs me in Automations › Built-in turns this off.
  • Working: the transcript is being written now.
  • Idle: quiet, and you spoke last. A session that only waits is idle too, however fresh its transcript: its newest call is a loop on the gate lock (slate-heavy.lock), a sleep still running, or a ScheduleWakeup. The wait must be the whole command: sleep 5 && yarn test is work. The dot is grey and does not pulse, and its flow word says Waiting.

In the menu bar

A Sessions icon in the menu bar shows a count while a session needs you. Its panel lists the sessions working or waiting on you, waiting ones first in Home's order (permission, question, finished), each with its kind, tool and workspace colour. Click one and Slate opens on it. The panel also has Keep the computer awake, New session, Open Slate and Quit Slate.

Closing the window only hides it, so the icon and your sessions stay; ⌘Q quits. A hidden window stops reading sessions and stops every timer, and catches up when you open it. The icon's count, the notification and keep-awake come from Slate's server, so they work while it is hidden. A visible window you are not using shows changes within 5 seconds, and its other timers run at a quarter pace. Two switches in Automations › Built-in: Show Slate in the menu bar (on) and Start Slate at login (off).

Branches waiting for review

A worktree branch whose agent has finished, with commits main does not have, is waiting for you. Slate finds these in every project it knows. A worktree with a session whose turn is still open is not waiting.

Each is tagged on its row, under its project, beside its branch: Review · n files ›, then behind n when main has moved past it, then how long it has waited, all grey. The row shows even when nothing runs in that project. If the branch still has a session, the tag sits under that session's row. When a project holds several git repositories, the row names the git repository first (editor · feat-x).

A branch main has moved past cannot merge until its session rebases. With nothing running in it, its row folds into a closed line at the end of its project, Behind main · n (named for the branch it left, such as master), closed each time the rail is drawn. A branch with a session, and a kept branch, stay in view.

Click the tag to open the branch's review (Reviewing the whole branch). Review & merge is also in the row's ⋯ menu. The header counts waiting branches as n to review; click it to open the one that has waited longest. Above the review:

  • Merge into main fast-forwards main to the branch, then removes the worktree (the project's On remove command runs first) and the branch. It never makes a merge commit and never checks a branch out. When no checkout holds main, only the ref moves; when one does, that checkout moves too, and the merge is refused if it has uncommitted changes to a file the merge would change. It is also refused while the worktree has uncommitted work, while an agent's turn is open there, and when the branch has new commits since the review was drawn. It stays grey until the review has loaded.
  • Ask to rebase replaces Merge when main has moved. It pastes Rebase this branch on main and run the tests again. at that session's prompt without pressing Enter, or copies it when no session in Slate is there.
  • Keep leaves the branch and turns its tag into a grey Kept, out of the count; the button then reads Unkeep. Kept is remembered on this computer only. New commits from the agent make the branch waiting again.
  • Discard first lists every commit on no other branch that will be lost, and whether uncommitted work goes too. Confirming removes the worktree and the branch. Uncommitted work that appeared after the confirm opened is refused, not removed unlisted. Discard is also refused while an agent's turn is open, and when the branch has new commits since the review was drawn.

A branch is measured against origin/main as well as the local main, because worktrees start from origin/main and the local one is often behind. Commits either holds are not the branch's work. The tag, review, Branch changes and the rail's counts all measure this way. The tag's number leaves out untracked files, so the review can hold more files than the tag says.

After Merge or Discard the next waiting branch opens, oldest first. If main moved but the worktree cannot be removed (its On remove command failed, or it is locked), the merge still counts and a notification says why the worktree was kept. The project's main branch is never merged or discarded from here.

Narrowing to a workspace or a project

A workspace picker under the side panel's title starts on All workspaces each time the tab opens. Pick one and only its sessions stay, in the list and on the map. A session no workspace claims counts as Personal's. A project picker then appears beside it, on All projects, listing that workspace's projects; a project keeps the sessions that run in it or in its git repositories and branches. Changing the workspace drops the project. The choice lasts while the window is open. Just finished and Earlier today follow the pickers. Opening one of their docs, or All past sessions, from a workspace the window is not in switches the window to that workspace first.

The map and the list

Two views of one list. The map shows the shape of the machine and the rail reads it out. Hovering either lights up the other; pointing at a project or branch lights every row under it.

The map is a radial tree with this machine at the centre: group → project → branch → session. A project on its own sits on the first ring; a project in a group one ring further out. A session with no project and no branch hangs from Everything else. When more than one workspace has work running, a workspace ring sits inside the group ring. Each level divides its parent's angle in proportion to the sessions beneath it. Colour is the workspace's colour from the switcher. The halo around a dot is its status, and a node wears the most urgent state beneath it.

Names sit on a small chip, cut in the middle at 16 characters for a workspace, 20 for a project and 18 for a git repository. A branch keeps the start of its name, cut at 15 (fix/sessions-gr…). Point at a node for the whole name.

Moving around. The map always fits the panel: no zoom, pan or scroll. Click a group or project to redraw the map with it at the centre; the rail narrows to its sessions and a crumb trail names where you are. Any crumb jumps to that level. All, a click on empty space, or Escape returns to the whole machine. Drag a node to reorder it among its siblings; Reset layout undoes it. Below about 1024px the map is dropped and the rail shows everything.

The rail has two levels: the group or project, then its sessions. Each row names its branch, and its project too when the group holds more than one. With two workspaces running, a heading names both (Work / Beacon). Every level is ordered by urgency, then name: most blocked sessions first, then busiest, then longest waiting. Inside one, blocked comes before working before idle, longest-waiting first. The order holds still while the pointer or focus is in the rail.

A session groups under the group or project its folder is filed under. A session in a git repository no project holds yet groups under the git repository's name, and Slate makes it a project the first time it records the session. Anything else (a plain folder, your home folder, no folder) groups under Everything else.

Each row shows a status dot, title, live line and meta line.

  • Title: the session's branch, with what its checkout holds and its pull request beside it (ui/hotfixes ↑4). It also heads the session's doc and tab. The tooltip shows what the session was asked to do (or its name) and the branch's goal. With no branch, the title is its name, else its opening prompt. The name Claude Code gives an unnamed session (the folder plus two characters, slate-66) counts as no name. On Home a card already shows the branch, so it is titled by what the session was asked.
  • Live line: the question when it waits on you; what it just said it was doing when it works; the next unticked item from its doc's plan when it has gone quiet with work left.
  • Meta line: the tool's mark, how long ago it moved, how it runs, how full its context is, and its flow as a small strip with the word of its current stop ("Build", "Check", "Waiting"), or plan progress (0/4) with no flow yet. A terminal glyph means Slate runs it and you can type into it; an eye means it runs in your own terminal and Slate only follows along. A session with an unseen transcript flag shows a Flagged badge; point at it to list each flag and its run.

Amber means the session needs you. A working session has a green dot that pulses three times when work starts, then holds still. Idle is grey. Added and removed lines are green and red, missing and failures red, the live sub-agent count blue. Everything else is grey.

Context fill comes from the session's own transcript. Codex states its window, so it shows a bar and 8% of 258k, darker from 75%. Claude Code and OpenCode do not state a window, so they show the count alone (323k). Gemini and Cursor record nothing per turn, so they show nothing. A session's tab shows only its status dot and name.

A row says what its checkout holds: commits it has that its base lacks (↑3), how far the base moved on (↓1), a grey ring for uncommitted work, and missing for a worktree git lists but cannot read. A clean branch level with its base says nothing. A checkout with nothing running is listed too, as checked out, nothing running. A branch with a pull request shows its number (#118), and a session that did real work and recorded no memory shows an owed pill.

A session is listed where its edits land. An agent started in one checkout can edit another worktree of the same project by full path. Slate lists it under the worktree its most recent edit went to, however long ago, with that worktree's branch and from <folder> naming where its terminal is. Until it edits anything it sits under its start folder. An edit outside the project does not move it. The same rule picks the branch Slate briefs the session on and the doc its memories are filed under.

Click a row to open the session in a temporary tab that the next row click replaces; a double-click keeps it. Pointing at a row shows ⋯, End (a second click ends it), what its branch changed (the whole review, no session needed) and the + that starts a session there. The ⋯ menu starts with the session's own acts:

  • Open beside puts it next to the one you are in (Sessions side by side). ⌘-click does the same.
  • Open PR opens the pull-request sheet (Opening a pull request). With nothing to compare it is grey and says why: Not on a branch, On main: nothing to compare, No commits ahead of main, or Nothing committed yet (10 files changed). Once origin has a pull request, PR #118 opens it in your browser and Open PR stays beside it for pushing new commits.
  • Hand back to my terminal, on a Claude Code session Slate runs (Moving a session back to your terminal).

Below a rule: New session, New worktree (on a project row with several git repositories), Copy path (the session's folder), Make a project (on a row in Everything else) and Copy resume (the tool's own resume command, such as claude --resume <id>; the first six tools have one, and the ten newest have none yet).

Park hides a checked out, nothing running checkout from the rail without removing anything. It folds into a Parked · n line at the end of its project, with Unpark beside each. A checkout with a running session, or a branch waiting for review, is never hidden. Parked checkouts are remembered on this machine only.

Just finished sits dim at the foot of the rail for ten minutes. Each row shows its tool's mark and when it ended, with a tick only when its last turn finished; a session stopped mid-turn says "Stopped before it finished". A click opens its record, or the doc the work belongs to until the record is saved.

Earlier today in \<workspace> folds every other session from today (your local day), leaving out what Just finished shows and every running session. It is collapsed with its count. All past sessions in \<workspace> → opens the whole history, newest first, at /sessions?past=1, with no time limit; each row has a Resume button.

With nothing selected, the main area shows the map. The header counts what needs you, and ⌘⇧J walks the waiting sessions longest-waiting first. A failure (a Run preview that fails, a refused start, a failed Stop) shows under its row, or at the head of the list when the row is off screen. The rail lives in the app's left side panel: drag its edge to resize it, and ⌘\\ hides it when a terminal wants the whole width.

The keyboard

Tab reaches the rail's rows and Enter opens one. ↑/↓ or j/k move between rows, Home and End jump to the ends (movement stops there), and Escape hands focus back to the terminal. ↑ or k from outside the rows enters at the last row. Cloud rows are in the walk.

On the focused row, f starts a second agent in its folder and s stops it. s needs a second press within four seconds. On a cloud row both do nothing, and f does nothing on a row with no folder.

These letters belong to the list, so they act only once focus is inside the rail and never while a text field has focus. Modified chords (⌘⇧J, ⌘K) pass through. From anywhere, ⌘K → Focus the sessions list moves focus to the first row; it is listed only while a session row is on screen.

Starting a session

Where you are looking is where it starts. Point at a group, project or branch (a map node, heading or rail row) and a + titled New session appears. It starts a session there at once, on the tool its group or project names as its default, under its account, and opens it in Slate. There is no picker. A project also has New worktree, which opens the worktree form with that project chosen. A group or project with nothing to run in shows no control. A refused launch shows on the tab in its own words.

The + in the side panel's title row starts a session somewhere you are not looking, or on a different tool. It shows where a session can run as a tree, group → project → branch, with a workspace level above when more than one workspace has work. Click a row to start there. A row with its own folder shows it. A git project's last row is New worktree…; a plain folder has none.

A session runs as the workspace its place belongs to, whichever workspace the window shows: a work project picked while Personal is on screen starts on the work workspace's tools and account. A refused start shows at the top of the picker, and every start, refusal and failure is written to slate.log.

Start without a project, at the bottom of the picker, starts a session for a question, a plan or a quick script. It runs in a folder Slate keeps for the workspace inside its data folder, so it never sees your home folder or a git repository. The rail groups it under Everything else.

Open folder… starts a session in any folder you pick. Recent folders lists the last few folders sessions ran in that no project holds, leaving out temporary folders (/tmp included), the agents' own folders and Slate's data folder. A folder another workspace already holds opens there. Otherwise it becomes a project in the workspace on screen, by the same rules as New project, onboarding and Make a project:

  • A worktree or subfolder of a git repository stands for that git repository.
  • A folder Slate already knows opens its doc. A doc in the Trash comes back.
  • A folder inside a group becomes a project in that group.
  • A plain folder holding two or more git repositories asks first: Add as a group, Add as one project or Not now.
  • Anything else becomes a project on its own.

Your home folder and the disk root are refused, because every session would file under them. When a folder becomes a project, its sessions move out of Everything else into it.

You choose your projects

Slate makes no project on its own. Setup's last step lists the folders your AI sessions ran in, newest first, with nothing ticked; the ones you tick become projects. A session in a folder no project holds is still recorded, under Everything else. Adding the folder later (from setup, + in Projects, or the session's row) moves its earlier sessions in. Setup never lists your home folder, a temporary folder, an agent's own folder, Slate's data folder or a folder you removed. A removed project stays removed until you restore the doc or add the folder yourself.

A row in Everything else offers Make a project behind its ⋯. With more than one workspace the menu names each (Make a project in Work), the session's own first. A folder no workspace claims is filed in Personal, so it is private by default.

Runs on is asked once, above the tree. It lists the agents connected in Connect → Agents for the workspace in focus and names that workspace when more than one has work. It starts on that workspace's default; picking another tool changes this session only. The worktree form has the same control. Groups and projects with no linked folder are not offered.

A chat instead of a terminal

Chat, beside + on a group heading and on a map node, and in a row's ⋯ menu, starts the tool of that group or project but draws it the way Home does: each turn, each tool step as it runs, and an approval card wherever the tool needs your yes. A row's chat works in that row's checkout. It opens as a tab named after the group or project, and its composer shows the folder.

The chat's tool does not share Home's, so chatting in a worktree never restarts Home's conversation. The chat lasts as long as its tab: Close and end this chat stops its tool, and so does quitting Slate. A chat is not recorded as a session in the list. Use a terminal session for work you want to leave running.

Cloud sessions

A cloud session runs on your agent's computer, so it keeps going when yours sleeps. Claude Code and Codex have them. Gemini and OpenCode have none, and Cursor's cloud agents have a web API only (agent features).

Start one from New session → Cloud: write the task, pick a project, press Start in cloud. Only git repositories are offered, because the cloud session works on a copy. The form says what will leave your computer:

  • Claude clones the project's GitHub remote at its current branch, so push first. A project with no GitHub remote is uploaded instead: its history and uncommitted changes to tracked files, not untracked ones.
  • Codex runs in an environment you set up for the git repository at chatgpt.com/codex, on its GitHub remote at your current branch. Type the environment's name; the names used before are offered, and the last one used from a project is filled in next time.

It runs under the project's profile. Slate asks that account's CLI whether it can start one before you can press Start. Claude needs a claude.ai sign-in: an account that uses an API key, a token, Bedrock or Vertex cannot, and the form says so. Codex needs a ChatGPT sign-in; an expired one is told to run codex login.

Find it in the list under the project it started from, with a cloud where the status dot sits. A Codex row says where the session stands (working, ready, applied or failed); Slate asks Codex's list once a minute while Sessions is open. Claude keeps no list, so its row says the status is on claude.ai.

Its doc shows what you asked and every message you sent, with the controls its tool has:

  • Claude: Send a follow-up (queued, answered on claude.ai). Bring back opens it in a new worktree with the whole conversation, as a normal session here.
  • Codex: no Send. Show diff is read-only. Apply in a worktree lands the changes, uncommitted, in a new worktree and opens the branch's changes.
  • Both: Open on the tool's site, and Remove from Slate (it stays on the tool's site).

Neither tool offers Stop, and the doc says so.

Removed on the tool's site. Codex says so when Slate asks, and the session leaves the list. Claude says so only when Slate next sends it something: the first Send to a session you removed on claude.ai drops it, with a sentence saying why.

Started somewhere else. Claude has no command that lists cloud sessions, so Slate keeps its own record: the sessions Slate started, and the ones another Claude Code session started while Slate's hooks were connected to it, through a scheduled task run with the RemoteTrigger tool (run, or create for one that runs at once) or claude --cloud "<task>" from that session's shell. Slate's hook files the session under the project that holds the calling session's folder, and the row appears within 15 seconds while the window is open. It says started by a scheduled task or started from another session, and counts only the messages Slate sent. Send, Bring back and Open on claude.ai work as on any Claude row. Codex lists only the sessions Slate started. Not recorded: a cloud session started on the web or phone, and a scheduled task that fires on its own schedule, because no session on this computer sees those start.

What Slate remembers. A Claude cloud session brought back writes its whole conversation into a normal transcript once you send it a message, and Slate captures it like any session. One never used leaves none. A Codex session brings back changes, not a conversation, so applying it notes on the project's doc what changed. A running cloud session has none of Slate's hooks and cannot reach Slate's memory, so what it decides arrives as a record. ADR 0071 explains why Slate uses only each tool's own CLI.

On my phone

A session can keep going from your phone while it runs on this computer. Slate has no phone app: you pick the session up in your tool's app. Today that is Claude Code, in the Claude app (the Code tab) or at claude.ai/code.

Start one on the phone by turning on On my phone in New session, above the options beside Runs on. Put a running session on the phone with On my phone at the top of its doc. Either way a card titled Ready on my phone opens with three steps and the session's claude.ai link, with Copy and Open. The same button, now blue, reopens it; Stop phone access turns it off. A session on the phone shows a phone mark in the list, and the header counts them. Slate reads this from the transcript, so it also shows a session you put on the phone by typing /remote-control in your own terminal.

The control is on every session and greyed out with a reason where it cannot work. It works for Claude Code running in Slate. For Claude Code in your own terminal it is shown but not switched from Slate: type /remote-control there. It does not work on an account that cannot (API key, token, Bedrock or Vertex, or off by your organization), and the reason is Claude's own. Codex pairs your whole computer with the ChatGPT app, not one session, so it is not supported yet. Cursor's phone control is in its app, not its command line. Gemini and OpenCode have none. Slate asks Claude (claude doctor) once per account whether it can.

It still runs here, so Slate's hooks, memory and capture work as always. While it is on, the conversation also goes through Anthropic, which keeps it. ADR 0072 explains why.

Worktrees

The worktree form asks for a Branch and a From branch (local branches only, nothing is fetched), and shows the Folder it will make, always a sibling of the project. Then it starts a session inside it.

Carry over makes the new folder usable. git worktree add copies tracked files only, so a fresh worktree has no dependency tree, .env or build output. The form offers what the project ignores at its top level as chips; tick node_modules, skip .DS_Store. On a Mac each folder is cloned copy-on-write: no disk cost until a file changes, and a change in the copy never reaches the original. Elsewhere files are hard-linked. Nothing carried is tracked. The form says what it is carrying while Slate stays usable. If a ticked path is missing or its copy fails, the worktree is made, the form names the path and holds the start, and offers Start anyway.

A worktree that fails to finish is rolled back. If carry-over breaks, or Then run fails, Slate removes the folder, git's record of it and its port, and shows the error with the command's output. It removes the branch too when Slate made it for this worktree and nothing has moved it since; a branch that already existed stays. Fix the cause and press Create and start again with the same name.

Then run is one command run in the new folder once the files are there: a build step, a codegen pass, a submodule fetch. Empty is normal. On remove is one command run in the folder just before a worktree is removed, however it is removed. Use it to stop a dev server, drop a local database or free a port. If it fails, the worktree is kept and the error shows what it printed (it can take up to 60 seconds). Both run in your login shell (/bin/sh -lc) on macOS and Linux, PowerShell on Windows (cmd if missing), untranslated, so write them for your shell.

Carry over, Then run, On remove and Run preview are saved on the project (and so on its group for later worktrees), only when you press Create and start. Closing the form or Back saves nothing.

Each worktree Slate makes has its own port, a free one from 4100 to 4999, kept until the worktree is removed and stored on this computer only. It is SLATE_PORT in Then run, On remove and every session terminal started in that folder or inside it, so two worktrees can each run vite --port $SLATE_PORT. The row shows it as :4101. A worktree you made by hand has none. Sessions there also get the worktree's own temp folder outside it: TMPDIR, TMP and TEMP point at it, and it leaves with the worktree.

Run preview is the command that starts a checkout's dev server, such as yarn dev. A session row's ⋯ menu offers it. It opens the command's terminal beside the session, so a failure says why. When the server prints a local address (http://localhost:5173), it opens as a Preview tab in the same strip. The preview can reload, open in your browser, or Stop, which ends the server's terminal and closes the tab; the tab also closes when the terminal ends. The first run on a project with no command asks for it, and Save and run stores it. A checkout with no project runs it once and saves nothing.

Pick (the crosshair) turns the preview into a picker. Point at anything to outline it, click, and its description is pasted at the prompt of the session in that folder: the doc it is on, a CSS selector, size and position, deciding styles and its HTML. Nothing is submitted; add what should change and press Enter. There is no screenshot, because the preview has a different origin than the app. To pick, the web page is framed through a small proxy Slate runs on its own loopback port. It adds one script, answers only requests to its own loopback address, and proxies only a dev server on this machine. Hot reload keeps working. Click the crosshair again to return to the plain preview.

A worktree made for a session ends with it. When the session you started in a new worktree ends (you exit the tool or press Stop; closing its tab is not an end), Slate removes the worktree:

  • Nothing uncommitted, branch merged or empty: folder and branch both go.
  • Commits not merged: the folder goes and the branch stays.
  • Uncommitted changes: Slate asks once, Keep worktree or Delete forever.

First Slate stops what the session left running there: every process whose working folder is inside the worktree (dev server, watcher, test run) gets a polite stop, then a forced one after 3 seconds. It goes by folder, never by port, and spares shells, tmux, screen and apps, so a terminal tab you left open stays. On Windows, which cannot see another process's working folder, it stops a process whose program or command line names a path inside the worktree, or that listens on the worktree's port, with everything it started, at once. A process started with a relative command line and no Slate port is not found there.

One message at the bottom of the window says what was given back, Cleaned up · stopped :3000 · 11.2 GB freed, and on a second line what happened to the worktree and branch; if counting takes over about 3 seconds the size is left out. It waits while another session is still working in the folder. It never touches a worktree it did not make for a session: one you made by hand, one another tool made, or one whose session was running when you quit Slate. The folder is renamed aside at once and removed in the background, so a large dependency tree holds nothing up.

Removing a worktree by hand is offered on a branch row in New session, under the trash icon. It stops no processes and counts nothing. It refuses a checkout with uncommitted work unless you say to discard it, and can remove the branch too. A dirty branch is marked before the click, and a worktree git cannot read says missing.

Starting a session from a doc

A branch, project or group doc has a Start session button in its header. It runs the tool that doc's group (or project on its own) has connected, in the folder the doc stands for, under the account its group or project assigns to that tool, and opens it in Slate. Any doc with a folder also has a button for a plain terminal.

If the doc has a Goal, that line is seeded into the CLI's prompt with the next unchecked plan item (Continue on feat/x: … — next: …). It is typed, never sent: you read it, edit it and press Enter. It is always one line, because a newline in a terminal prompt is a send. Slate watches the session's output for the line. If a CLI's startup repaint swallowed it, the terminal says so and offers the line back to Insert it or copy.

When a session cannot start, the refusal names what to do: "Acme does not use gemini. Sessions under /code/acme use: claude. Add it in Connect → Agents to allow it here." A doc with no folder is refused the same way.

A doc shows what is running on it. Sessions working towards a doc appear in its header as needs you, working or idle. Click one to open it. This prevents starting a second session on a branch that already has one working.

The terminal

A session Slate hosts runs on a real pseudo-terminal the app owns, so the CLI behaves as in Terminal.app: colours, spinners, the full TUI. It is the same CLI under its own limits. Slate supplies the folder, account and context and stays out of the conversation. It is captured like any session. The CLI sees TERM_PROGRAM=Slate.

Terminal | Conversation, above the session, switches the main area. Conversation is the session read from its transcript: each message formatted, each tool step as it runs, and a prompt under it. Enter there is Enter at the terminal's prompt; Shift+Enter is a new line. / lists the skills the tool loads in its folder. @ names a doc, session, memory, task, automation or report, whose content is sent in front of your words, as on Home. Menus and permission dialogs the tool draws itself show only in Terminal. When the session waits on a call with no result yet, a bar above the prompt names it and Open Terminal switches there. Every session opens on Terminal; a pick of Conversation holds for that session only. A plain shell has no conversation and no switch.

Slate starts a Claude session as a background job (claude --bg, which begins idle and spends no turn) and opens a view onto it. It belongs to no terminal, so you can pick it up in Slate, in any terminal, or after Slate has quit. A tool with no such mode starts the ordinary way. Navigating away or reloading the app does not end a session; coming back replays what it said meanwhile.

The terminal gets the window. A session's tab draws no doc chrome. One line above the terminal shows how far its plan has got and what is next (3 of 7 · Wire the totals) and the Terminal | Conversation switch. A plain shell has no line.

What the session in your active column did, and what it changed, are in one panel on the right, open by default and shared by the window: it follows the column you are working in (the one with the blue line on top) and is off only while that column holds no session (the map, a doc, a plain shell). ⌥⌘B or the button at the strip's end hides it; while hidden, a button at the end of the tab row brings it back, showing the number of files waiting to be committed. Slate remembers your choice. Drag its left edge to resize it from 280 px to 640 px (never over 60% of the window); double-click for 320 px. The map icon at the end of the workspace picker's row returns to the map.

  • Details (ⓘ). ⌥⌘I in a session's column, or a click on the state words in its header, opens the panel on it.
  • Changes (⇄), with the count of files waiting to be committed on its icon. It lists what the session's checkout changed (What the branch changed). The checkout is the one the session works in: a session started in the main checkout that edits a worktree reads that worktree's changes. All files opens Projects › Code, narrowed to the session's project.
  • Turns: every prompt the session was given, newest first, with when. A click scrolls the conversation to it, or finds it in the terminal's scrollback. A prompt that changed files shows how many; open it for the files, each opening its change.

Details has four sections: Environment (tool, project, branch, folder, how many other agents work there), Progress (the flow as one line such as "Check · 4 of 5", "27m in", and a bar), Context (how full it is; a tool that does not state its window is read against the size it has reached: past 200k tokens, a 1M window) and Links. Its foot carries what the branch is for (its doc, goal and documents under it), the Changed list, Recorded and Given. A session ends from its tab.

Links is what the session's branch is attached to. Shut, it reads like PR #142 · #138. Opened, each row carries its source's mark (GitHub, Jira, Linear or Slate); click to open:

  • The pull request: title, checks (passing, failing or running), reviewer count, and open, merged or closed. Before there is one, it says how many commits the branch is ahead and offers Open PR.
  • The issue. A branch named after a Jira or Linear key (SLT-138-…) shows that item from Tasks. Otherwise it is the GitHub issue the pull request closes, or the one whose number starts the branch name (fix/138-…).
  • The branch's doc in Slate.

The pull request's number comes from origin. Its title, checks and reviews, and a GitHub issue, are read with gh; without gh the card shows the number alone. With nothing attached, no card shows.

Focus mode, ⌘⇧M hides the top bar, rail and sidebar, leaving one agent; the same chord, or the Exit focus button, restores them.

What else the terminal does:

  • It follows your theme, including a retint from Settings → Appearance, while the session runs. ⌘F searches the session, scrollback included.
  • ⌘C copies, ⌘V pastes, ⌘+/− zooms and ⌘0 resets the size, which is remembered. Ctrl-C still interrupts, because the app's shortcuts live on ⌘. Every other app chord (⌘K, ⌘P, ⌘W) reaches the app, not the CLI. Shift+Enter adds a line. Option is Meta: ⌥← and ⌥→ jump a word, ⌥⌫ removes one.
  • The mouse behaves. Selecting text copies it (a switch in Settings → Terminal), the middle button pastes, and right-click opens Copy, Paste, Select all, Clear (⌥⌘K) and **Remember on doc**.
  • Scrolling up is safe. Output keeps arriving, and a Newest output pill brings you back. Past the scrollback limit the terminal prints earlier output is no longer kept.
  • Links look like links. A local server address (http://localhost:5173) opens in Slate's own browser as a tab beside the session. Any other URL opens in your browser. A printed slate://page/<id> opens that doc beside the session. A printed path such as src/x.ts:42 opens that file at that line, resolved against where the session runs.
  • It is your terminal. Settings → Terminal sets font, size, line height, cursor shape and blink (only the terminal you type in blinks), copy-on-select and scrollback (5,000 lines by default). Changes reach a session already on screen.
  • A terminal you cannot see keeps less. While its tab is behind another or the window is hidden, it keeps only its last 1,000 lines and gives back its graphics memory. When you look again it keeps your full scrollback from then on. Dropped lines return when the session is next opened fresh (a new tab, or after a restart).
  • A selection can be remembered. Selecting text shows a bar over the foot of the terminal. Copy is first. Remember files the selection as a memory under the doc this session belongs to. Nothing is captured automatically.

The timeline. Conversation shows what the session did, in order: each prompt, what the agent said, and every tool it ran with its target on one line (file, command or search). Click a step to see what it printed. An edit opens onto the lines it changed, drawn as in the branch review. A failed step says failed. The agent's plan (Claude Code's todo list, Codex's plan) sits at the top with how many items are done. The last 60 turns are shown. A step's output over 4,000 characters keeps its first and last 2,000. Claude Code, Codex, Gemini and OpenCode record each tool call with what it printed; Cursor records calls but not output, and its timeline says so. A receipt is read from the same timeline.

Recorded lists the memories this session filed, and whether it wrote them on its own or after Slate asked. It carries no commits, because joining commits to a session by time and project would count a concurrent agent's work. A session nobody has judged yet stays silent, not "nothing recorded".

Given lists the memories Slate gave the session, each once: At start (in the session brief) or On your prompts. A green dot means the session used the memory (its replies repeated the memory's rare words), an outline means it did not, a dashed outline means not judged yet, which happens after the session ends. Five rows show per group, then a count. Click a row to open Memory. A session given nothing shows no Given section.

Several sessions at once

A session you open is a tab in the same strip as your docs. Its status sits where a doc's icon would, with the lines its checkout changed and its context fill beside the name. A file, a branch's changes and a preview are tabs in the same strip. Every open tab stays mounted, so switching tears no terminal down.

While a session's tab shows, the rail stays on Sessions. Clicking a row opens a temporary tab in italics that the next click replaces; a session you launch gets a kept tab. Tab gestures and keys are as for every tab (Tabs).

Closing a session's tab ends the session, after asking. The ×, a middle-click and ⌘W all ask End qa?, naming the tool still running. End session stops the tool, closes its terminal and removes it from the rail. Close tab only closes just the tab of a terminal Slate hosts; the session stays on the rail as "In Slate · no window". Cancel keeps the tab. Close others, Close to the right and Close all ask once, listing every session they would end. If a stop is refused, the dialog stays open with the reason. A session in your own terminal is not Slate's to end: closing its view leaves it running. A session replaced in a temporary tab keeps running as In Slate · no window; click its row to bring the tab back. On close, the tab beside it takes its place; with none left you land on the map. Escape, or the back arrow on a transcript, returns to the map without closing anything. Sessions in the rail returns to the session tab you were last on.

⌘-click any tab to open it in its own column: two sessions, a session and its doc, or an agent beside the dev server.

Sessions side by side

Open beside in a row's ⋯, or ⌘-click on the row, shows that session in a new column right after yours. The main area holds up to 4 columns; with four in use, Open beside adds a tab to the column next to yours.

  • Each column has its own tabs. Your working column has a blue line on top; click another to work there. The list marks each session on screen with its column: left and right, middle with three, column 1 to column 4 with four.
  • Drag the line between two columns to widen one. Double-click a line to equalise all. Widths are saved per workspace and survive a relaunch.
  • Back to one view: Unsplit at the top of the last column, or ⇧⌘\\. Every tab is kept. Closing a column's last tab closes the column.

Opening a pull request

Open PR, in a session row's ⋯ and above the Changes tree, opens one sheet:

  • From and to: the branch, the trunk it goes into, and the git repository on its site (github.com/acme/nimbus).
  • Title: the subject of the oldest non-merge commit on the branch. Edit freely.
  • Description: the newest 50 commits, oldest first, then the size of the change (31 files changed, +469 −108). Edit freely.

The sheet first saves every unsaved file the editor holds under that folder, so the files it counts are the files on disk.

Push and open GitHub pushes exactly the branch (git push -u origin refs/heads/<branch>:refs/heads/<branch>) with your own git and SSH key, so no branch name can force-push another branch; a name starting with + is refused when a worktree is made. It then opens the site's compare web page in your browser with title and description filled in, and you press Create pull request there. GitHub, GitLab and Bitbucket are recognised from the origin remote, including an https port and an ssh alias such as gitlab.com-work; any other host is treated as GitHub (Enterprise). Bitbucket's link takes no title or description. If the push is refused, the sheet stays open with everything git printed, including the hook or rule that refused it. If the browser cannot open, it stays open with the compare link to click or copy. It cannot be closed while the push runs.

The PR number appears on its own. Slate reads refs/pull/* on origin and puts #118 on the session's row once one points at the branch's tip, asking once a minute, and every 30 seconds for five minutes after a push. The trunk never shows one. Refs cannot say whether a pull request is still open, so the number may belong to a merged or closed one, and a branch sharing its tip with another on origin shows none.

The sheet refuses, with the reason, outside a git checkout, on a detached HEAD, on the trunk or with no trunk to compare, with no commits ahead, with no origin, or when it cannot tell which site origin is on (a local path, for example). Uncommitted work is not pushed: commit it first.

Naming a session

A session has one name, shown by its tab, list row and memory doc. Right-click its tab and choose Rename…; Enter or clicking away keeps it, Escape keeps the old one. A name is one line of up to 80 characters.

A session with no name, or one that reads as none (blank, "session", "untitled", a raw id), shows "\<Tool> session in \<project>", in the list, tabs, map, ⌘K and the notification. A name taken from the opening prompt leaves out what the tool wrapped around it: <pasted_content …> around a paste, Cursor's [Image] and <user_query>, a Codex preamble. A tag you typed yourself, like <div>, stays. An agent run's session is named for its run.

Renaming the tab renames the session in its own tool, so its resume list shows the new name. Claude Code, Codex and Cursor get /rename <name> typed into the session; OpenCode is asked through its own server; Gemini keeps no names, so Slate keeps it. Slate types the command only when it cannot land in your words: the last turn has ended and nothing is half-typed in the prompt. Claude Code and Codex say when a turn ends. Cursor does not, so a running Cursor session gets its new name when you next open it in Slate, and the tab shows the name dimmed until then. If you started typing and cleared it, Slate waits for your next Enter or Ctrl+U. A session in your own terminal cannot be typed into, so its new name reaches the tool when you next open it in Slate. /rename typed in any of the four CLIs updates the tab, row and memory doc too.

Agents that know about each other

When two or more sessions run in one project, Slate tells each the others are there, once, at the start of a turn, in the message that carries the branch brief. The rail says so under the group: each told the other is here.

Each agent gets the other's own words: its tool, branch, how it is, what it was asked to do and its last message, plus the doc id. The branch goal is left out, since agents on one branch share it. Slate never claims a session is running: transcript timestamps show only that a file was touched, so it says last active six minutes ago. It asks for nothing; the agents decide.

An agent can leave one note for the others, or send one to a particular agent. Each is shown once on their next turn, and a reply is another note addressed back. There is no inbox, scheduler or queue. Notes that only narrate work in progress are refused. Slate never assigns anybody anything.

Reading a file beside the session

The Changed list at the foot of Details names every file the session's own tool calls wrote, read off its transcript, not guessed from time. An agent in the same folder never appears on another's list.

Each file opens as a tab beside the session, with an icon for its kind and language; the rail stays on Sessions. A printed path in the terminal opens it at that line.

⌘P finds a file by name in every checkout. Type two or more letters and, beside matching docs, it lists files from every project Slate tracks and every worktree of each, grouped under the checkout and branch (FILES · acme · main, then FILES · acme-feat-x · feat/x). A file's name outranks a folder that merely matches. New uncommitted files are included; whatever the project ignores (node_modules, build output) is not. ⌘K shows the same files, and ⌘⇧F finds text inside them (Search). Opening the palette starts reading every checkout, so keystrokes answer in about 20 ms. Picking a file opens it in its code: the side panel moves to Projects → Code → Files with the file's project unfolded to it. A worktree outside every tracked folder is not searched.

Code opens highlighted, numbered, searchable with ⌘F and editable. Markdown opens rendered, with Read one click away. An image is drawn. An SVG is both picture and text. A view re-reads itself when a session moves, and an updated pill says the text changed under you.

Comment on the changes, then send them to the agent. In Show changes, put the cursor on a line (or select several) and click Comment on line 88 (or lines 90-93). Write the note and press Add, or ⌘Enter. Notes collect under the header in line order. Send to the session pastes them as one message (Review comments on <file>: then each note against its lines) at the prompt of the session running in that file's folder, the deepest when several. Nothing is submitted. With no session in Slate in that folder, the message is copied instead. Comments never change the file.

Rewinding a turn

Every prompt you send a session takes a checkpoint first. When a new prompt appears in a live session's transcript, before the agent acts, Slate snapshots the folder the session started in: every tracked and untracked file inside it, not what the project ignores. Other folders of a larger git repository are not in the snapshot. It works for every tool whose transcript Slate reads, because it reads the transcript. Nothing you own moves: not the branch, HEAD, staged changes or stash. Checkpoints live under refs/slate/checkpoints/<branch>/, which git log and git push do not show, and the newest 100 per branch are kept. A turn that changed nothing takes none, nor does a folder outside any git repository.

Turns, in the session's Details, lists them newest first, each named by its prompt and holding the files that turn changed (from its checkpoint to the next; the newest to now). A file opens showing what changed since that turn began. Restore asks for a second click, then puts the session's folder back to that checkpoint and removes files created since, touching nothing outside it. It first takes a checkpoint of the present (Before restoring: …), so a restore can itself be restored.

Reading a file

A file opens as itself, its name on its tab. The bottom bar names the branch, says worktree when the file is in one, and gives its path from the project's folder.

  • Marks down the margin show what the branch changed: green added, blue changed, a red notch where lines were removed. Click a mark to open that change.
  • The cursor's line shows after its end when it last changed and in which commit; click to see that commit's change. It is drawn only while the line has room and the file has no unsaved edits.
  • Blame, at the end of the bar, does the same for every line, down the left: commit age as the strength of one blue, time and subject once per run of lines. Pointing at a line lights every line from the same commit.
  • Show changes appears when the file differs from where its branch began, with long unchanged stretches folded. against picks the comparison: where the branch began (default) or the last commit. Back to the file or Esc leaves it.

The Now pill opens the file's history: this branch's commits, a line where the branch left its base, and the commits before. Pick one to see the file at that commit, read-only, with what it changed; the pill turns amber, and Back to now or Esc returns. [ and ] step through changes; ⌥H opens the history.

What agents know about the file

A dot in the margin marks each line a memory cites. Any memory, decision or lesson whose source_ref names the file and a line range (src/export/csv.ts:10-22) or a symbol puts a dot, in its kind's colour, on those lines. Point at a dot to read the claims. Code that moved is found where it went, and the dot moves with it. A memory citing the whole file has no dot. Dots show at Now only.

The header counts them: 4 memories · 2 told to agents who touch it, or No memories yet. The second number is the lessons and decisions Slate hands an agent when it reads or edits this file (lessons). Click the count, or a dot (that line's memories first), to open the card above the text.

Each memory in the card says what it claims, its kind, its lines (click to go there), its ref (m:7f3a2b1c), how often sessions used it and in which tools, and whether the code still matches: Matches the code, The code changed since — still true?, or Not checked against the code for a memory written before Slate kept fingerprints.

  • Confirm: still true. It counts as confirmed by you, its fingerprint is retaken from the file as it reads now, and a line citation whose code moved is re-pointed.
  • Correct: edit the claim in place. The new words replace the old memory, which stays in its history, and cite the same lines as they read now.
  • Retire: the memory stops reaching sessions, as in Memory.

Teach and ask from the lines you select. The card's head offers:

  • Remember line 7 (or lines 7–9): type what agents should know. It is saved as your own memory in the project, citing those lines with a fingerprint, so it gets a dot and later a changed mark if the code moves on.
  • Ask an agent about line 7: pastes the lines and every memory on them, with its ref, at the prompt of the session working in the file's folder. Add your question and press Enter; nothing is sent for you. With no session working there, the message is copied. A selection over 200 lines is cut. Unsaved lines in that folder are saved first.

What you do to the code teaches the memory. Your acts count as evidence on the memories behind the code:

  • Merge into main of a branch in review confirms each memory the sessions on that branch cited.
  • Revert hunk, Revert file and Discard of the branch contradict them; a branch counts once per memory.
  • Saving an edit on lines a memory cites asks once, on its card: You edited these lines: still true? Confirm answers yes; Correct or Retire answer no.

"The sessions on that branch" are those Slate captured in that checkout on that branch. An act on main (or another trunk) blames nobody. Each act shows on the memory's card, here and in Memory, with the branch or file and date, and × undoes it. No single act retires a memory. Everything stays in your own store; only what you paste at a session leaves the computer.

Editing

At Now, Read is editable. There is no edit mode: type, as in VS Code. Changed lines are amber in the margin, the tab wears a dot, and the bar says how many lines are unsaved, with Revert and Save (⌘S). Because the agent is a second writer:

  • While an agent works in that folder, Save waits. The button says Waiting for Claude Code; keep typing. When its turn ends, Save works.
  • Every save takes a checkpoint first, so Turns can undo it. The Saved line also offers Undo.
  • If the file changes on disk while you have unsaved lines, the two are merged. Changes to different lines are all kept, and a line says so. Where you and the agent changed the same lines, each place shows Yours beside theirs, and you choose Keep yours, Keep theirs or Keep both. Nothing is written until you press Save.

The editor uses VS Code's keys: undo ⌘Z, redo ⌘⇧Z (Ctrl+Z and Ctrl+Y on Windows and Linux); ⌥-click adds a cursor, ⌘D the next match, ⌘⇧L every match, ⌥⇧-drag a column; find and replace ⌘F, go to line Ctrl+G, comment ⌘/, move a line ⌥↑/↓, copy it ⇧⌥↑/↓, remove it ⇧⌘K. Brackets and quotes close themselves, and typing one over a selection wraps it. Other matches of the selected word are lit, and words already in the file are offered as you type (Enter or Tab takes one). Fold a block with the arrow in the margin.

A file is saved the way it was written. Line endings (LF or CRLF, even mixed), indentation (tabs, or the width of spaces it already uses; four when it has none) and a leading byte-order mark are kept. Slate does not autosave, format, trim trailing spaces or add a final newline, because each would turn a small edit into a large diff. In Diff, each change offers Revert, which puts it back as an ordinary edit you then save.

The agent reads the disk, not your screen. When an agent is in the folder and you have unsaved lines, a line says it cannot see them yet. Anything Slate sends it (review comments, Open PR) saves your unsaved files in that folder first. Review comments say so if one could not be saved; Open PR stays silent (Opening a pull request).

Unsaved text survives closing the tab and quitting Slate. It is kept in the app's own storage, never in the file, and forgotten once saved or reverted. It returns through the same merge as an agent's write, so a file that changed meanwhile is merged, never overwritten. A past commit, Diff and Blame are never editable. There is no rename, new file or removal.

Slate reads and writes only inside a folder it already has business in: a group, project or branch folder, or a folder a live session runs in. A file a live session changed opens wherever it is, a scratchpad under /tmp included, because its Changed list names it. Up to 1 MB of text or 8 MB of image opens. Anything larger, a binary that is not an image, or a file outside those folders goes to the system with Open in Finder and a sentence saying why.

What the branch changed

The Changed list is one session's own work. The side panel's Changes is the other half: everything each worktree's branch holds that its base does not, whoever put it there. That is the question before a merge, and no session can answer it about itself. It is measured from the point the branch left its base, so a commit that landed on the base afterwards is never counted, and it includes what is not committed yet.

Changes shows the worktree of the agent you are working in: its branch, then source control. With no agent selected, every worktree with a session gets a section folded to one line (branch, lines waiting to be committed), and ▸ opens one. The branch name opens the whole branch's review. A worktree's files, and a search through them, are in Projects' Code.

Source control

Changes works like VS Code's Source Control, and Slate runs the git itself.

  • The count on the ⇄ in the session's header, the panel's Changes tab and the Changes title is the files waiting to be committed. An unpushed commit is not counted: that is what Sync changes is for.
  • The branch line shows the branch, its upstream only when not named after the branch, when the remote was last fetched, and a button that fetches now.
  • One main button says the next step. With files to commit: Commit N files, with Commit & Push beside it. With everything committed: Sync changes, with commits to push (↑) and pull (↓) on it; it pulls, then pushes. A branch never pushed shows Publish branch. With nothing to do there is no button and Changes says Nothing to commit, and up to date.
  • Commit takes a message and exactly the files you tick, all ticked to start, except the agents' MCP, hook and settings files (.mcp.json, .claude/settings.json and the like), which can hold secrets and start unticked. Nothing is staged: a file you staged yourself stays staged and is not committed unless ticked. ⌘↵ in the message commits.
  • Each file opens its change with a click. The ↺ button puts it back as in the last commit. Slate takes a checkpoint first, but no button brings a discarded change back.
  • Folded below: Outgoing · N commits, Incoming · N commits, and on a feature branch This branch vs main · N files. A branch never pushed has no upstream, so its commits show as Not yet published · N commits against its base.

Every write waits for the agent. While a session works in the worktree, Commit, Sync, Publish and ↺ are off; pointing at one says Claude Code is working here — waits for its turn to end. Fetching moves no file, so it never waits.

Pull is a fast-forward or nothing, and push never forces. When the branch and its upstream have both moved, Sync says what git said and leaves the branch as it was. Merge or rebase in the terminal, where conflicts can be resolved. Open PR opens the pull-request sheet. The tree has no rename, new file, removal or drag.

Reviewing the whole branch

The branch name at the top of a worktree's section, or pointing at a row in the rail, opens the branch as one doc: every changed file's lines, one under the next, measured from the same point. The header counts the files and lines added and removed.

  • The file tree on the left holds every changed file in its folders. Clicking a file scrolls to it and unfolds it. Viewed files are drawn quieter.
  • Fold a file with its arrow, or all with Fold all (Unfold all undoes it). A review draws at most 2,000 changed lines open: a file that would pass that starts folded, a later smaller file that fits starts open, and the first file always opens. Files you have seen keep their fold when the doc re-reads the branch. A binary file, a file with over 3,000 changed lines and a new file over 512 KB are listed with a note instead of their lines.
  • Viewed folds a file and counts it (3/12 viewed). If the agent changes it again it comes back unviewed.
  • Click a line number to comment. Notes collect across files, and Send to the session pastes them as one message at the prompt of the session working in that folder; nothing is submitted. A note on a removed line says removed line.
  • A file's name opens the whole file, against the same point.
  • The doc re-reads the branch when a session in that folder acts, or when you return to the window. A failed read says why and offers Try again.

Revert hunk undoes one hunk and Revert file puts a file back to how the branch found it (a file the branch created is removed). Slate takes a checkpoint first, so Turns can undo it. A revert is refused while an agent works in that folder and when the file changed after the doc was drawn; the doc says so at the top. Only files change: nothing is staged or committed, and nothing you staged is touched. A revert counts against the memories the branch's sessions cited (What agents know about the file). A branch waiting for review also carries Merge, Keep and Discard above its review.

A plain shell

⌃` opens a plain login shell (your own shell and environment) in the folder the doc you are on stands for, or your home directory when nothing on screen names a folder. It is hosted like a session: it survives navigating away, opens in the Sessions tab beside everything else, and everything above applies. It has no tool account and no hand-back.

Taking over a session from your terminal

A session in your own terminal can be continued here. Clicking its row only shows it: its conversation, live, read from the transcript the tool is writing. Its details and changes are in the window's panel. One button above it says what continuing would do. Nothing on that screen types into your terminal.

  • Already kept by its tool as a background job (a Claude Code background job, or a Cursor persist session): no button. The row opens it in Slate as itself with claude attach or cursor-agent persist attach, which copies nothing and interrupts nothing.
  • Claude Code in a terminal, Codex and OpenCode: Continue in a copy (--resume <id> --fork-session, codex fork <id>, opencode --session <id> --fork). It is a second conversation with the whole history; the original keeps running where it is.
  • Cursor and Gemini: Move here. cursor-agent --resume appends to the original transcript, so two processes would write one file. The original is ended first, and the button asks twice, because an in-flight turn is lost.

A copy gets its own transcript, so the two never interleave. The copy's row says Copy in Slate. The original's tab keeps showing the original, live, as it goes on in your terminal, and its row offers Open your copy to read or stop the copy.

Whatever a row offers runs under the account the session already used. A tool's sessions live inside its config directory, so continuing under a different account finds nothing and quietly starts a new conversation.

Moving a session back to your terminal

Hand back to my terminal is in a session row's ⋯, with the line Keeps running; you get the command to resume it. It detaches a session Slate runs and leaves it running. Slate sends the tool's own detach input (/bg for Claude Code), waits about 1.5 seconds, and closes the session's terminal. A message then shows the command that picks it up, with Copy resume: claude attach <handle> for a backgrounded Claude session, prefixed with its account where there is one. When Slate cannot name the command, the message says It keeps running in the background. Only Claude Code can do this today, so the item appears only on a Claude Code session Slate runs.

Stopping a session

Every row whose session can be ended has a Stop button. The first click arms it and the row says Click Stop or press s again to end it. The second click, or s, ends it. Mouse and keyboard share one arm, which forgets itself after four seconds.

A backgrounded Claude session is ended with claude stop <handle>, which keeps the conversation so you can attach again. Everything else gets SIGTERM, so the CLI can shut its own MCP subprocesses down, and that ends the conversation. A signal is refused when the process is no longer the tool it was reported as, because pids are recycled. This works for sessions Slate never started, such as a forgotten CLI in a terminal three desktops away.

Quitting Slate ends the sessions it hosts, because an interactive CLI holds its own MCP subprocesses. First it hands back what it can: a Claude session that is not already a background job is sent its detach input and given 1.2 seconds (one wait for all such sessions together), so it lives on as a job you can pick up later. A Claude session that already is a background job keeps running.

Session flow

A session's flow says where it stands in its work. A build skill's flow has five steps: Overview, Plan, Build, Check, Land. Research has three: Asked, Published, Decided. It is drawn in three places, never twice in view: on the session's row (a small bar and the step's word, such as ▬▬▬▬▭ Check, in place of the plan count), in the session's header (only the words, "● Working · Check"), and in Details under Progress (the goal, the bar, and each step with what lit it).

The word is the step the session is in now. The bar is how far it has got. The word follows the latest evidence: a session that ran its tests and went back to editing reads Build again, while its bar stays solid through Check.

Waiting. A session whose latest step only waits reads Waiting instead of a step: a shell loop on the gate lock (slate-heavy.lock) while another session's receipt holds it, a sleep still running, or a ScheduleWakeup. An idle session in the middle of a step reads Waiting too. Its status is Idle and nothing pulses. In Details, the step says what it waits on, such as "waiting for the gate lock". Waiting on you is the amber status, and its step keeps its own word.

The bar has one colour, the app's accent: steps done are solid, the current step is lighter and breathes while it works, steps ahead are the grey track. Only an exception changes a segment's colour:

  • red on Check when the session stopped on a failed check. Build is then the current step again, with "retry 1", and the words read "Check failed" (row) or "check failed" (header). While the session still works, a failed check is not red: it is back at Build, fixing it.
  • amber on the current step while the session waits on you.
  • green on every segment once the work is on the default branch.

There is no percent and no time left, because the steps take very different times.

The agent reports nothing. Slate lights each step only from what the transcript and git already recorded:

  • Overview: the session started and is reading; it counts what it read and searched before it planned or edited. A session opened by an approved brief says "read the brief".
  • Plan: Claude Code's plan mode was approved, the agent wrote a todo list (Claude Code's todo list, Codex's update_plan), or an approved brief opened the session. With none of these, Plan is hollow and says "no plan recorded". A session that hands work out (a message to another session, a scheduled run it starts) is at Plan and counts its "hand-offs".
  • Build: an edit to a file in the session's own checkout. A brief written into the git folder, or a file outside its checkout, is not its build, so a session that only coordinates never reads Build. Once it commits, it says "committed". An edit after a check or a landing moves it back to Build.
  • Check: a test or gate run: the project's own checks (its scripts, its pre-push hook) or a known test runner.
  • Land: the work is on the default branch, origin's copy or the local one: its last commit, or the commit its git push moved the default branch to. It is read from the git repository even after the worktree was removed. Its last evidence is the closing card the session sends, "card sent".
  • Asked: research was asked. Published: it published a doc to read (an artifact, a Slate doc or app). Decided: your reply after it published.

The steps come from the skill the session runs. Each skill lists its steps in its SKILL.md frontmatter:

flow: overview plan edit check land

edit is shown as Build. A helper skill that does one part of another skill's work says flow: step and adds none of its own. When the session's checkout is older than the skill's flow: line, the line in the git repository's main checkout is used. Slate sees which skill a session runs, measured on the first five tools, from a slash command you typed, a prompt that opens with a skill's run phrase, a Skill call, or the agent reading the skill's SKILL.md (with a read tool, or through the shell with cat, sed, head or tail, in any folder under skills/). A search or listing that names the file (grep, ls) does not count, nor does text a tool adds to a prompt on its own, such as a list of skills. When the session switches skill, the new skill's steps follow. A session that names no skill shows only the steps that happened, and no bar until there is more than the overview.

The goal is read from what was written, never made up. Slate takes the first it finds:

  1. The brief whose path the first prompt names: its title as the goal, its checklist as Done when. Only a Markdown file of at most 64 KB inside the session's checkout or its git folder.
  2. The issue: the branch is fix/<n>-…, or the prompt says #<n>.
  3. The branch's Plan doc in Slate: its goal.
  4. The first prompt, marked "as asked". With a slash command such as /research why…, the goal is what follows the command. The notice Claude Code writes when you stop a turn is never the goal.

Nothing is stored: the flow is worked out from the transcript each time the tab reads it.

How status is worked out

Status comes from the transcript, from who spoke last, and from whether a running CLI process vouches for the session. A quiet transcript with no live process is a closed conversation: it is dropped from the tab, never shown as Needs you. A process vouches for a session of its tool in the folder it works in. For a CLI told to work elsewhere (codex --cd <folder>, cursor-agent --workspace <folder>) that is that folder, not the terminal's. A session that moved on (its shell changed folder, or it entered a worktree) is still found beside the process in the folder it began in, and two spellings of one folder (/tmp and /private/tmp, a symlink and its target) count as one. For a tool that lists its own sessions, an unlisted session is gone, but a listing alone does not prove one alive, because a CLI remembers a background job long after it stopped. A job the tool reports as done, stopped or failed is finished, and that outranks everything else.

The write that ends a turn is what touches the transcript, so a session that just asked you something would read as Working for the rest of a 45-second window. Three signals correct that, and none is consulted for a session nothing vouches for:

  • The window title of a session Slate hosts. Slate owns that pty, so a session whose title has stopped moving becomes Needs you in about ten seconds. Only a title seen to move counts, and of the first five CLIs only Codex animates its title.
  • The tool's own listing, when it reports a session as busy.
  • A sub-agent that is still writing. This reaches a session in somebody else's terminal.

For Claude Code only, the transcript's own records settle it: a record carrying a tool call is mid-turn, one carrying only text has finished. A call with no result is Working, since the command is still running; a transcript never records a permission prompt that is still open. Only a session Slate hosts, whose terminal has drawn nothing, reads a quiet open call as Needs you, asking you to allow it.

Three blind spots remain. A permission prompt in a session Slate neither hosts nor can ask about reads as Working for Claude Code and as idle for the other tools. "Waiting for permission" and "answered, waiting for your next prompt" look the same, and both surface as Needs you. A tool whose title does not move and whose transcript Slate cannot read that way is judged on timing alone, so the end of its turn can take up to the window plus a tick to show.

How it stays current

Pushed, not polled. The server holds the live set in memory and streams changes over server-sent events (GET /sessions/live/stream); an idle machine sends nothing. GET /sessions/live is the one-shot.

One fs.watch covers the transcript roots (auto-capture shares it) and only the changed file is re-read, coalesced over 150ms because one turn is many writes. Two more watches cover HEAD in each live checkout, so a git checkout shows at once, and the directory holding OpenCode's database. Three timers cover what a file event cannot report, each running only while something on the tab depends on it: time passing (5s, pure CPU; this flips a session to Needs you), a dropped OS event (60s, a full re-walk), and a process list (ps, 15s), only while a live session has no process id of its own. With nothing live, no timer runs. A session killed outside the app leaves the tab on the next 5s tick. A tool's own session listing is asked again only when a session starts, stops or goes back to its terminal.

What you do yourself does not wait for a timer. A stop, a hosted terminal closing, a hand-back and a hosted child exiting all force a refresh (POST /sessions/live/refresh). A stop is a request, not a settled state, so Slate looks at once, then 250ms later, then after 700ms, 1.5s and 3s, each counted from the look before (about 5.5 seconds at most), and stops when the processes it ended have left the process table.

Git is asked once per project and once for the whole window. Branch counts refresh at most every thirty seconds while sessions are reporting, and at once when the window is focused, which is how a commit made in an outside terminal shows up.
