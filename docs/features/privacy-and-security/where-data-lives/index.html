Where each piece of data lives

View as markdownOpen the .md copy of this page

No server holds your workspace, only the docs you hand it. A model sees only what you send it in a turn.

WhatWhere
Personal workspaceLocal workspace.db; syncs only if you switch sharing on (Your Data & Export)
Each shared workspaceIts own local SQLite file, same schema, mirrored to and from Postgres
Docs, sessions, memories, decisionsInside that file
Which workspaces this machine hasA local registry (names, colours, your role) so the switcher reads offline
Tasks from other toolsOne line per task in the workspace file. Never description, comment or message text; never shared. For a tool learned by Teach Slate: how to read it (tool name, arguments, field paths), never its answer
Agent run draftsPR text, ticket update, review comments or reply, so Approve to ship shows them word for word. In the owning store, removed 30 days after the run closes, never shared. The task description is never stored
ReceiptsOne per session, in the file of the workspace holding its folder: last reply's first paragraph, each run's command and result counts, edited paths, commit ids and subjects. Read from the transcript with no model. Never a run's full output; never shared
Agent run rules fileSmall JSON in the run worktree's own git folder (never committed), or in the run's folder under app data for a reply
ActivityPer session and model response: times, token counts, model, the tool's own cost. Never prompt or reply text. In machine.db, so never shared
Slate's own costOne line every 15 minutes in slate.log (~/Library/Logs/app.slate.workspace/ on a Mac): CPU, memory and wake counts for server, app and web view. Numbers only, never sent; telemetry switches do not reach it
ExportA one-click copy of the SQLite file
Agent credentialsNone stored; the CLIs hold their own

Credential files, all 0600:

FileHolds
Cloud session (app-data root)The cloud sign-in; never in a database, so an export cannot contain a live token
slate-server-token (beside the database)The credential every local caller presents to the server, capture port included (how). Persists across launches. No agent's config holds it
slate-mcp-token (beside it)A copy sits in each connected agent's MCP entry, in a config made owner-only and never passed on a command line (ADR 0106). It opens Slate's MCP server only, not the rest of the server. Slate will not write it through a config file that is a link
work-gateway-auth.jsonThe token a web-address work gateway, or an app connected from Slate, issued to Slate; sent only to that server
work-token-auth.jsonThe token you pasted for Bitbucket, Gitea, Gerrit, YouTrack, Zulip or Rocket.Chat, with the account name, keyed by workspace and server. Sent only to that server, never logged, removed on Disconnect
oauth-pending.jsonA sign-in in progress; dropped when used and after 15 minutes
