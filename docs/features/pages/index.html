Features

Pages & the Block Editor

The page is Slate's universal unit. A note, a design doc, a repo, a captured AI session, a mission — all of them are rows in one page table. There is no separate "document type" storage layer to learn: nesting, reordering, icons, and archiving work the same way for everything.

Each page carries an id, a parent_id, a title, an icon, a fractional position, its block content, and a handful of metadata columns (doc_type, status, archived, timestamps). Because it's all one table, moving a mission under a branch or nesting a design doc under a repo is the same operation everywhere.

The block editor

Slate's editor is BlockNote. You write in blocks, and every block is a first-class, reorderable unit rather than a run of Markdown text.

The editor is keyboard-first:

  • Type / to open the slash menu and insert any block without leaving the keyboard.
  • Drag-reorder blocks by their handle, or move them with the keyboard.
  • Standard rich-text shortcuts apply inside a block.

Content is stored as BlockNote JSON in the page's content column, so the document structure survives round-trips exactly as you left it.

Right-to-left pages

A page written in Hebrew, Arabic or any other RTL script lays out right-to-left — the body, the title, its tab, its breadcrumb and its row in the sidebar. Nothing to turn on and nothing to set: Slate reads the direction off the text itself, and an English page is untouched.

The rule is the majority of words, counted by the script each word starts in — not the browser's dir="auto", which judges by the first strong character alone. Real notes open their paragraphs with a ticket id or a package name (PROJ-18323 — Studio 2 דוחה…), and auto calls every one of those an English paragraph. It is not a per-character majority either: one long identifier (@nimbus/r-auto-panels-adt-runtime-lightningcss) would otherwise outvote five Hebrew words in the same sentence.

A page has ONE direction, so an English heading inside a Hebrew page stays with the page rather than flipping mid-document. A title declares its own — a Hebrew page may keep an English name.

The page tree

The sidebar is a nested tree of pages. Any page can hold children, to any depth.

  • Breadcrumbs show the path back to the root as Grandparent / Parent / Title.
  • Each entry shows an icon + title. The icon is either a Lucide icon name or an emoji.
  • Drag-to-reorder uses a fractional position (a REAL column), so dropping a page between two siblings normally rewrites just the one row that moved. Roughly 52 drops into the same narrowing gap exhaust what a float can divide; at that point the sibling list is renumbered once and the drop lands where you put it.
  • Move / nest a page by dragging it under a new parent.
  • Archive sends a page to the Trash rather than deleting it outright, so a mistaken archive is recoverable.

Fractional positioning is provided by positionBetween in @slate/shared. It computes a value strictly between two neighbors, which is why reordering is normally a single-row update instead of a bulk rewrite. When the midpoint would equal a neighbour — the float has run out of room — rebalanceSiblings renumbers that one parent's children and the move is recomputed. position is a local sort key and is never pushed to the cloud, so a renumber costs nothing beyond the write.

What the tree knows, and what it doesn't

The sidebar holds page metadata — title, icon, kind, parent, position, status. It does not hold page bodies. A body is fetched when the page is opened, and the tree is refreshed by a conditional request that costs nothing at all when nothing has changed (see the server's own storage layer).

The visible consequence is backlinks. "Linked from" used to be computed in the browser by scanning every page's body, which only worked because the tree happened to carry them all. It is a server query now — GET /pages/:id/backlinks — asked once when a page opens. Nothing about the panel changed; the scan moved to the layer that already holds the rows.

Markdown in, Markdown out

Blocks convert to and from Markdown through pure helpers in @slate/shared (blocksToMarkdown, markdownToBlocks, parseBlocks). That means content pasted as Markdown lands as real blocks, and blocks can be rendered back to Markdown for tools that expect plain text — including the AI agent and the MCP tools that read and write your pages.
