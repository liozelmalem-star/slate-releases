Features

Pages & the Block Editor

The page is Slate's universal unit. A note, a design doc, a project, a captured AI session — all of them are rows in one page table. There is no separate "document type" storage layer to learn: nesting, reordering, icons, and archiving work the same way for everything.

Each page carries an id, a parent_id, a title, an icon, a fractional position, its block content, and a handful of metadata columns (doc_type, status, archived, timestamps). Because it is all one table, moving a branch page under a project or nesting a design doc under a group is the same operation everywhere.

The line under a page's title ends with who can read it: Private in your Personal workspace, or Shared · <workspace> in a shared one.

What you have open stays current. When an AI tool writes to your workspace over MCP — appends to the page you are reading, renames it, files a new page, saves a memory — the open screen shows it within a few seconds, without reopening it. If you are typing on that page at the time, Slate keeps your text and shows the "changed elsewhere" notice instead of replacing it. The notice offers Copy my text, Keep my version (asks once, then saves over the newer one) and Reload page.

The block editor

Slate's editor is BlockNote. You write in blocks, and every block is a first-class, reorderable unit rather than a run of Markdown text.

You get BlockNote's own blocks — paragraph, three heading levels, bullet, numbered and to-do lists, quote, code, table, image, divider — plus four Slate ones: a callout, a link to page, a page card that embeds another page as a preview, and Ask AI, which drafts a block for you. If a draft fails, the prompt stays open with the reason and a Retry.

A callout is drawn as a plain note. Only the ⚠️ emoji draws it in the warning colour.

The editor is keyboard-first:

  • Type / to open the slash menu and insert any block without leaving the keyboard. Its first item, Write with AI, asks an AI tool to draft text into the page.
  • Drag-reorder blocks by their handle, or move them with the keyboard.
  • Standard rich-text shortcuts apply inside a block.
  • Type @ to link a page inline. The same list opens from /Link to page: it matches loosely, shows recent pages first, and takes the arrows and Enter.
  • Pasted Markdown works like any paste: it replaces a selection, fills an empty block, and splits a paragraph at the cursor.
  • Right-click menus, here and in the tree, open with their corner at the pointer.

Content is stored as BlockNote JSON in the page's content column, so the document structure survives round-trips exactly as you left it.

Right-to-left pages

A page written in Hebrew, Arabic or any other RTL script lays out right-to-left — the body, the title, its tab, its breadcrumb and its row in the sidebar. Nothing to turn on and nothing to set: Slate reads the direction off the text itself, and an English page is untouched.

The rule counts words, by the script each word starts in, and a tie goes to RTL. That is what makes a real note work: a Hebrew paragraph often opens with a ticket id or a package name, and one long Latin identifier should not outvote five Hebrew words around it.

A page has ONE direction, so an English heading inside a Hebrew page stays with the page rather than flipping mid-document. A title declares its own — a Hebrew page may keep an English name.

Projects: made in the workspace menu or a picker, narrowed to in a feature

Projects are the workspace's contents, so they live in the workspace menu — click the workspace mark at the top of the rail, on any tab:

  • New project… — choose a folder, and the name comes from it.
  • Manage projects… — the workspace's projects by group. Rename one, Open project page (where its AI tool is set), or Move to Trash.

⌘K has both too, and so does the foot of every project picker's list.

Inside Pages, Routines, Activity, Artifacts and Memory, a project picker at the head of the pane narrows that one feature to one project. Each feature keeps its own choice — narrowing Pages leaves Routines where it was — and every feature opens on All projects. Memory remembers the one you pick. Home and Skills keep their own project controls. Sessions, which lists the whole Mac, picks a workspace first and shows the project picker under it (see Sessions).

The page tree

The Pages pane is a nested tree of pages. With a project picked it starts inside that project — its branches and pages; on All projects it shows every group and project. While the tree holds at most one group or project, a line at its top explains them: A workspace holds your projects. A project is a folder you open. A group collects related projects. It goes once the tree has more. Any page can hold children, to any depth. New page (⌘N) adds a blank Doc to the picked project. On All projects it goes under Not in a project. The button names where it will go: "New page in slate", or "New page · Not in a project". The page opens with the caret in its title, and you can change its type afterwards (see Typed Documents). Generate a page (⌘⇧G) asks an AI tool to draft one instead.

  • Breadcrumbs show the path back to the root as Grandparent / Parent / Title.
  • Each entry shows an icon + title. The icon is either a Lucide icon name or an emoji.
  • Captured sessions are not rows in the tree. A main branch collects them for months, and listing them buried the groups, projects and pages the tree is for. The page they belong to lists them under Sessions · N, and Sessions lists every one.
  • Drag-to-reorder uses a fractional position (a REAL column), so dropping a page between two siblings normally rewrites just the one row that moved. Roughly 52 drops into the same narrowing gap exhaust what a float can divide; at that point that parent's children are renumbered once and the drop lands where you put it. position is a local sort key and is never pushed to the cloud, so a renumber costs nothing beyond the write.
  • Move / nest a page by dragging it under a new parent.
  • Move to Trash keeps the page recoverable. A message says "Moved “Title” to Trash." with Undo, and the page's open tab closes.
  • Trash lists each page with when it went there and the page it was under: "Moved to Trash 2 days ago · from slate". A box filters the list by title. Each row has Restore and a Delete forever… icon. Tick rows and the toolbar offers Restore (N) and Delete forever (N); with nothing ticked it offers Empty Trash, or Delete forever · N shown while the filter hides some. Delete forever always asks first. Click a page to read it, read-only, with a bar that offers Restore. A link to a page that no longer exists says so and offers Open Trash.
  • A branch page appears when there is something in it. The branch you are on, and a branch with its own worktree, get a page straight away. Any other branch gets one when a session, a document or a decision lands on it, and a branch page that holds nothing is removed.
  • A removed worktree files with its project. Slate makes a worktree beside its repo as <repo>-<branch>. A session captured after that folder was removed used to become a "project" of its own named after the folder; it now files under the project it came from. A folder that still exists keeps its own name, since a real repo can be named the same way. Pages made the old way were moved under their project once, and the emptied page went to the Trash.
  • Past branches. When git deletes a branch, its page is marked done and leaves the tree with everything under it — sessions, plans, decisions — and appears in a Past branches row at the bottom of its project, grouped by month. It is not in the Trash, and emptying the Trash never removes it. Restore brings a branch back, and it comes back on its own if git has the branch again. Nothing is deleted. Deleting a trashed project forever keeps its Past branches too, moving them up to the project's parent page, where a Past branches row lists them — or to the top of the tree if the project had no parent. If the Trash or the Past branches row cannot be read, it says so with Try again instead of showing an empty list. Clicking the row opens a full page, one project at a time (or every branch of a forever-deleted project, when opened from the tree's root): every past branch, newest month first, each with its goal, what it holds, and its own Restore. A search box narrows the list and shows a live N of total count; searching opens every month at once, so a match is never hidden behind a closed disclosure.
  • A group's or a project's Settings. A group page, or a project standing on its own, has a Settings button in its header — a project inside a group uses its group's. It opens one sheet with everything that belongs to it: its folder, the AI tools it uses (and on which account), the worktree commands (Set up, Preview, On remove, Carry over), the Check command that decides a task is done, and Autopilot. Each field saves when you leave it; the tools save with Save tools. The sheet says it is saved on this Mac, because it names accounts and commands on this computer and never travels with a shared workspace. Accounts and models themselves are set in Connect → AI tools. The tools here override the workspace's: a new project asks for none and runs on the tools the workspace connects, so this is where a group or project that needs other accounts sets them. New session and the task start box still set the rest.
  • A refused action says so. If a move, rename, duplicate, Move to Trash or restore does not go through — the page is gone, the workspace is read-only, the page is somebody else's — a message at the bottom of the window names the page and the reason, and the tree stays as it was. It closes by itself after 8 seconds (it waits while you point at it), or with its ✕. The same message reports what you just did elsewhere in the app, with Undo when it can be undone.

The tree holds page metadata — title, icon, kind, parent, position, status — and not page bodies. A body is fetched when the page is opened, and the "Linked from" panel is a server query (GET /pages/:id/backlinks) asked once at that moment.

Markdown in, Markdown out

Blocks convert to and from Markdown through pure helpers in @slate/shared (blocksToMarkdown, markdownToBlocks, parseBlocks). That means content pasted as Markdown lands as real blocks, and blocks can be rendered back to Markdown for tools that expect plain text — including the AI agent and the MCP tools that read and write your pages.
