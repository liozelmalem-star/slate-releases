Missions

A mission page was Slate's first container for one piece of work. The branch page replaced it: a branch is the page that sessions, plans and decisions now file under. Slate makes no new mission pages, and an old one still opens.

An old mission page is a page with doc_type = mission, so it keeps the whole page model: nesting, breadcrumbs and the block editor. It also keeps three things of its own:

  • The type chip under its title shows its status: draft, active, done or canceled.
  • A new empty one starts from the old outline: Goal, Checklist, Session log, Decisions and Notes.
  • Above the text, a list shows the pages filed under it. A project may hold one without a warning in the tree.

The Doc ▾ menu does not offer mission. See Typed Documents & Hierarchy for where it sits among the types.

Progress on a branch

A branch page keeps a running record of the work, so the next session, yours or an AI tool's, starts with that context already in front of it. Nothing restarts from zero.

AI tools write it for you. The MCP tool log_mission_progress takes a branch page and adds a dated entry to a Progress section. The entry is a heading with the date and the tool's name, then the summary, the decisions and the open items:

recall  →  work the task  →  log_mission_progress(summary, …)
  • Where it goes. The entry goes into the branch's Plan page when it has one, and into the branch page itself when it does not. It never creates a page. If the id is not a branch page, the call is refused.
  • On a trunk branch (main, master, develop) the entry always goes on the branch page, never on a Plan page, and the log keeps only the latest 20 entries.
  • Where you read it. On a branch page it is the Progress tab. With a Plan page, the entries live there, so the tab shows them under the branch's own text, read only, headed Logged on the Plan page.

Over a few sessions the Progress section becomes the branch's narrative: what was tried, what landed, what is still open.

Slate offers the page at each milestone

When your work reaches a milestone — a plan, a review, a test plan, a bug report or a design — Slate asks you, in the chat with your AI tool, whether to keep it as a page. Slate does not write the question. It tells the tool to ask with the tool's own click-to-answer question tool, so where that tool shows a question as choices, you click one. The wording of the choices is the tool's.

Choose save and the AI tool saves the page under the branch. Choose not to and nothing is saved. If the branch already has that page, the choice is to add to that page, which keeps everything already on it. Every tool also carries the same standing instruction to ask before it saves a plan, review, test plan, bug report or design. Nothing is ever saved without asking you.

The app is the backup. A plan written in plan mode that was not saved in the chat waits at the top of the branch page's Pages tab: Claude Code wrote a plan, with Create Plan page, Dismiss and Show plan. Create makes the Plan page and opens it; on a branch that already has a Plan page you wrote, the button reads Add to Plan page and puts the new plan above what you wrote. Dismiss removes the offer, and the same plan is not offered again. A Plan page Slate made from an earlier plan is updated by the next one; a Plan page you wrote is never changed without asking.

You can always create a page yourself from the New buttons at the bottom of the panel.

Beside the written log, a branch's Sessions tab lists the sessions themselves — one entry per conversation, with its tool, its title and when it ran, so you can reopen any of them. A branch that has run for months keeps every one. The tab shows the latest ten and says how many there are in all.

log_mission_progress is one of Slate's memory tools, exposed to every AI tool you connect. It appends rather than replaces, so progress is additive and the history stays intact. See Recall & Remember for how it fits the wider recall/remember contract.
