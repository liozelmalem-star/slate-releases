Missions

A mission is a page with a job. Where a plain page holds knowledge, a mission holds work: it's the container you open when you're driving a feature, a fix, or a task from start to finish, and it stays the anchor for everything that happens along the way.

Because a mission is just a page with doc_type = mission, it inherits the whole page model — nesting, breadcrumbs, the block editor — and adds two things that make it a work container:

  • A status dot that reflects the page's status (draft, active, done, canceled) at a glance.
  • A session-log section where progress accumulates over time rather than overwriting itself.

The session log

The point of a mission is continuity across sessions. You (or an AI tool working on your behalf) don't restart from zero each time — the log is a running record of what happened and when.

AI tools write it for you. The MCP tool log_mission_progress takes a branch page and appends a dated entry — summary, decisions, open items — to a Progress section. The entry goes into the branch's Plan page when you have one, and into the branch page itself when you don't. It never creates a page:

recall  →  work the task  →  log_mission_progress(summary, …)

Over a few sessions the Progress section becomes the mission's narrative: what was tried, what landed, what's still open. The next session — human or agent — picks up with that context already in front of it.

Slate offers the page at each milestone

When your work reaches a milestone — a plan, a review, a test plan, a bug report or a design — Slate asks you, in the chat with your AI tool, whether to keep it as a page. In Claude Code the question is a choice you click: Save as a Plan page or Don't save. A tool without clickable questions asks in plain text.

Choose save and the AI tool saves the page under the branch. Choose not to and nothing is saved. If the branch already has that page, the choice is Add to that page, which keeps everything already on it. Nothing is ever saved without asking you.

Every tool also carries the same standing instruction to ask at a milestone.

The app is the backup. A plan written in plan mode that was not saved in the chat waits on the branch's Workspace panel: Claude Code wrote a plan, with Create Plan page, Dismiss and Show plan. Create makes the Plan page and opens it; on a branch that already has a Plan page you wrote, the button reads Add to Plan page and puts the new plan above what you wrote. Dismiss removes the offer, and the same plan is not offered again. A Plan page Slate made from an earlier plan is updated by the next one; a Plan page you wrote is never changed without asking.

You can always create a page yourself from the New buttons at the bottom of the panel.

Beside the written log, Slate keeps a list of the sessions themselves — one entry per conversation, with its tool, its title and when it ran, so you can reopen any of them. A mission that has run for months keeps every one; the panel shows the recent ones and the count tells you how many there are.

log_mission_progress is one of Slate's memory tools, exposed to every AI tool you connect. It appends rather than replaces, so progress is additive and the history stays intact. See Recall & Remember for how it fits the wider recall/remember contract.
