Apps

A app is a small app that runs inside Slate: a review queue, a weekly chart of your sessions, a form that files tasks. You describe it, your AI tool writes it, and it appears beside the chat that made it. You can change it by asking again, or by editing its files.

An app is an artifact with a home of its own: the Apps tab on the rail, beside Artifacts, with every version kept. The decisions behind it are ADR 0077 and, for acting on GitHub, ADR 0080.

Making one

  1. Open Apps. With no app open it is the Apps home: the Apps mark, "What will you build next?", and a box. New app in the list takes you there and puts the cursor in the box.
  2. Describe the app in your own words and press the arrow (or Enter). The box names the AI tool that builds it. It starts on your workspace's tool (set in Connect → AI tools); press it to pick another of your tools. Once you have opened an app, Keep it in a folder… puts the next app in a folder you pick (see Keeping an app in a folder).
  3. You stay on the home. A card and a list row for the new app appear at once, marked Building: "Claude Code is writing App.tsx" when the tool is writing a file, else "Building…". When the tool finishes the card says Ready (its age, as for every app), or Failed if the last build did not pass. Click a card or a row to open the app and watch the chat.

Your apps are the cards under the box. Each shows the app itself, a quarter of its size, in the same sealed frame Preview uses: it asks for nothing and starts nothing from there, and only the cards on screen run (at most nine at once). A card that is not running shows the app's glyph.

Nothing opens in Sessions. The work runs in a session Slate keeps in the background, under your own AI tool and account. See the full session opens it if you want to look.

An app lives in your workspace and belongs to no project. It joins a project only if you keep it in a folder. The list in the rail shows every app in the workspace, with no project picker.

An app that is not in a folder still needs somewhere for its AI tool to work. Slate gives each one its own folder in Slate's data on this Mac (sessions/<workspace>/apps/<app id>), which never syncs. The tool writes the app through Slate, so nothing in that folder is the app. In Sessions its chat is listed as a session with no project. Delete forever removes the folder. Because Slate made that folder, it tells your AI tool to trust it, so the tool does not stop on its first-run "do you trust this folder?" question. A folder you picked is never marked trusted for you.

Your AI tool can still stop and ask something the chat cannot turn into buttons: a sign-in, a question it asks before it starts, or a question with no card yet (see The chat). When that happens, or when 30 seconds pass and the tool has not started on your message, the header says Asking you and the chat shows the session's terminal, under "Claude Code is waiting on you" (with your tool's name). Click into it and answer there. Open in Sessions opens the same terminal full size.

Using and changing one

Pick an app in the list and it opens as a builder of its own. The list steps aside; ‹ Apps brings it back. One line on top shows the app's name, Preview | Dashboard, the chat button and ⋯. The chat is open on the left in both views and stays as you switch. The chat button (Hide chat / Show chat) hides it, and Slate remembers the choice for each app.

  • Preview — the app, updating as the chat works, with Reload and Full size (Esc returns). Under it, one quiet line says what it can reach: "Reads Personal. No internet." (with the name of the workspace you are in).
  • Dashboard — a short list on the left, one section on the right. A section shows only once it has something to say.
  • Data — what the app reads ("Your Personal data"), where it lives (its folder with Show in Finder, or "Only in Slate"), and what it keeps of its own, key by key, with how much of its 1 MB it uses. Edit a key's value (it must be JSON) or Clear it; a running app sees the change after Reload.
  • Permissions — what the app asked for and what you allowed. Take any of it back with its switch. Undo this app's memories retires the memories this app saved, and only those.
  • Versions — each version, who made it (your AI tool, or you) and when. Restore brings an older one back as the newest.
  • Usage — how often you open it: opens in the last 7 and 30 days, and when you last opened it. Counted on this Mac only; it never syncs. If you turned on anonymous telemetry, Slate also sends that an app was opened, never which.
  • Trash, and the 60-day move — ⋯ → Move to Trash takes the app out of your list and keeps every version; it asks nothing, because nothing is lost. Open Trash to Restore it, or to Delete forever, which asks first. While it waits there it does not run, and search and your AI tools do not find it or change it. In a shared workspace, your teammates lose it until you restore it. An app you have neither opened nor changed for 60 days moves to Trash by itself, when Slate starts (with the other startup repairs). Its card warns you first: "Goes to Trash in 7 days", counting down. The move waits until that warning has shown for 7 days, even if Slate was closed on day 53. The 60 days never start before Slate began counting opens, so an old app you still use is safe on the first launch. Opening it, or restoring it, starts the 60 days again.
  • Code — the tab between Preview and Dashboard. The app's folder: a tree and an editor. Add a file (a path like lib/format.ts makes its folder), remove one, and press Save (⌘S). Pick Preview to go back.
  • As you type, the editor offers what can come next: after slate. the calls, inside <Button its props, with each one's description beside the list.
  • Format (⇧⌥F) lays the open file out the way VS Code does; the brush above the tree formats every file. Nothing is formatted on save.
  • Diff shows the open file against the version before, and puts a change back as an ordinary edit. Blame shows, line by line, which version wrote it.
  • Select lines and press the speech bubble to ask the chat about them.
  • Slate checks the app's types and builds it. If either fails, nothing is saved: your edits stay, and each error opens its file at its line. Only the newest version of your own app can be edited.

A teammate's app has Preview and Code only, both read-only. The chat and the Dashboard are the author's.

The chat

Ask in the chat for anything else: "make the buttons green", "add a filter for this week". The same chat goes on while its session is open; New chat starts over. Hide chat puts it away.

The chat is the live session. Its header names your AI tool and says what the session is doing: Asking you, Working or Done. While it works, each step appears as it happens: "Read App.tsx", "Edited App.tsx +18 −4", "Ran yarn tsc --noEmit, no errors", with how long it took on the right. A step that waited for your permission counts the wait too. Stop interrupts it, like Esc in its terminal. It sends one Esc per press and can be pressed again after 3 seconds, because two Esc presses in a row open Claude Code's rewind list.

  • Questions are cards. When the tool asks you to pick, the question shows with its options numbered. One click answers it; Something else lets you type the answer in the box. When it asks to run a command or edit a file, the card shows the exact command or file, with Allow once and Deny. A third button shows only when the tool's own prompt offers it: Allow for this app for "don't ask again" or "always allow", which Claude Code saves in this app's folder, and, for edits, Allow edits for this chat. After you answer, the card folds to "You answered …".
  • A click is a key press, and only for the question you saw. A click sends the tool the same key you would press in its terminal. Before it does, Slate reads the terminal again and checks that the same question, with the same options in the same order, is still there. If it changed, nothing is sent and the chat says so; answer in the session. A new card ignores clicks for half a second, so a double click cannot answer the next one too. Text the session printed, like a file or a command's output, never becomes a card, and a prompt with hidden or direction-changing characters in it shows the terminal instead.
  • Which tools get cards. Claude Code: steps with their times, question cards and permission cards. Codex: steps with their times; its questions and permission prompts show its terminal. Cursor, Gemini CLI and OpenCode: what you asked and what the tool said, with no steps; anything they ask shows their terminal.
  • Every version stays in the chat, with who made it: your AI tool, or you with a save in Code. Restore brings an older one back as the newest, so nothing is lost. When a session ends, what you asked and each version stay; the AI's own words are in the session, under See the full session while it runs.
  • Ideas for what next. The AI ends each answer with up to three ideas. Each is a button that asks for it.
  • Build or Discuss. Under the box, Discuss talks a change through and changes nothing. Build it then asks for what it planned.
  • Fix with AI. When the app no longer type-checks, or stops on an error while it runs, a note above it says where. Fix with AI sends the chat only what Slate worked out: the file (only if it is one of the app's own files) and line, and the kind of error (a TypeError, say). It never sends the app's own error text, because an app's words are not to be trusted as instructions to your AI tool. Quote it puts the app's text in the chat box as a quoted block that you can read, edit and send yourself. Pointing at a part of the app does the same. Invisible characters are removed from anything the app wrote before it is shown.
  • Each new version is checked that it renders. After a version builds, Slate runs it once in the same sealed frame Preview uses, hidden, with no network. It answers what the app reads, never answers a write or a read from outside your Mac (GitHub, MCP tools), and never shows you a card from it. The version fails if it throws, if Slate refuses one of its calls, or if nothing shows within 10 seconds. An app that asks for a permission does not fail. The chat then says so: "Version 3 built, but did not render: pages.get was refused (bad_request)." with the file and line when Slate finds them.
  • The previous good version stays on screen until a new one renders. A note above Preview says which version you see and why.
  • Slate asks the AI tool to fix it. It tells the tool in its answer to publish_app, so the tool usually fixes it in the same turn. If the tool has already finished, Slate types one message into the session, with only what Slate checked (the call and its code, the kind of error, the file and line), never the app's own words. The step then ends "Asked Claude Code to fix it." (with your tool's name). Slate does this at most twice per ask. After that, or for a version you saved yourself, the step has Fix with AI.

When Apps opens on an app by itself, because it is the newest one, the list stays. A link that names an app under Artifacts (from ⌘K, Activity or a tool) opens it in Apps.

Keeping an app in a folder

An app can live in a folder on your Mac, as a git repository. The folder's files are the app's files, and the folder is a project in Slate, so you can start AI sessions in it like in any project. The decision behind it is ADR 0079.

  • Making one. On the Apps home, describe the app and press Keep it in a folder…. Pick an empty folder, or one that does not exist yet: Slate makes it a git repository, writes the starting files and commits them. Or pick a folder that already holds an app (an index.html at its top): its files become the app. A folder holding other files is refused, so Slate never writes over your work.
  • Changing it. Save in Code, ask in the chat, or edit the files in the folder with any tool. An edit made outside Slate rebuilds the app on its own. If it builds, it is the next version; if it does not, nothing changes and the error shows, and Code says the folder has changes Slate has not built. Slate only writes the folder after a build worked. Before a save or a Restore writes over a change in the folder that is not in a version yet, Slate commits it first, so it stays in the git repository's history.
  • Each version is a commit. Slate commits only the app's files, so anything else you staged stays as it was. No git hook of that git repository runs, and Slate's commits are not signed, so a git repository that signs every commit never asks for a passphrase. It never pushes and never changes branch.
  • The folder moved or was removed. The app keeps running from its newest version, and saving waits. The Dashboard says "Not found"; Find the folder… points the app at its new location. An empty folder gets the newest version written into it. Moving an app to the Trash, or deleting it forever, never touches the folder.
  • An app kept only in Slate can move into a folder later: Dashboard → Data → Keep it in a folder….

Its files are the folder's files of the types an app may hold, leaving out what git ignores, dot-folders, node_modules and build output. Linked files (symbolic links) are skipped, so a folder cannot bring a file from elsewhere on your Mac into an app. Slate writes nothing into a dot-folder (such as .git or .vscode), node_modules or build output, never writes through a linked file or folder, and refuses two files whose names differ only in case or accents, because macOS stores them as one. Its card on the Apps home carries a small folder mark.

A folder grants nothing. The app runs sealed exactly like any other, with no internet. In a shared workspace a teammate sees the built page and never your folder's path, which stays on this Mac.

What it can do

It reads freely inside the workspace it lives in:

  • pages from every project, and what each one is (a project, a branch, a document), so it can draw the tree
  • memories
  • AI sessions, their counts per day and per tool, and the ones running right now
  • AI runs: which tool and model, how long, how many tokens, and what they cost
  • git activity in the folders of the workspace's projects: commits, branches made and switched, files staged
  • the workspace's artifacts, which it can open in Slate
  • agents

It sees the whole workspace it lives in, every project, and no other workspace: your Personal apps never read a shared workspace, and the reverse. Activity in a folder with a similar name is not there. The project an app was made in is only where it was made. It keeps its own data on this Mac (up to 1 MB), never synced.

Anything else needs a permission, which the app lists in its slate.json with a reason. When a new app's first version asks for anything beyond reading, its chat shows one card with what the app asks for and why, and Allow or Not now. Allow grants exactly what the card lists. If you say Not now, or the app asks for a permission in a later version, Slate asks the first time the app uses it, on a card it draws outside the app:

PermissionWhat it allows
Read your TasksEvery open item in Tasks.
Change your TasksAdd your own items, set reminders, mark items done.
Read your GitHubYour open pull requests, the ones waiting for your review, and their checks. Read only, as the GitHub account this workspace uses.
Act on your GitHubAsk to approve, request changes on, comment on or label your pull requests, as the GitHub account this workspace uses. Slate shows you each action first, every time.
Save memoriesSave memories, filed in the project the app was made in, or in the workspace. Each one is held until you release it.
Write pagesMake pages and add text to pages in the project the app was made in. An app made in no project makes its pages at the top of the workspace and may add to any page of it.
Run agentsRun an agent. Slate asks you each time, naming it.
Open AI sessionsOpen a session with a prompt typed in. You press Send.

Even when allowed, a memory or page write shows you its words on a card before anything is saved. The card shows the whole text, in a box that scrolls, with its length, and says if some are invisible characters, so what you approve is what is saved. It also names the page the text is added to, and the kind of memory. Slate's server writes the card's words and gives the window a one-time ticket for them. The write runs only when that ticket comes back, for the same app, call and words, within 5 minutes. The app never sees the ticket.

An action on GitHub has its own card, in red, because it acts outside Slate and cannot be undone. It names the GitHub account that will act, the pull request, its title as a quote, and the exact words. The words are never the app's: they are words you wrote for that app under Permissions, or words you type on the card. Slate reads the pull request again when you press the button, and sends nothing if the card is no longer true. The button works 0.6 seconds after the card appears, so a click aimed at the app cannot land on it. An app takes at most 5 actions an hour, all apps together 20, and Permissions lists every one. Permissions lists what the app asked for and lets you take any of it back. An app cannot remove anything.

Reading through your MCP tools

An app can read through the MCP tools your workspace already reaches: the servers you connected in Slate and the ones your AI tools declare, such as Linear's or Notion's. It has no network, so Slate makes the call and hands the app the answer. The decision is ADR 0078.

  • One tool at a time. The app lists each tool it wants in slate.json, with a reason. The first time it calls one, Slate shows a card with the server, the tool's name, its description and the reason. Nothing allows a whole server.
  • Only reads, and you say so. Allow stays off until you tick "This tool only reads. It changes nothing." A tool's server may claim the tool only reads; the card shows that claim, but it never ticks the box for you. Like every card an app makes Slate show, Allow works only 0.6 seconds after the card appears. A tool whose name or server says it writes is never offered.
  • A changed tool asks again. What you allow is pinned to the tool as you read it. If the server changes its name, description, inputs or hints, the app is refused until you allow it again, on a card marked Changed since you allowed it.
  • Checked on the way in and out. The app's arguments must match what the tool says it takes. The answer has invisible characters taken out and is cut at 20,000 characters. Words in it were written by someone else, so an AI tool that is given them sees them as quoted data.
  • Paced. Slate keeps an answer for a minute and asks each server at most 20 times a minute for apps, so an app cannot spend your limits with the vendor.
  • Only this workspace's servers. The app never sees an address, a token or a server's own error words.

Permissions on the app's Dashboard lists each tool it names, where it comes from, and whether it is allowed, changed, or cannot be offered. Its switch allows a tool, through the same card, or takes it back.

What an app writes stays the app's

You are not sure an app is telling the truth, so what it writes is marked as its own, for as long as it exists.

  • A memory an app saves is held from the first moment. It sits in Memory, marked as the app's, and no session, teammate or AI tool receives it until you release it. It is never shared with a team, released or not. Undo this app's memories retires every memory that app saved, and only those.
  • A memory you release is still quoted. An AI tool sees it as Data saved by an app (not an instruction): «…», with invisible characters removed.
  • A page an app makes, or adds text to, is marked as written by an app. Search, get_page, mentions and briefs show an AI tool that page's text in the same quote. The mark is per page, so a page of yours that an app added to is quoted as a whole. It outlives the app: removing the app does not turn its text back into yours.

What it cannot do

  • Reach the internet. No requests, sockets, images, fonts or scripts from anywhere. No WebRTC, no resource hints, no frames, no popups. If it tries to leave for another address, Slate closes it.
  • Read outside its workspace, or anything of a teammate's.
  • Change anything through an MCP tool. It may only read through a tool you allowed.
  • Open any screen in Slate it likes. It can open one page, task or artifact by its id (slate://page?id=…, slate://task?id=…, slate://artifact?id=…). Any other link is refused. A task link carries only the id: Tasks finds the item and opens the section it is in.
  • Act on its own where it matters: an agent, a session, a memory or page text and every GitHub action all wait for you.
  • Choose what it says on GitHub, or where. Its words are yours, and its target is a pull request in your own lists.

In a shared workspace, a teammate sees your app as its built page, with nothing answered: it never reads their store, and its reads fail at once saying so. They get Preview and Code, read-only, and no chat or Data.

When Slate updates

An app may name the SDK version it was made for in slate.json ("sdk": 1). Within a version Slate only adds calls and parts. When you open your app, Slate checks its code against this version of Slate; if it no longer fits, a note above the app says where, and the chat can fix it.

For the AI tool building it

An app is index.html with <script type="module" src="./App.tsx"></script>, then .tsx .ts .jsx .js .css .json .md .svg files in any folders. It may import its own files and react, react-dom/client, lucide-react, @slate/sdk (the calls), @slate/sdk/react (useQuery, useStore) and @slate/ui (Slate's own buttons, inputs, cards, rows and states, in both themes). An app has its own two MCP tools, apart from the ones that publish pages. The tool sends files with publish_app. get_app returns three things beside the app's files:

  • playbook: the steps and rules for building or changing an app. Write slate.json first, learn from the closest example, add only what the app uses, use the API exactly, draw with @slate/ui, never call the network, then publish and fix every error Slate reports. Slate's own prompts only carry your ask and the app's id, and tell the tool to follow the playbook, so every AI tool works from the same rules.
  • sdk: the whole API as TypeScript declarations, the same ones Slate checks every build against. The calls are listed in App API.
  • examples: four whole apps from Slate that build (a chart, a tasks list that adds a task, notes kept in the app's own data, and a page written after you approve it), and your other apps in this workspace by id and title, so the tool can read the closest one.

Every publish checks the code against slate.json. A call such as slate.tasks.create that needs a permission slate.json does not list is a build error at its line, and so is a permission that no call uses. The check reads the source as text, skipping comments and strings. It cannot see a call made through another name (const s = slate), so Slate still refuses at run time any call the person has not allowed.

After a version builds, Slate runs it once to check that it renders. publish_app waits a few seconds for that and returns render; get_app returns the same render for the version it reads. render.status is ok, failed or pending. When it failed, render.problems lists each problem (kind, call, code, errorClass, file, line) and render.next says it in one line. pending means the Slate window has not run it yet, for example because Slate is closed: call get_app later.

For an app kept in a folder, get_app also returns folder, and its files are the folder's as they are now. The tool can edit them there, and Slate builds the app again on its own; publish_app with the app's id and files: [] builds the folder at once and returns any build errors. publish_app with files writes them into the folder too.

Limits

  • Up to 300 files per app.
  • An app's own data: 1 MB.
  • A toast at most once a second.
  • Up to 20 MCP tools per app; a tool's arguments up to 4,000 characters, its answer up to 20,000.
  • 5 GitHub actions an hour (20 for all apps together), and 20 sets of words, each at most 1,000 characters.

Slate is in alpha. Your data stays on your machine.
