Apps

An app is a small program that runs inside Slate: a review queue, a weekly chart of your sessions, a form that files tasks. You describe it, your agent writes it, and it appears beside the chat that made it. Change it by asking again, or by editing its files.

An app is an artifact with its own Apps item on the rail. Every version is kept. Decisions: ADR 0077, and ADR 0080 for GitHub.

Making one

  1. Open Apps. With no app open you see the Overview: a box at the top, then your apps and widgets as cards, two to a row. Before your first app or widget, "What will you build next?" stands above the box. Apps · Widgets at the top of the side panel picks which you see and make; + in its title row asks App or Widget.
  2. Describe the app and press the arrow (or Enter). The box names the agent that builds it, your workspace's tool from Connect → Agents; press it to pick another. Keep it in a folder… puts the app in a folder you pick (below).
  3. A card and a list row appear at once, marked Building: "Claude Code is writing App.tsx" while a file is written, else "Building…". When done, the card shows the app's age, or Failed if the last build did not pass. Click it to open the app and watch the chat.

Each card shows a still picture of the app, kept for the 24 apps shown most recently. Without one for the current version, Slate runs the app once, unseen, in the sealed Preview frame (nine cards at most at once). A pulsing doc shape shows meanwhile, then the app's glyph after 12 seconds.

The work runs in a session Slate keeps in the background, under your own agent and account. It does not open in Sessions; See the full session opens it.

An app belongs to the workspace, not a project, unless you keep it in a folder. The rail lists every app in the workspace. An app outside a folder gets a work folder on this computer (sessions/<workspace>/apps/<app id>), never synced; the tool writes the app through Slate, not into it. Delete forever removes that folder. Slate marks it trusted so tools skip "trust this folder?".

If your agent stops on something the chat cannot turn into buttons (a sign-in, a question before it starts, a question with no card yet), or does not start within 30 seconds, the header says Asking you and the chat shows the session's terminal under "Claude Code is waiting on you" (your tool's name). Answer there. Open in Sessions opens it full size.

Using and changing one

An app opens as a builder under the same header every place has. It reads Apps / and the app's name (Widgets / for a widget); pressing Apps goes back to the Apps home. Then the tabs Preview | Code | Dashboard, and on the right the chat button, ‹ v2 of 3 › (from two versions) and ⋯. ⌘\\ shows or hides the Apps list. The chat stays open on the left in every view; Hide chat / Show chat toggles it, remembered per app.

  • Preview: the app, updating as the chat works, with Reload and Full size (Esc returns). A line under it says what it can reach: "Reads Personal. No internet."
  • Dashboard: a section shows only when it has something to say.
  • Data: what the app reads ("Your Personal data"), where it lives (its folder with Show in Finder, or "Only in Slate"), and its own keys with how much of 1 MB they use. Edit a value (JSON) or Clear it; a running app sees the change after Reload.
  • Permissions: what the app asked for and what you allowed, each with a switch to take it back. Undo this app's memories retires the memories this app saved, only those.
  • Versions: each version, who made it (your agent or you) and when. Restore brings an older one back as the newest.
  • Usage: opens in the last 7 and 30 days, and when you last opened it. Counted on this computer, never synced (telemetry never says which app).
  • Code: the app's folder as a tree and an editor. Add a file (a path like lib/format.ts makes its folder) or remove one. The save button counts changes ("Save 2 changes", ⌘S); Discard puts your edits back.
  • The editor completes calls after slate. and props inside <Button. Format (⇧⌥F) formats the open file, the brush above the tree every file; nothing formats on save.
  • Diff shows the open file against the version before and puts a change back as an edit. Blame shows which version wrote each line. Select lines and press the speech bubble to ask the chat about them.
  • Slate checks types and builds. If either fails, nothing is saved, your edits stay, and each error opens its file at its line. Only the newest version of your own app is editable.
  • Trash: ⋯ → Move to Trash keeps every version and asks nothing. In Trash, Restore brings it back and Delete forever asks first. A trashed app does not run, and search and agents cannot find or change it. In a shared workspace teammates lose it until you restore it. An app you have not opened or changed for 60 days moves to Trash when Slate starts. Its card warns "Goes to Trash in 7 days", counting down, and the move waits until the warning has shown for 7 days. Counting never starts before Slate began counting opens, so an old app you use is safe on the first launch. Opening or restoring it restarts the 60 days.

A teammate's app has Preview and Code only, read-only. The chat and Dashboard are the author's.

When Apps opens on the newest app by itself, the list stays. A link to an app under Artifacts (from ⌘K, Activity or a tool) opens it in Apps.

The chat

Ask for anything: "make the buttons green", "add a filter for this week". The chat is the live session. New chat starts over. The header names your agent and its state: Asking you, Working or Done. Each step appears as it happens ("Read App.tsx", "Edited App.tsx +18 −4", "Ran yarn tsc --noEmit, no errors") with its time. Stop sends Esc to the terminal and can be pressed again after 3 seconds, because two quick Esc presses open Claude Code's rewind list.

  • Questions are cards. A question shows numbered options; one click answers. Something else lets you type. For a command or file edit, the card shows the exact command or file with Allow once and Deny. Allow for this app and Allow edits for this chat show only when the tool's own prompt offers them. Answered cards fold to "You answered …".
  • A click is a key press for the question you saw. Slate rereads the terminal first; if the question changed, nothing is sent and the chat says so. A new card ignores clicks for half a second. Text the session printed never becomes a card.
  • Which tools get cards. Claude Code: steps with times, question and permission cards. Codex: steps with times; its questions and permissions show its terminal. Gemini CLI and OpenCode: steps without times; Cursor: steps without times or what they printed. Copilot CLI: what you asked and what the tool said, no steps. Anything these four ask shows their terminal.
  • Every version stays in the chat, with who made it, and Restore brings one back.
  • Ideas and Discuss. Each answer ends with up to three ideas, each a button that asks for it. Discuss talks a change through and changes nothing; Build it then asks for what it planned.
  • Each new version is checked. After a build, Slate runs it once, hidden, with no network, in the Preview frame. Writes and outside reads (GitHub, MCP tools) get no answer and show no card. The version fails if it throws, if Slate refuses a call, or if nothing shows within 10 seconds. Asking for a permission does not fail it. The chat says: "Version 3 built, but did not render: docs.get was refused (bad_request)." with file and line when known. The last good version stays on screen until a new one renders, and a note says which you see.
  • Slate asks the tool to fix it. The failure is in the answer to publish_app, so the tool usually fixes it in the same turn. If the tool has finished, Slate types one message into the session with only what it checked (call, code, kind of error, file, line), never the app's words. The step ends "Asked Claude Code to fix it." At most twice per ask. After that, or for a version you saved, the step has Fix with AI.
  • Fix with AI also appears when the app stops type-checking or stops on an error. It sends only the file (if the app's own), line and kind of error (a TypeError, say), never the app's error text, because an app's words are not trusted as instructions. Quote it puts that text in the chat box as an editable quote. Pointing at a part of the app does the same. Invisible characters are removed from anything the app wrote.

Keeping an app in a folder

An app can live in a folder on your computer as a git repository. Its files are the folder's files, and the folder is a project in Slate, so you can start AI sessions in it. Decision: ADR 0079.

  • Making one. On the Apps home, describe the app and press Keep it in a folder…. Pick an empty or new folder: Slate makes it a git repository, writes the starting files and commits. Or pick a folder that already holds an app (an index.html at its top). A folder with other files is refused, so Slate never overwrites your work. An app kept only in Slate can move into a folder later: Dashboard → Data → Keep it in a folder….
  • Changing it. Save in Code, ask in the chat, or edit the files with any tool. An outside edit rebuilds the app. If it builds, it is the next version. If not, nothing changes, the error shows, and Code says the folder has changes Slate has not built. Before a save or Restore overwrites a change not yet in a version, Slate commits it first.
  • Git. A folder that is the top of a git repository stays as it is. A folder inside another one gets its own, so Slate's commits never land among your work. Each version is a commit of only the app's files. No git hook runs, commits are unsigned, and Slate never pushes or changes branch.
  • The folder moved or was removed. The app keeps running from its newest version and saving waits. The Dashboard says "Not found"; Find the folder… points to the new place. An empty folder gets the newest version. Trash and Delete forever never touch the folder.

Git-ignored files, dot-folders, node_modules, build output and symlinks are skipped, and two files whose names differ only in case or accents are refused. A folder grants nothing: the app runs sealed, with no internet. In a shared workspace a teammate sees the built doc, never your folder's path.

What it can do

It reads freely inside its own workspace (every project, no other workspace; Personal apps never read a shared workspace, nor the reverse): docs and what each is, memories (except those kept away from apps), AI sessions (counts and the ones running now), agent runs, git activity in the workspace's project folders, artifacts, and agents. The project an app was made in is only where it was made. It keeps its own data (up to 1 MB) on this computer, never synced. Every call is in App API.

Anything else needs a permission, listed in the app's slate.json with a reason. When a new app's first version asks for more than reading, its chat shows one card with what it asks and why, with Allow or Not now. Allow grants exactly what the card lists. After Not now, or for a permission a later version adds, Slate asks the first time the app uses it, on a card it draws outside the app.

PermissionWhat it allows
Read your TasksThe open items in Tasks, and with open: false the done ones too.
Change your TasksAdd your own items, set reminders, mark items done.
Read your GitHubYour open pull requests, the ones waiting for your review, and their checks. Read only, as the GitHub account this workspace uses.
Act on your GitHubAsk to approve, request changes on, comment on or label your pull requests. Slate shows each action first, every time.
Save memoriesSave memories in the project the app was made in, or the workspace. Each is held until you release it.
Write docsMake docs and add text to docs in the project the app was made in. An app made in no project makes docs at the top of the workspace and may add to any doc.
Run automationsRun an automation. Slate asks each time, naming it.
Open AI sessionsOpen a session with a prompt typed in. You press Send.

Even when allowed, a memory or doc write shows its words on a card first: the whole text in a scrolling box with its length, a flag for invisible characters, and the doc or memory kind. Slate's server writes the card's words and gives the window a one-time ticket. The write runs only when the ticket comes back for the same app, call and words within 5 minutes. The app never sees it.

An action on GitHub has a red card, since it cannot be undone. It names the account, pull request, title and exact words. The words are never the app's: you write them under Permissions, or type them on the card. Slate rereads the pull request when you press the button and sends nothing if the card is stale. The rules and limits are in App API. An app cannot remove anything.

Reading through your MCP tools

An app can read through the MCP tools your workspace already reaches, such as Linear's or Notion's. The app has no network, so Slate makes the call and hands over the answer. Decision: ADR 0078.

  • One tool at a time. The app lists each tool in slate.json with a reason. The first call shows a card with the server, tool name, description and reason. Nothing allows a whole server.
  • Only reads, and you say so. Allow stays off until you tick "This tool only reads. It changes nothing." A server's own claim never ticks the box. Allow works 0.6 seconds after the card appears. A tool whose name or server says it writes is never offered.
  • A changed tool asks again. If the server changes a tool's name, description, inputs or hints, the app is refused until you allow it again, on a card marked Changed since you allowed it.
  • Checked and paced. Arguments must match the tool's schema. The answer loses invisible characters, is cut at 20,000 characters, and reaches an agent as quoted data. Limits are in App API.
  • Only this workspace's servers. The app never sees an address, a token or a server's own error words.

Permissions on the Dashboard lists each tool the app names, its source, and whether it is allowed, changed, or cannot be offered. The switch allows it through the same card, or takes it back.

What an app writes stays the app's

An app is not trusted to tell the truth, so what it writes stays marked as its own.

  • A memory an app saves is held from the first moment. It sits in Memory marked as the app's, and no session, teammate or agent receives it until you release it. It is never shared with a team. Undo this app's memories retires every memory that app saved.
  • A released memory is still quoted. An agent sees Data saved by an app (not an instruction): «…», with invisible characters removed.
  • A doc an app makes or adds to is marked as written by an app. Search, get_doc, mentions and briefs show an agent that doc's text in the same quote. The mark is per doc, so a doc of yours that an app added to is quoted whole. It outlives the app.

What it cannot do

  • Reach the internet. No requests, sockets, images, fonts, scripts, WebRTC, resource hints, frames or popups. If it tries to leave, Slate closes it.
  • Read outside its workspace, or anything of a teammate's.
  • Change anything through an MCP tool.
  • Open any screen it likes. It can open one doc, task or artifact by id (slate://doc?id=…, slate://task?id=…, slate://artifact?id=…; an id is up to 64 letters, digits, _ or -). Any other link is refused.
  • Act on its own where it matters: an automation, a session, a memory or doc text and every GitHub action wait for you.
  • Choose what it says on GitHub, or where. The words are yours, and the target is a pull request in your own lists.

In a shared workspace a teammate sees your app as its built doc with nothing answered: its reads fail at once and never reach their store. They get Preview and Code, read-only.

When Slate updates

An app may name the SDK version it was made for in slate.json ("sdk": 1). Within a version Slate only adds calls and parts. When you open your app, Slate checks its code against this version of Slate. If it no longer fits, a note says where and the chat can fix it.

Widgets

A widget is an app made for one tab, shown there as a card: today Activity or Home. The Overview lists widgets under Your widgets, after your apps, and the side panel lists them with the tab each is on.

  • Making one. Pick Widgets at the top of the side panel (or + › Widget). Show it on appears: pick the tab, describe the card ("tokens per project, as a bar list") and press the arrow. Your agent builds it like an app, and you change it the same way in its chat. Widgets are made and changed only here.
  • Showing one. A widget is on its tab once built: on Activity at the top of the side column, on Home in a row under the box. "On Activity" or "On Home" shows in the Apps list and on its card. Its ⋯ menu opens it here or takes it off the tab; on Activity the + in the side panel's title puts it back.
  • What it reads. Only what its tab shows. An Activity widget reads the sessions and memories learned in the range and project picked in Activity's side panel, and reads again when you pick another. Memories kept away from apps are left out. A Home widget reads what is live now: the AI sessions running for the project picked on Home, and your open tasks only if it asked for Read your Tasks and you allowed it. With a project picked, it gets only that project's tasks. A widget reads nothing else, writes nothing and calls none of your MCP tools. It can keep its own settings and show a toast, but cannot open a doc, task or artifact. Slate, not the widget, decides range and project.
  • Its tab is fixed. An app cannot become a widget, nor the reverse. Decision: ADR 0089.

For the agent building it

An app is index.html with <script type="module" src="./App.tsx"></script>, plus .tsx .ts .jsx .js .css .json .md .svg files in any folders. It may import its own files and react, react-dom/client, lucide-react, @slate/sdk, @slate/sdk/react, @slate/sdk/format and @slate/ui. The tool sends files with publish_app. get_app returns three things beside the files:

  • playbook: the rules for building or changing an app (write slate.json first, learn from the closest example, use the API exactly, draw with @slate/ui, never call the network, fix every error Slate reports). Slate's prompts carry only your ask and the app's id, so every agent follows the same rules.
  • sdk: the whole API as TypeScript declarations, which every build is checked against. See App API.
  • examples: four whole apps that build, and your other apps in this workspace by id and title.

Every publish checks the code against slate.json. A call without its permission listed (such as slate.tasks.create) is a build error at its line, and so is a permission no call uses. The check reads source text, so it misses a call made through another name (const s = slate); Slate still refuses at run time any call you have not allowed.

publish_app and get_app return render (ok, failed or pending); fields are in App API. For an app in a folder, get_app also returns folder, and its files are the folder's as they are now. The tool edits them there and Slate rebuilds. publish_app with the app's id and files: [] builds the folder at once and returns build errors; with files, it writes them into the folder too.

Limits

300 files per app. 1 MB of its own data. 20 MCP tools per app. Other limits are in App API.

Slate is in alpha. Your data stays on your machine.
