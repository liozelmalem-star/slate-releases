Features

Workspaces

A workspace is one SQLite file on your machine. It holds its own docs, memory, activity, artifacts and search. Switch into one and the whole app is in it.

Every workspace starts private. Share one and everything in it belongs to its members. Nothing is marked per doc.

Personal, and the ones you share

Personal is the workspace you start with. It is the only one that fills by itself: captured sessions, git repositories with no project doc, cross-project notes. It cannot be left or removed.

Any workspace can be shared, Personal included. Click a workspace's row in Settings → Workspaces and use its Sharing switch. Sharing publishes what the store already holds, so Slate first counts the docs, memories, activity rows and artifacts and asks you to agree to that number. Switching sharing off withdraws them. They were readable in between.

Sharing needs the Team plan. Everything else is free, including any number of private workspaces. Team is coming soon, so on Free the sharing switch is refused with a message that says so. Accounts that already shared keep sharing at no charge until Team ships. Turning sharing off is always allowed.

The switcher sits at the top of the rail. Work landing in the wrong workspace is a privacy problem, so the current workspace must be clear at a glance. The badge is Slate's mark in the workspace's colour, with its name under it. A shared workspace has a small people mark. A workspace that fails to sync has a warning. A read-only one has a padlock. In the open switcher each row says Shared or Private, whether it syncs.

⌘\` steps to the next workspace and ⌘~ to the previous one. With only Personal, they do nothing.

Switching back returns you to where you left off: the same doc, tab strip and rail section. A workspace not yet opened in this window opens on Home. Nothing carries over from the one you left, because a doc id means something only inside one store.

What follows a switch

Everything about the work is per workspace: open tabs, favourites, recents, expanded sections, what Home is scoped to.

Some things describe this computer and are the same everywhere: theme, sidebar and rail widths, running AI sessions, the CLI accounts your tools use. They live in machine.db.

Automations are per workspace. An automation belongs to a group or project doc, so it lives with the docs it reads.

Using it

  • Sign in. Settings → Account, with GitHub. The first sign-in creates your account.
  • Make, share, rename, recolour, leave or remove a workspace. Settings → Workspaces. A private workspace can be renamed at once. Inviting people needs it shared first, because an invitation is a cloud record. Personal keeps its name. A workspace you belong to but have not set up on this machine shows Add here.
  • Switch. Use the switcher. Its last row, Manage workspaces…, opens Settings → Workspaces.
  • Move a doc in. Right-click it in the sidebar, or use ⋯ in its header, and pick Move to <workspace>. See Working in a Shared Workspace.
  • Read what others wrote. Their docs sit in your tree with their avatar on the row. The editor is read-only.
  • Ask your AI. recall_workspaces and workspace_doc answer "has anyone solved this?" across every workspace you belong to, including ones not set up here. recall stays inside the workspace of the working directory.

How a shared workspace stays in step

Sync runs every 2 minutes and once at startup. Sync now in Settings → Workspaces runs it at once and reports what moved. After a failure the retry waits 2 minutes, then 4, 8 and so on up to 1 hour. A success resets the wait. With no shared workspace, the loop does nothing.

It is a timer, not a hook on writes. Docs are written by the UI, by MCP tools and by the session watcher, and a hook on each would miss a writer sooner or later.

The pass asks the cloud for two columns per row, compares a hash of exactly the published fields, and sends only what changed. A workspace with nothing new costs one query.

The same comparison withdraws. A row the cloud holds that your replica no longer has (in Trash, removed for good, or moved to another workspace) is tombstoned upstream, and every member's copy goes on their next pull. A store's first pass (new Mac, reinstall) withdraws nothing and brings your own rows down first.

Offline works. You are the only writer of your rows, so a queue draining in any order lands the same state.

What actually leaves your machine

Everything in a shared workspace is for its members. Slate withholds what is specific to your machine.

Postgres enforces the activity kind list with a CHECK constraint, not the client.

The right column withholds fields, not words. A doc body and a memory's sentence go up as written. A path you typed into a doc, or one an agent recorded in a decision, goes up with the row. Withheld are the structured places a path is held: properties and the absolute git repository path on a commit.

Every workspace, Personal included, keeps an append-only log in its own store: docs created, renamed, moved, trashed and removed, joins, syncs that moved something, withdrawals. Two SQLite triggers stop an entry being changed or removed for 400 days. Startup then removes it, and activity rows that old.

Leaving, erasing, and being removed

Four actions with different effects.

ActionWhat happens
Stop sharingThe workspace stops publishing and everything you authored is withdrawn from the cloud and from every member's copy on their next sync. Slate first says how many docs, memories, activity rows and artifacts, and the button reads Stop sharing and erase my work. The store stays on this machine and keeps working. Share again and the next sync publishes it as it stands then. The cloud keeps a blank row per item, saying it existed. When you are the only member, Slate removes those too.
LeaveThis machine's replica is removed after a copy is kept in backups/ (named left-…). For a shared workspace the button reads Remove this machine's copy of “…” and your rows upstream stay. A workspace never shared has no other copy, so the button says Delete workspace forever, the confirm reads Delete “…” forever, with everything in it, and you should export from Storage first. If the copy fails, or a connected agent still has the workspace open, nothing is removed. Personal cannot be left.
Erase my workEvery row you authored there is tombstoned upstream, and every member's replica drops it on their next pull. Final: sharing again does not bring it back. This is the Article 17 request.
Someone removes you, or the owner removes the workspace for goodRow Level Security stops answering. Your replica is marked read-only. What you read yesterday stays readable and exportable. Removing it is your decision.

Personal is never marked read-only, because every window falls back to it. If it is shared and its cloud side goes away, sync fails. Stop sharing is the way out.
