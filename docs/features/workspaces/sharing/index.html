Working in a Shared Workspace

There is no "publish this doc" button. The unit is the workspace: it is a team's, so everything in it is the team's.

A doc you create there is shared at once. A decision your AI records there is the team's. A commit in a git repository the workspace owns lands in its activity feed. A captured AI session's doc is never published.

Work you do not want shared goes in a workspace you have not shared. The boundary is a different file.

Sharing needs Team, which is coming soon. On Free you cannot turn it on. Accounts that already shared keep sharing at no charge until Team ships.

Getting existing work in

A group or project is moved, not copied. Right-click it in the sidebar, or use ⋯ in its header, and pick Move to <workspace>. Slate first says how many docs move and who can read them.

  • The whole subtree goes. A group takes its projects. A project takes its branches and their plans and designs.
  • Ids are kept. A doc already published keeps its cloud rows.
  • Properties come too. The folder path routes the git repository to the workspace.
  • Its memory comes too: memories anchored to the moved docs. A move refuses to carry a memory anchored to no doc.
  • It lands at the top level. Its old parent stayed behind.
  • It refuses what is not yours. A subtree with anyone else's docs, memory or activity is refused, and so is a move where either workspace is read-only for you. Nothing is copied or removed then.

The order is read, write, remove. No transaction spans two SQLite files. A failure between write and remove leaves the docs in both workspaces, which you can see and re-run.

Moving out works the same way.

Read-only, and why there is no merge

Each doc has one writer: its author. A teammate's doc opens as the real doc with a read-only editor and a line giving the reason.

ReasonMeaning
Another authorA teammate wrote it, and the line names them. Their edits reach you. Yours would not reach them.
Workspace is read-onlyThe workspace was removed upstream, or you were removed. Everything stays readable and exportable.

Who wrote what

In a shared workspace every doc and memory is signed.

  • Sidebar: a teammate's doc shows their picture at the end of the row. Your own show none.
  • Under the title: "Written by you" or "Written by Sam".
  • Memory: a teammate's memory shows their name where yours shows "you".

Personal shows none of this.

Names come from each member's profile. Slate keeps the member list on your machine, refreshed at app start and when you open Members in Settings, so docs stay signed offline. A member not yet looked up shows as "A teammate".

Only the author can change a row, so "take the remote copy" and "send the local copy" never compete. There are no version columns, no 409 handling and no conflict resolution.

Your manual sibling order is not published. On a teammate's machine your docs arrive in pull order.

Removals travel as tombstones

A row that vanished from the cloud looks the same as one you have not fetched yet. So a removal is a tombstone: a row saying "gone", and when.

doc.parent_id cascades on removal, so a plain local DELETE of a teammate's doc would take your children with it. The pull re-parents your surviving children to the workspace root first. Sync now reports that count as reparented.

A tombstone removes only its author's row. When you move your doc to Trash, a teammate's doc under it stays. When you delete your doc forever, their doc moves up to your doc's parent, with everything under it.

Memory

A memory (a decision, fact, preference or state saved by remember or record_decision) is anchored to a doc. If that doc is in a shared workspace, the memory is the workspace's.

What travels, and what never travels, is listed in What actually leaves your machine. Supersede a decision and the old one is withdrawn on the next pass.

Artifacts

An artifact published while you work in a shared workspace belongs to it. Every member sees it in Artifacts. Only you can publish a new version, rename it or delete it forever. A teammate's artifact says who wrote it, and its menu offers Copy and Open in browser only.

Only the newest version travels. Members keep the versions they received. Removing an artifact withdraws it from everyone on the next sync.

Finding a teammate's memory from your own checkout

You and a colleague clone one git repository to different folders. Their memories hang on docs that record a path missing on your machine.

So Slate identifies a git repository by its git remote, normalised to host/owner/repo. When recall finds no stored path for your checkout, it finds the doc recording the same remote.

  • Only the remote counts. A checkout with no fetchable remote gets nothing.
  • Never by name. Two unrelated git repositories called site share nothing.
  • Any clone form. git@github.com:Acme/Site.git and https://github.com/acme/site are one git repository: the key is lower-cased and credentials are stripped.
