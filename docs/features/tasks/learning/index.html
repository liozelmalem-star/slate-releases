How Slate learns an app

View as markdownOpen the .md copy of this page

Slate can read some apps it was not built for. This guide covers the automatic try, Teach Slate, the safety check on every call, and what Tasks keeps on disk.

Tools Slate learns on its own#

During a sync, a tracker app with no reader gets one try a day per workspace. No model.

StepWhat happens
PickRead-only tools whose names say tasks, issues, items, tickets, cards or stories and that are yours (get_my_issues) or take an assignee. Writers and tools needing unknown input are never tried
IdentifyYour id from the app's "who am I" tool (atlassianUserInfo, Todoist user-info, Shortcut users-get-current). Apps with none (ClickUp) are asked to resolve "me"
CallThe best tools, at most 6 calls: your id as assignee, then me
KeepThe first read returning a list with a title and a status for at least one task (a done flag like completed: true counts). A plain list beats one narrowed to a slice, such as by date

Then the tool is read like Jira, free, with your id as a placeholder; Done, Closed and Resolved are left out.

  • An app that reads fine but has nothing yours yet (new account): no read is kept; retried next day.
  • Sync, connecting or disconnecting an app: learns again at once.
  • A kept tool renamed or removed by the app: read removed, learned again in the same sync.
  • A gateway tool that read fine in the last 3 minutes is not asked again until Sync; one awaiting sign-in is always asked.

Teach Slate#

Connecting an app in Connect → Integrations with no reader starts one automatic lesson, nothing to press. Its tile says Learning how to read your tasks in GitLab… for about a minute; apps go one at a time. Claude (Sonnet) is asked about that app through Slate's connected_tools and read_connected, with no shell or web. Slate tries the answer and keeps it only if it returned a list; afterwards no agent and no tokens. If nothing is found: Couldn't find your tasks in Notion. with Try again, and Slate never retries by itself. A read kept later clears it.

Write-word check. Every tool is checked when picked, when kept and on every read. Refused: any tool with a write word in its name (send, create, update, remove, add, move, post, reply, comment, merge, close, assign, set, mark, upload, write and about fifty more), or belonging to another app. Filter words pass: get_assigned_issues yes, assign_issue no.

Tools only your Claude account reaches (a claude.ai connector such as monday.com): read by Claude (Haiku) on opening Tasks when the last read is over 30 minutes old, or Sync (at most every 2 minutes). Never a tool Slate reads itself; no background timer.

What is stored#

  • Per task: one line with tool, key (acme/api#412), title, state, person, link, a few counts, the tracker's type (Bug, Story), reminder time. Never description, comment or message text. A line you wrote is the same row with no tool. In the workspace's local file, never shared, even in a shared workspace.
  • Meetings: never on disk; in memory until the day ends or Slate quits.
  • Per project: only the skills you picked (a name per kind), in the file of the workspace holding the project's doc. Skill text never copied.
  • Per learned tool: name, arguments, your id in that app, where each field sits in the answer; never the answer. For an app Teach Slate found nothing in: when.
  • Receipts: see Receipts.

Private files on this machine, readable only by your user:

FileHolds
work-gateway-auth.jsonSlate's own sign-in for a web-address gateway or an app connected from Slate; sent only to the server that issued it
work-token-auth.jsonA pasted token with the account name; never logged, sent only to its server; Disconnect removes it
oauth-pending.jsonAn unfinished sign-in, kept 15 minutes so a restart mid-browser-step loses nothing

A connected app's address is in the workspace's file; not secret, never shared. Sign-in returns to one fixed address; if another program holds it, to the app's own port.
