Features

Agents

Most of Slate is something you drive. An agent is the part that works for you: a standup at 7:00, a review of whatever you paste in, a debrief when a coding session ends, a plan for each ticket assigned to you. Every agent lives in Agents, and so does everything it writes.

What an agent is

An agent is a job, a trigger and a list of steps, held to rules for what it may do. You make one in Agents with New agent: start from a template, describe what you want and let an AI tool write it, or fill it in yourself. Generate an agent, beside it, goes straight to describing it.

Its job

The Job box is what the agent is for, in your own words: "Every weekday morning, tell me where each project stands and what to focus on." Every step reads it first. An agent with no job runs its steps exactly as written.

What starts it

StartsWhen it runs
By handOnly when you press Run now. You can type something for it to start with.
On a scheduleHow often is every day, every weekday, every week or every month, at the time you set: an hour, and a minute in quarter hours (:00, :15, :30, :45). A weekday is Monday to Friday: a run that would fall on Saturday or Sunday moves to Monday, at the same time. A monthly run takes a day from 1 to 28. The list shows it as "Weekdays · 7:30 AM". An agent you ask Home for "every weekday" gets the same schedule.
When a session endsAfter Slate captures an AI coding session. It follows the Notice a session ending switch in Automations: with that off, these agents do not start. A session that ends while it is off does not start them later.
When a task arrivesWhen Tasks pulls in a new item from an integration, such as a ticket assigned to you. One read of Tasks hands the run up to 5 new items. If the agent is already running, items that arrive wait and start one run after it, with all of them together. A tracker you just connected is not "arriving": its first read brings in everything at once, and starts nothing. Your own to-dos never start one. Tasks reads your integrations when you open it, and when you come back to the window after more than a minute.

An agent that starts on its own only does so while Runs on its own is switched on. The switch sits under Starts in the editor, beside the schedule. Under the schedule, a line says when it runs next ("Next: Mon 7:30 AM") before you save, or "Off, so it will not run on its own." while the switch is off. Any agent can be run by hand at any time, switched on or not.

If the computer was asleep when a scheduled run was due, the run starts once when it wakes. For an agent whose report is only useful on time, such as a morning brief, switch on Skip a run that is more than two hours late: a run that late is dropped, and the agent waits for its next time; Agents shows it as "· skips late runs" beside the schedule. Only one agent runs at a time, and an agent that is still running is never started a second time. If Slate stops while an agent runs, from a crash or a restart, the run is marked failed with a line saying so, and a scheduled one runs again a few minutes after Slate is back.

An agent belongs to the workspace you made it in, and runs while Slate is open on that workspace. It needs a project to run in. A new agent opens in the project the Agents screen is narrowed to, and cannot be saved without one; Save says why. The six agents Slate seeds have no project yet. On such an agent, Run now and Turn on ask which project to run in. They save your choice, and then run it or switch it on. Turn off never asks. A scheduled run never starts for an agent with no project. An agent whose project was removed can still be edited and switched off, but not switched on until a project is chosen. Agents made from Home use the same project. Moving a group or project to another workspace takes its agents with it.

Its steps

Steps run in order, and each one reads what came before:

  • @context is what the run started with — the text you typed at Run now, "A coding session just ended.", or today's date for a scheduled run. After Recent work, it is that step's report.
  • @prev is the previous step's answer.

A step can name its own AI tool, so one step can run on Claude and the next on Gemini. A step that names none uses the agent's tool, and the group or project supplies the account.

Every run writes one report. It leads with the last step's answer; the earlier steps follow under their own labels, so nothing is lost.

The thread

An agent's page opens on its Thread: every run, oldest first, like a conversation. Words you typed sit above the answer they started. Under each run, a line says what it used ("Used jira ×2, github · 1 call waiting for you").

The box under the thread answers the last run. Type a reply and press Send: the agent runs again, on the same AI tool in the same folder, reads the last four turns of the thread and your words, and answers. Each earlier report is cut to its first 3,000 characters. It is one short run, not the agent's steps. The box is off while the agent is running, and while it cannot run, for example with no project. Before its first run, the box is what the first run starts with, and the button says Start. Run now, at the top, runs its steps with nothing typed.

A report longer than 1,600 characters shows its opening in the thread; Read the whole report opens it.

What it may do

An agent can use the tools its AI tool can reach: your MCP servers for Jira, GitHub, Slack and the rest. What it may do with them is set in Setup, under May do:

  • Reading goes on without asking. Searching, listing, opening a ticket or a pull request.
  • A call that changes something asks you first. Posting a message, commenting on a ticket, creating an issue.
  • Merging, removing things and writing files are refused.

Three lists change that for one agent, the same three an AI run has: Allow, Ask first and Deny. One call per line, as the AI tool names it; a trailing * covers a whole server (mcp__jira__*).

Slate's rules hook holds these rules, the same hook that holds an AI run's. They apply when the agent's AI tool is connected in Connect with Slate's hooks on. An AI tool without Slate's hooks is not held to them, and Setup says so.

When it asks first

When a run tries a call that asks first, the call is held and the run carries on with the rest of its job, saying what it wanted to do. When the run ends, the held call waits as an Ask first card ("Standup's rules held a call: …"), in the thread under that run, and on Home between a waiting session and a task.

Yes, do it starts one short run that may make exactly that call, and the card then says how it went: "Done: Posted to #acme-dev." or "Not made: …". No closes it. Each call is answered once; Later, on Home, sets the card aside.

What it knows

What it knows lists the memories the agent wrote, and shows a preview of the memories it is given before a run, each with a pin and a keep-out. It also says what each run reads: its job, the sessions and memories of the project or group it works in, its own last three reports, and your replies when it answers one. A memory it wrote that was later replaced or retired stays listed, crossed out.

Recent work

The first step can be Recent work. It is what makes a standup a standup: before it writes anything, Slate gathers what happened and checks it against your live tools. Only the first step can be one, because every later step reads its report.

Context Recent work sees

SourceWhat it brings in
SessionsUp to 80 of the newest captured AI sessions in the look-back window, each tagged with its group or project. Each shows its summary on one line, cut at 280 characters
MemoriesUp to 30 memories, picked by pin, recent use and kind, not by date. Each has its kind (decision / preference / state / fact / lesson), its ref and its reasoning. The list stops at about 5,600 characters. A memory whose cited code changed is left out. An agent scoped to a group or project reads that page's own memory, and a group's includes its projects', plus global.
PagesThe titles of up to 100 pages, newest change first, in the agent's group or project
Prior runsThis agent's own three most recent reports, so it can build on what it already said. Each shows the opening 600 characters

Look back sets how many days of sessions it reads, from 1 to 365. It starts at 7. Write decisions back to memory lets Recent work end its report with an atoms block that Slate saves as memory, at most five per run, and removes from the report you read. With the same switch, a memory-proposals block proposes merges and retirements of the memories it was shown, by ref. Each proposal waits in Memory under Needs review and changes nothing until you accept it. Only an agent scoped to a group or project can file one.

Recent work can also search the workspace and your connected tools, so its prompt can tell it to look for the real decisions behind a session summary. What it may change is set by the agent's rules: see What it may do.

Grounding on your live tools

Everything above is Slate's own record — what was true when it was written. A ticket that has since moved is invisible to it. So before Recent work writes, it checks the world.

Each captured session records the directory it ran in and the CLI config it ran under. Slate derives the distinct working contexts from the period's sessions. It leaves out folders under /tmp and similar. It ranks the rest (real git checkouts first, then by how much work happened in them) and takes the top three. The others are named in the run as skipped. For each one it runs one short pass, one after the other, with the AI tool started in that directory under that config, which is what makes your project-scoped MCP servers (Jira, GitHub, Slack) load. Each pass works through four steps in order:

  1. Jira or Linear: the issues assigned to you and not Done. This list decides what counts as your work, so a ticket that left your plate drops out of the report.
  2. GitHub: your pull requests for those tickets, with state, CI result and who the review waits on.
  3. Calendar: today's meetings. This step is skipped when Slate has already read your calendar.
  4. Slack: who is waiting on what, for those tickets and pull requests, in the last three days.

A pass asks only for identifiers and states, and for names and times. Ticket bodies, comments and message text are never requested or stored.

A report from a Recent work step opens with three columns: Assigned to me, Pull requests and Today's meetings. A column whose source needs signing in says so and has a sign-in button. It signs in against the same account and directory the pass used, and runs the agent again. A column whose source could not be reached says that, and never says "Nothing assigned" for a tracker it could not open.

The report text then carries two lists: what was verified this run, and which sources could not be reached. A source counts as unreachable when the AI tool said so. It also counts when the AI tool's own CLI reported the server as failed, pending, unknown or needing sign-in, even if the AI tool left it out. When no project had sessions in the look-back window, nothing is checked at all, and the report opens by saying so. Recent work may state a ticket or PR status as current only if a tool returned it this run. The seeded Standup and Shutdown both end with a Not verified section; if Recent work reached everything, it says so outright. A template you start from the gallery does not add that section unless you write it into the prompt.

Prompt template variables

Recent work's prompt can use these, filled in just before it runs:

VariableExpands to
@sessionsRecent captured sessions
@factsThe memories the run is given, as in the table above: up to 30, each with its kind, ref and reason. Never a held memory or a stale state. When Slate's server is not running, the line says the run has no memory.
@pagesThe page titles above
@dateToday's date
@prior_outputsThis agent's recent reports

Only Recent work can read them. The editor tells you if a later step uses one, and points you at @context instead.

Where an agent works

An agent runs in its group's or project's directory — the checkout Slate is watching for it, or the folder if there is no checkout. That is what makes your project-scoped MCP servers load for every step. An agent with no group or project does not run by itself: nothing supplies the account it would run under, and Agents says so above Run now. Pressing Run now asks you to choose a project first.

The directory is resolved once for the whole run, so editing a group or project mid-run cannot split one agent across two of them.

A background run costs the same model calls as running the prompts yourself. Nobody is watching it, so three limits apply. A whole run, with all its steps, shares one spend ceiling of $5. Each turn gets what is left, and the next turn does not start once nothing is left. A tool that does not report its spend cannot be added up, so a run of that tool is limited to 12 turns. Claude Code is also limited to 30 agent turns inside each turn; other tools have no such flag. A step gives up after four minutes of silence: every word, tool call or result the AI tool sends restarts that clock, so a step that is still working is not cut off.

The ceremonies

Slate seeds six agents that mirror the operating rhythm of an engineering org, each a single Recent work step, organized by project. All six arrive switched off and with no project. Press Run now or Turn on, and Slate asks which project to run in, saves it and goes on. After that, switch one on to run it on its schedule.

AgentStartsLooks backWhat it produces
Standupdaily, 07:003 daysWhere each project stands and today's focus
Shutdowndaily, 18:001 dayWhat moved today, loose ends, and tomorrow's first move
Planningweekly, Monday 08:007 daysWhat to commit to for the week ahead, per project
Weekly reviewweekly, Friday 17:007 daysWhat shipped, what's in flight, what's blocked
Retroweekly, Friday 17:007 daysWhat went well, what dragged, one concrete change
Monthly reviewmonthly, day 1, 09:0030 daysTrajectory, the decisions that mattered, one thing to change

Standup, Shutdown, Weekly review and Retro also write decisions back to memory, up to five a run. Planning and Monthly review do not. None of the six skips a late run.

Each is an ordinary agent: change its time, scope it to one project, or add a step after Recent work — "turn this into three Slack-ready bullets".

The memory pass

One more template keeps memory itself small and true. Memory pass runs daily at 08:30 and reads yesterday's sessions and the group's or project's memories. It adds at most five new ones (a correction you made, an approach you confirmed, a decision and why) and proposes merges and retirements for review. It is a template, not a seeded agent: nothing runs until you save it, scoped to a group or project, and switch it on. It runs on its AI tool, under the account you already gave that tool.

The Memory care agent

Turning on AI memory care in Connect → Automations adds one more agent, Memory care, to Agents. It runs daily at 03:00 and skips a night it missed. It has one step, which reads the night's memories twice. Its switch, cost and monthly token cap are in Automations. It follows Scheduled agents too: with that off, it does not run.

The Agents place

Agents opens on its Overview: the latest report from each agent, and every report before it. Latest shows the newest report from each agent plus a live card for any run in progress. History below holds every report, grouped by agent, newest first. Its find box narrows it by agent name, a word in the title or opening lines of a report, or a date ("Oct 8" or "2026-10-08"). Every word you type must match. A renamed agent keeps its whole history under its current name. A report opens only when you pick one. If the reports cannot be read, the Overview says so with Try again; it says No reports yet only when there truly are none.

Below Overview in Agents' list are your agents, grouped by what starts them: Running, On a schedule, When a session ends, When a task arrives and By hand. Pick one to open it on three tabs: Thread, Setup (its job, what starts it, where it works, what it may do and its steps) and What it knows. Run now, Edit and the on/off switch sit above them. Edit opens the same agent in the editor, and Overview brings the first screen back.

A report goes for good rather than to Trash — Delete forever… asks once ("Delete forever?"), and the agent can always run again. Deleting an agent forever keeps its reports.

⌘K searches reports too. They have an index of their own over title and body, listed under Reports, separately from your pages, because a report opens in Agents. At most four show. Artifacts follow under Artifacts the same way.

The report finds you

When a run finishes, a native OS notification carries the report's opening line, cut at 180 characters. Slate also shows a Report ready toast with the report's title. A failed run shows an Agent failed toast, and the error stays under Last run on the agent. When your AI tool's own sign-in lapses, you get one notification, on the first run that fails that way. Wherever you open a report from, it opens in Agents, beside the runs that came before it.
