Loop & Routines

Most of Slate is something you drive. A routine is the part that runs for you: a standup at 7:00, a review of whatever you paste in, a debrief when a coding session ends. Every routine lives in Loop, and so does every report it writes.

What a routine is

A routine is a trigger and a list of steps. You make one in Loop with New routine: start from a template, describe what you want and let a brain write it, or fill it in yourself. Generate a routine, beside it, goes straight to describing it.

What starts it

StartsWhen it runs
By handOnly when you press Run now. You can type something for it to start with.
On a scheduleDaily, weekly or monthly, at the time you set.
When a session endsAfter Slate captures an AI coding session.

A routine that starts on its own only does so while Runs on its own is switched on. Any routine can be run by hand at any time, switched on or not.

A routine belongs to the workspace you made it in, and runs while you are in that workspace. Moving a project to another workspace takes its routines with it.

Its steps

Steps run in order, and each one reads what came before:

  • @context is what the run started with — the text you typed at Run now, "A coding session just ended.", or today's date for a scheduled run. After a brief, it is the brief's report.
  • @prev is the previous step's answer.

A step can name its own AI tool, so one step can run on Claude and the next on Gemini. A step that names none uses the routine's tool, and the project supplies the account.

Every run writes one report. It leads with the last step's answer; the earlier steps follow under their own labels, so nothing is lost.

The brief

The first step can be a brief of recent work. A brief is what makes a standup a standup: before it writes anything, Slate gathers what happened and checks it against your live tools. Only the first step can be one, because every later step reads its report.

Context a brief sees

SourceWhat it brings in
SessionsRecently captured AI sessions, each with its full one-line summary, tagged with its top-level project
FactsActive facts, tagged by kind (decision / preference / state / fact) with the reasoning attached
PagesRelevant workspace pages
Prior runsThis routine's own three most recent reports, so it can build on what it already said

Look back sets how many days of sessions it reads. Write decisions back to memory lets the brief end its report with an atoms block that Slate saves as memory, and removes from the report you read.

A brief also runs with the same read-only workspace tools as the Console, so its prompt can tell it to search for the real decisions behind a session summary.

Grounding on your live tools

Everything above is Slate's own record — what was true when it was written. A ticket that has since moved is invisible to it. So before a brief writes, it checks the world.

Each captured session records the directory it ran in and the CLI config it ran under. Slate derives the distinct working contexts from the period's sessions, ranks them (real git checkouts first, then by how much work happened in them), and takes the top three. For each it runs one short pass with the brain started in that directory under that config, which is what makes your project-scoped MCP servers (Jira, GitHub, Slack) load. Each pass asks only for identifiers and states: ticket keys and statuses, PR numbers and states. Ticket bodies, comments and message contents are never requested or stored.

A source that failed because it needs signing in gets a Log in button on the running card, which signs in against the same account and directory the pass used and runs the routine again.

The report then carries two lists: what was verified this run, and which sources could not be reached. A brief may state a ticket or PR status as current only if a tool returned it this run. The Standup and the Shutdown both end with a Not verified section; if a brief reached everything, it says so outright.

Prompt template variables

A brief's prompt can use these, filled in just before it runs:

VariableExpands to
@sessionsRecent captured sessions
@factsActive facts
@pagesRelevant pages
@dateToday's date
@prior_outputsThis routine's recent reports

Only a brief can read them. The editor tells you if a later step uses one, and points you at @context instead.

Where a routine runs

A routine runs in its project's directory — the checkout Slate is watching for it, or the project folder if there is no checkout. That is what makes your project-scoped MCP servers load for every step. A routine with no project does not run: nothing supplies the account it would run under, and Loop says so above Run now.

The directory is resolved once for the whole run, so editing a project mid-run cannot split one routine across two places.

A background run costs the same model calls as running the prompts yourself. Nobody is watching it, so a brief stops after six tool turns, every step gives up after four minutes without an answer, and each run carries a spend ceiling.

The ceremonies

Slate seeds six routines that mirror the operating rhythm of an engineering org, each a single brief organized by project. All six arrive switched off: run one from the Console card when you want it, and switch it on in Loop.

RoutineStartsWhat it produces
Standupdaily, 07:00Where each project stands and today's focus
Shutdowndaily, 18:00What moved today, loose ends, and tomorrow's first move
Planningweekly, MonWhat to commit to for the week ahead, per project
Reviewweekly, FriWhat shipped, what's in flight, what's blocked
Retroweekly, FriWhat went well, what dragged, one concrete change
Monthly ReviewmonthlyTrajectory, the decisions that mattered, one thing to change

Each is an ordinary routine: change its time, scope it to one project, or add a step after the brief — "turn this into three Slack-ready bullets".

Loop

Loop opens on its Overview, an operating picture. Latest shows the newest report from each routine plus a live card for any run in progress. History below holds every report, grouped by routine, newest first. A renamed routine keeps its whole history under its current name. A report opens only when you pick one.

Below Overview in Loop's list are your routines, grouped by what starts them: Running, On a schedule, When a session ends and By hand. Pick one to see what starts it, when it runs next, its steps and every report it wrote, with Run now and a box for what to start it with. Edit opens the same routine in the editor, and Overview brings the first screen back.

A report is deleted rather than trashed — the delete button asks once, and the routine can always run again. Deleting a routine keeps its reports.

⌘K searches reports too. They have an index of their own over title and body, listed under REPORTS, separately from your pages, because a report opens in Loop.

The report finds you

When a run finishes, a native OS notification carries the report's opening line. On the Console home a Today card shows your latest ceremony — the Standup in the morning, the Shutdown from 17:00 — with a button to run a fresh one when the last is not from today. Wherever you open a report from, it opens in Loop, beside the runs that came before it.
