Licensing & Updates

Slate is moving from a personal tool to a commercial product. This page describes how licensing and updates are planned to work.

Most of what follows is roadmap, not shipped. Licensing and code signing land in the commercialization phase (phase B); auto-update and distribution follow. Treat the numbers and mechanisms here as the current plan, and see docs/internals/prd.md for the authoritative, section-numbered spec.

How the license check is planned to work

The design goal is a check that's thin and offline-capable — it should not phone home on every launch, and it should keep working on a plane.

The planned flow:

  1. You buy through a merchant of record (LemonSqueezy or Paddle) and receive a license key.
  2. On first activation, Slate exchanges the key for a signed receipt and stores that receipt in the OS keychain.
  3. From then on, Slate verifies the receipt locally. After the first activation it works offline — no repeated network check.

Trial state is tracked with a trial_start_at value in the setting table. When the 30 days elapse without a key, Slate is planned to go read-only until a valid key is entered — your data stays fully intact and readable, you just can't write until you activate.

The one-time activation check is one of the three cases where Slate contacts the network at all. See Privacy & Security for the full list.

Auto-updates

Updates run through Tauri's updater, wired to GitHub Releases. This part is shipped, not roadmap.

Slate checks for a newer version shortly after it opens, and again every few hours while it stays open. When it finds one it downloads it in the background and tells you it's ready — nothing is installed at that moment.

The new version is put in place when you next quit Slate, which costs you nothing: the app is closing anyway. If you'd rather have it now, the notice has a Restart now button. Because Slate hosts running CLI sessions, that button tells you how many are open before you press it — quitting normally ends them too, so the only difference is when.

Nothing restarts on its own, and nothing is installed while you're working.

The About pane in Settings shows your version, whether an update is waiting, and a Check now button if you don't want to wait for the next automatic check.

If Slate won't start

If three launches in a row fail to get as far as a working window, the next one starts in safe mode: the file watcher, background agents and the login item are all skipped, and you get a single screen that looks for an update and installs it. Your workspace file is never touched by any of this.

If you'd rather try a normal start, safe mode has a button for that too.
