The tools every AI tool gains

Slate runs an MCP server on your machine. Connect Claude Code, Codex, Cursor, Gemini or OpenCode to it — from setup, or Connect → AI tools — and each of them gains these 24 tools against the same workspace. Not a copy each. The same one.

24 tools · five AI tools · one workspace

Memory

The two every tool is told to call — recall at the start of a task, remember at the end — and the handful that read, correct and tidy what they saved.

recall

The one search. On a feature branch it opens with the branch brief, then memories and pages ranked by keyword match, each memory one line with the ref to cite it by. Marks a memory whose cited code has since changed or gone.

remember

Save one typed memory — decision, preference, state, fact or lesson — scoped to the project and deduped against what is known. A near-duplicate strengthens; an update supersedes. Keys and tokens are replaced with [secret].

get_memory

Read memories in full by ref: the claim, its reason, its citation and whether the cited file changed, who confirmed it, and what it replaced.

list_memories

For a tidy you agreed to: the project's memories, oldest first, a hundred at a time.

propose_memory_change

Propose a merge, a retirement, a lesson or a skill. Nothing changes until you accept it in Slate, under Memory → Needs review.

record_decision

Record a decision with its reasoning, alternatives and confidence. Writes both a memory and a decision page; recall returns decisions first when a question asks why.

log_mission_progress

Append a session summary — decisions, open items — to the branch's Plan page, or the branch page when there is no plan.

Pages

A tool can save a typed document and add to a page. Renaming, moving and trashing are done in the app, where there is an undo.

create_document

Create a typed document — plan, design, review, bug report — filled from a template when no Markdown is given. Only after you said yes.

get_page

Read one page by id or by target: title, icon, breadcrumb path and body as Markdown.

append_to_page

Add Markdown to the end of a page, and say back which page it landed on.

Artifacts & apps

Things a tool makes for you to look at, or to use. Both land in your workspace with every version kept.

publish_artifact

Publish an HTML or Markdown page to Slate's Artifacts tab — whole, from a file, or as edits to the newest version. A live artifact can read its project and still reach no network.

get_artifact

Read an artifact before changing it, or list every artifact.

publish_app

Build and publish an app — a folder of React files Slate builds and runs in Apps. A build error comes back with file and line; a render failure comes back with what broke.

get_app

Read an app before changing it, with the playbook, the SDK it may import and example apps to build from.

Tasks & activity

What you owe and what you have been doing, across every tool — assembled from what Slate captured, not from anything you had to log.

my_work

Your Tasks list: to-dos overdue or due today, and the open items your tools gave you, each with the key you know it by.

update_my_work

Add a to-do, tick one off, rename it, or set a reminder that rings when it comes due.

activity

Recent sessions across every tool and project, or the branches you left carrying uncommitted changes and never came back to.

Other agents

When two sessions work in the same project, each one knows about the other.

live_sessions

Every AI session running on this computer right now — tool, status, project, branch, what it was asked and the last thing it said.

handoff

Leave a note for the other agents in this project, or for one of them. Each sees it once, at the start of its next turn.

Workspaces

The only tools here that read anything other than your own machine. They need a sign-in, they are read-only, and signed out they say so rather than return an empty result that would read as “nobody shared anything”.

recall_workspaces

Search what other people published, across every workspace you belong to — their memories and their pages.

workspace_page

Read one shared page in full. Read-only — a page belongs to whoever wrote it.

AI runs & contract

The first two only answer inside a session a Slate AI run started; anywhere else they say so.

get_task

The AI run's current step, its attempt and the step's instructions — or why it is blocked.

report_task_step

Report that step as done, blocked, needing input or failed, with a short summary.

slate_capabilities

Handshake the contract: version, supported tools, access levels, approval policies and schema hash.

Worth knowing

A tool works in the workspace that owns its folder. Almost every tool takes an optional cwd. Slate resolves it to the workspace that owns that folder, so a session in a shared checkout reads and writes that workspace; leave it out and you get Personal.
Pages don't need an id. get_page and append_to_page take a target instead — a kind, a cwd, a branch, a doc type — and Slate writes only when it resolves to exactly one page. An ambiguous target is refused.
This is not Slate's only tool list. These are the tools your own AI tools reach, over MCP. Home and your agents call a second, in-process surface directly, with finer tools of their own. The two differ on purpose — slate_capabilities means nothing in-process, and renaming, moving and trashing pages are gestures you make in the app.

Every argument and default is in the full tool reference, generated from Slate's own docs on every release.
