Overview

Core Concepts

Slate has a small number of ideas that everything else is built from. Understand these six and the rest of the product follows.

1. Everything is a page

The page is Slate's universal unit. A project, a repo, a design doc, a mission, a captured AI session — all of them are rows in one page table, distinguished by an optional doc_type. Pages nest into a tree (each page has a parent_id), order by a fractional position so drag-reorder never renumbers the whole tree, and carry their content as block-editor JSON.

This uniformity is why the same handful of tools — create, read, update, move, archive — work everywhere, whether you're editing by hand or an AI is writing on your behalf.

2. Typed documents give work structure

A page can be typed: project, repo, branch, plan, design, review, meeting, test-plan, bug-report, mission, or plain general. The type pre-fills a template and constrains where the page can live — a branch sits under a repo sits under a project, and knowledge pages (plans, designs, reviews…) hang off any of them. This hierarchy is what lets memory tools resolve "the plan for the branch I'm on" without you naming an id.

3. Memory is a shared MCP layer

Slate's second identity is a memory server. It speaks MCP, so any AI tool — Claude Code, Cursor, Codex, Gemini, or Slate's own Console — can call the same two verbs:

  • recall at the start of a task to load the relevant context (the brief for your current branch, repo conventions, project facts).
  • remember at the end to save what happened — a decision, a result, a learned preference — routed automatically to the right page.

A filesystem watcher captures the sessions themselves, so the memory grows even when a tool forgets to write to it. The result: what one tool learns, every tool can see.

4. Brains drive your CLIs

Slate doesn't ship its own model or ask for an API key. A brain is a thin driver over a CLI you already have installed and logged into — the Claude Code, Gemini, OpenCode, Cursor or Codex CLI. Slate proxies calls through its Rust layer, so your credentials stay in those tools and never touch the app's renderer.

The agent is designed to run well even on a light model by pushing intelligence into code: it resolves the right tool and prefills its arguments, leaving the model to fill only the gaps via structured output.

5. Studio is one playbook for every tool

Studio is where you write your instructions and skills once — in STUDIO.md and .studio/ — and project them out to every AI tool's native config format: Claude Code, Cursor, Codex, Gemini and OpenCode. Change the playbook in one place, run yarn studio sync, and every tool picks up the change.

6. A workspace is shared or private as a whole

Workspaces are optional and inert until you sign in. When you do use them, the unit of sharing is not a page and not a rule — it is the container: this workspace is a team's, so everything in it is the team's.

Your Personal workspace is the store that never syncs. Each shared workspace is its own file, on the same schema, and you switch into one from the top bar the way you switch branches. Nothing is marked, so there is no predicate to get wrong; work you do not want shared goes in Personal, which is a different file rather than a different rule.

Sharing is one-way. Each page has exactly one writer — its author — which is what removes merge conflicts, version columns, and "whose edit wins" from the design entirely. A teammate's page opens read-only, in the real editor, with a line saying why.

How it fits together

                    ┌──────────────────────────────┐
   You ───────────► │  Personal — one SQLite file  │   never leaves this machine
   (block editor)   │        on-device, private     │
                    └──────────────┬───────────────┘
                                   │
                    ┌──────────────┴───────────────┐   ─ ─ push what I wrote ─ ─▶  team
                    │ Nimbus — its own SQLite file │   ◀─ ─ pull what they did ─ ─ workspace
                    │  same schema, same app shell │        (Postgres + RLS)
                    └──────────────┬───────────────┘
                                   │  MCP (recall / remember / pages)
        ┌──────────────┬───────────┼───────────┬──────────────┐
        ▼              ▼           ▼            ▼              ▼
    Slate Console   Claude Code  Cursor      Codex         Gemini
    (built-in)      └──────────── your AI tools, one shared memory ┘
                                   ▲
                              Studio syncs one
                            playbook to all of them

Everything above the files is stateless and swappable; the workspaces are the durable things you keep. Only the second box has a dashed line, and only you decide whether there is a second box at all.
