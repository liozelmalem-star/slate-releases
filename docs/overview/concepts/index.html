Overview

Core Concepts

Slate has six ideas. The rest of the product is built from them.

1. Everything is a doc

The doc is Slate's universal unit. A group, a project, a design doc and a captured AI session are all rows in one page table, told apart by an optional doc_type. Docs nest in a tree (parent_id), order by a fractional position so drag-reorder never renumbers the tree, and hold their content as block-editor JSON.

So the same few tools (create, read, update, move, Trash) work everywhere, whether you edit by hand or an AI writes for you.

2. Typed documents give work structure

A doc can be typed: group, project, branch, plan, design, review, meeting, test-plan, bug-report, mission or plain general. The type pre-fills a template and limits where the doc can live. A branch sits under a project. A project sits under a group or stands alone. Knowledge docs (plans, designs, reviews) hang off any of them. This lets memory tools resolve "the plan for the branch I'm on" without an id.

3. Memory is a shared MCP layer

Slate is also a memory server. It speaks MCP, so any agent (any of the 16 agents, or Slate's own Home) calls the same two verbs:

  • recall at the start of a task loads the relevant context: the brief for your branch, project conventions, project memories.
  • remember at the end saves a decision, result or preference, filed on the doc the hierarchy resolves to.

A filesystem watcher captures the sessions themselves, so memory grows even when a tool forgets to write. What one tool learns, every tool sees.

4. Agents drive your CLIs

Slate ships no model and asks for no API key. An agent is a thin driver over a CLI you already installed and signed in to: Claude Code, Codex, Cursor, GitHub Copilot, Antigravity, OpenCode, Gemini, Cline, Grok Build, Kiro, Qwen Code, Droid, Hermes Agent, Goose, Kilo Code or Auggie. Slate launches it from its Rust layer, so credentials stay in those tools and never reach the app's renderer.

The agent runs well on a light model because it pushes intelligence into code: code resolves the right tool and prefills its arguments, and the model fills only the gaps via structured output.

5. Toolkit is one playbook for every tool

Toolkit is where you write instructions and skills once, in AGENTS.md and .slate/, and project them into every agent's native config. Features by Agent says which tools it reaches today. Change the playbook, run yarn studio sync, and every tool picks it up.

6. A workspace is shared or private as a whole

Workspaces share by container. A team's workspace is the team's, and everything in it is shared.

Your Personal workspace starts unshared and syncs only if you switch its sharing on. Each shared workspace is its own SQLite file on the same schema, and you switch into one from the top of the rail. Nothing is marked doc by doc, so no rule can be wrong. Work you do not want shared stays in a workspace you have not shared, which is a different file.

Sharing is one-way, and each doc has one writer, its author. That keeps merge conflicts, version columns and "whose edit wins" out of the design. A teammate's doc opens read-only, in the real editor, with a line saying why.

Slate is in alpha. Your data stays on your machine.
