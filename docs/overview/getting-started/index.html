Overview

Getting Started

This page takes you from a fresh install to a working workspace with cross-tool memory and a running agent.

System requirements

What you can install today is macOS on Apple Silicon, and only that — the latest release ships one bundle, Slate_<version>_aarch64.dmg. There is no Intel Mac build, no Windows build and no Linux build; the codebase targets all three and none of the others has ever been produced. See Platform & Availability before planning around one.

To use the AI Console or connect Slate as a memory layer, you need at least one brain installed — the Claude Code, Gemini, OpenCode, Cursor or Codex CLI. Slate drives the CLI you already authenticated, so there's no API key to enter.

1. Install

Get the desktop app and open it. On first launch Slate creates your workspace database at a per-user location:

PlatformWorkspace database
macOS~/Library/Application Support/app.slate.workspace/workspace.db
Linux$XDG_DATA_HOME/app.slate.workspace/ — the path the code resolves; no Linux build ships
Windows%APPDATA%\app.slate.workspace\ — the path the code resolves; no Windows build ships

Everything you do lives in that one SQLite file. You can copy it, back it up, or open it in any SQLite browser — see Your Data & Export.

Capture starts before setup does. Slate looks for the AI CLIs already on your machine and begins reading their session transcripts the moment the window opens — the first setup screen names what it found. Nothing on your machine is changed to do that, and nothing is sent anywhere; reading files you already have needs no permission from another program.

Then a four-step setup runs — Welcome, Brain, Tools, Project. Every step is skippable, so nothing here blocks you from getting in, and everything it sets up is reachable later from the rail. Two of the four are worth not skipping:

  • Tools registers Slate with your AI tools, which is what makes memory shared rather than a notes app. It is also the one time you are asked before Slate writes to another program's config.
  • Project points Slate at a folder. Until one exists, captured sessions have nowhere to file and land under Private whatever repo they came from. The Console says so when it happens, with the folder picker one click away.

Sharing is no longer part of setup — everything above works with no account. When you want it, it is in Settings → Workspaces.

2. Create your first pages

The left column is a permanent icon rail — Sessions, Console, Projects, Memory, Activity, Agents, Workflows, Loop, Studio, Trash, Settings — beside a pane that switches with it. Click Projects, which is where you land, for the nested page tree — every root of that tree is a project. Create a page, give it an icon and title, and start typing — the editor is block-based (headings, lists, to-dos, code, quotes) with a slash menu and drag-to-reorder.

For real work, reach for a typed document: a project to group things, a plan or design doc, or a mission to track a piece of work with its own session log. Typed docs pre-fill a sensible template so you're not starting from a blank page.

Press <kbd>⌘K</kbd> any time to open the command palette — jump to a page, run an action, or full-text search across every title and body.

3. Connect a tool to your workspace

Open Connect → AI tools and turn on the tools this workspace works with, choosing the account each one uses. Every project inherits what you set, and may override it. See brains:

  • Claude — drives your installed Claude Code CLI (claude-sonnet-4-6 by default).
  • Gemini — drives your installed Gemini CLI (gemini-2.5-flash by default). Needs an API key or a Code Assist licence: Google stopped serving the CLI to consumer accounts on 2026-06-18. See Brains.
  • OpenCode — drives your installed OpenCode CLI; the model list comes from whichever providers you have logged into.
  • Cursor — drives your installed cursor-agent CLI (auto by default, and the model list comes from your Cursor account).
  • Codex — drives your installed Codex CLI (gpt-5.3-codex by default).

Because Slate uses the CLI you already logged into, there's nothing to paste. If you keep separate work and personal CLI configs, set up a CLI config profile for each.

4. Run your first request

Open the Console — Slate's in-app AI agent. It can read and write your workspace and call any connected tool. Try:

  • "Create a plan page under my Slate project for the onboarding flow."
  • "What did I work on this week?"
  • "Summarize the open decisions across my projects."

The agent uses curated commands to resolve the right tool and prefill its arguments, so these work even on a light local model.

5. Connect Slate to your other AI tools

This is where Slate becomes a shared brain. Slate is itself an MCP server, so Claude Code, Cursor, Codex, Gemini and OpenCode can all read and write the same workspace:

  1. Open Connect → AI tools and turn your tool on there, or see Connecting Your AI Tools.
  2. Once connected, those tools can call recall to load context and remember to save decisions — into the same pages you edit by hand.
  3. Turn on the session watcher so Slate captures your Claude / Codex / Gemini / Cursor / OpenCode sessions automatically. On macOS you can run whenever Slate is open.

From here, Studio lets you write one set of instructions and skills and sync them to every tool at once.

6. Optional: share with a workspace

If you work with other people, a shared workspace is a second store that its members read. Sign in from Settings → Account, create or join one in Settings → Workspaces, then switch into it from the top bar — the whole app follows, and everything you do in there belongs to its members.

Every workspace carries the same switch, Personal included — but Personal is where automatic capture puts things you never filed, so turning sharing on there counts what it would publish first. To share one project rather than a whole store, move it: its ⋯ menu offers Move to <workspace>, and the whole subtree goes with its memory. Nobody can edit your pages whatever their role, and the entire layer is inert until you sign in. See Workspaces.
