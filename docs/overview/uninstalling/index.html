Overview

Uninstalling

One command removes Slate and puts back what it changed:

curl -fsSL https://liozelmalem-star.github.io/slate-releases/uninstall.sh | bash

Your workspace is kept. Removing it takes a second, explicit flag.

See it first

--dry-run prints every step, lists the accounts it would clean up, and changes nothing:

curl -fsSL https://liozelmalem-star.github.io/slate-releases/uninstall.sh | bash -s -- --dry-run

Read the line that names your workspace and its size.

What it removes

Slate's entries in your agentsThe plugin trees, the capture hooks and the MCP registrations, in exactly the accounts Slate wrote to
/Applications/Slate.appThe app itself
Logs, cache and webview stateThree rebuildable directories under ~/Library

The first row is what a manual removal misses. Slate installs itself into up to eighteen other products (the 16 agents, Claude Desktop and VS Code), each with its own config format. Drag Slate to the Trash and every entry stays behind, pointing at an app that is gone.

So the app undoes its own work, from a record of the accounts it wrote to. An MCP server you registered yourself is never touched, and neither is a plugin marketplace that only shares a name. This step needs the app, so it runs before the bundle is removed.

What it keeps

Your data folder, ~/Library/Application Support/app.slate.workspace/:

  • workspace.db, your Personal docs and memory
  • one file for each shared workspace
  • machine.db (settings that describe this computer, the telemetry id and your choices about it)
  • your cloud sign-in file
  • the backups

It is plain SQLite. workspace.db opens in any SQLite browser with or without Slate, and reinstalling picks the same file up where you left it.

It also leaves what Toolkit wrote into your own project folders, such as skill folders and instruction files. Those belong to the project.

Removing the workspace too

curl -fsSL https://liozelmalem-star.github.io/slate-releases/uninstall.sh | bash -s -- --delete-workspace

This cannot be undone. It removes the whole data folder above. No other copy of these files exists, locally or in the cloud. A workspace you shared keeps the rows you published, for its members, until you withdraw them (Stop sharing) or remove them for good (Erase my work). Do that first, and export what you want to keep: Settings → Workspaces, then the workspace, then Storage. A Personal workspace you moved to another folder is not in the data folder and stays where you put it.

Options

FlagWhat it does
--dry-runPrint every step and change nothing
--delete-workspaceAlso remove the whole data folder: workspaces, machine.db, sign-in file and backups
--keep-connectionsLeave Slate's entries in your agents alone
--prefix <dir>Look for Slate.app somewhere other than /Applications

The script never asks a question. Piped to bash, it has no input to read an answer from, so the destructive half is a flag you type.

If you already removed the app

The script still cleans the logs, cache and webview state, and reports that it could not remove the agent entries. They are inert, because they point at an app that is gone. To remove them, reinstall Slate and run the uninstaller again.

Doing it by hand

# 1. Quit Slate, so the running copy cannot write back what the next step removes.
osascript -e 'tell application "Slate" to quit'

# 2. The agent entries — this is the step that needs the app.
/Applications/Slate.app/Contents/MacOS/slate --list-connections   # see them
/Applications/Slate.app/Contents/MacOS/slate --disconnect-all     # remove them

# 3. The app, and the three rebuildable directories.
rm -rf /Applications/Slate.app
rm -rf ~/Library/Logs/app.slate.workspace
rm -rf ~/Library/Caches/app.slate.workspace
rm -rf ~/Library/WebKit/app.slate.workspace

# 4. Your workspace — only if you mean it.
rm -rf ~/Library/Application\ Support/app.slate.workspace
