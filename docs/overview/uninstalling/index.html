Overview

Uninstalling

One command removes Slate and puts back what it changed:

curl -fsSL https://liozelmalem-star.github.io/slate-releases/uninstall.sh | bash

Your workspace is kept. Every page, every decision, the whole memory graph — it stays where it is. Deleting it takes a second, explicit flag.

See it first

--dry-run prints every step, lists the accounts it would clean up, and changes nothing:

curl -fsSL https://liozelmalem-star.github.io/slate-releases/uninstall.sh | bash -s -- --dry-run

That is worth doing once before the real run, because the line that matters is the one naming your workspace and its size.

What it removes

Slate's entries in your AI toolsThe plugin trees, the capture hooks and the MCP registrations, in exactly the accounts Slate wrote to
/Applications/Slate.appThe app itself
Logs, cache and webview stateThree rebuildable directories under ~/Library

The first row is the one a manual delete misses, and it is why this script exists. Slate installs itself into as many as seven other products — Claude Code, Codex, Gemini, Cursor, OpenCode, Claude Desktop and VS Code — each with its own config format and its own account layout. Drag Slate to the Trash and every one of those entries stays behind, pointing at an app that is no longer there.

So the app is asked to undo its own work rather than the script guessing at seven file formats. Slate keeps a record of the accounts it wrote to, and that record is what it works from — which means an MCP server you registered yourself is never touched, and neither is a plugin marketplace that merely shares a name.

That step needs the app, so it runs before the bundle is deleted.

What it keeps

Your workspace, at ~/Library/Application Support/app.slate.workspace/. That directory holds workspace.db — your pages and your memory — along with the pre-migration backups.

It is plain SQLite. workspace.db opens in any SQLite browser with or without Slate installed, which is the point: if Slate disappears, your work does not. Reinstalling picks the same file up exactly where you left it.

Deleting the workspace too

curl -fsSL https://liozelmalem-star.github.io/slate-releases/uninstall.sh | bash -s -- --delete-workspace

This cannot be undone. Nothing else on the machine holds a copy, and no cloud has one — a shared workspace syncs pages you published, not this file. Export what you want to keep first: Settings → Workspaces → Manage → Storage.

Options

FlagWhat it does
--dry-runPrint every step and change nothing
--delete-workspaceAlso delete your pages, your memory and the backups
--keep-connectionsLeave Slate's entries in your AI tools alone
--prefix <dir>Look for Slate.app somewhere other than /Applications

The script never asks you anything. Piped to bash it is the standard input, so a prompt would have nothing to read your answer from — the destructive half is a flag you type instead.

If you already deleted the app

The script still cleans up the logs, the cache and the webview state, and it will tell you that the AI-tool entries could not be removed. Those entries are inert — they point at an app that is gone, so nothing runs — but to clean them up properly, reinstall Slate and run the uninstaller again.

Doing it by hand

Nothing here is hidden. If you would rather not run a script:

# 1. Quit Slate, so the running copy cannot write back what the next step removes.
osascript -e 'tell application "Slate" to quit'

# 2. The AI-tool entries — this is the step that needs the app.
/Applications/Slate.app/Contents/MacOS/slate --list-connections   # see them
/Applications/Slate.app/Contents/MacOS/slate --disconnect-all     # remove them

# 3. The app, and the three rebuildable directories.
rm -rf /Applications/Slate.app
rm -rf ~/Library/Logs/app.slate.workspace
rm -rf ~/Library/Caches/app.slate.workspace
rm -rf ~/Library/WebKit/app.slate.workspace

# 4. Your workspace — only if you mean it.
rm -rf ~/Library/Application\ Support/app.slate.workspace
