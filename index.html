Why Slate

Every agent starts from zero.
Today, you are the memory.

It forgot yesterday

Each session starts blank. What Claude Code worked out on Tuesday, Cursor has never heard of on Wednesday — so you explain it again.

Many terminals, one of them waiting

Sessions run in different tools and folders. The one that stopped to ask you a question has been sitting there for twenty minutes.

The busywork never stops

Standups, reviews, the ticket you owe a reply. None of it happens unless you do it, and none of it is the work you sat down to do.

Slate fixes it the way your own memory works: it notices, remembers, recalls and acts — for every agent at once, on your computer, in files you own.

  1. 1

    It notices everything

    Every session from every agent is captured as it happens, from the transcripts the tools already write. Nothing to remember to do, nothing to paste.

  2. 2

    It remembers what lasts

    Decisions with their reasons, preferences, lessons, where each branch stands — each tied to the file it's about, and flagged when that code changes.

  3. 3

    It hands it back on time

    When any tool starts a task, the right memory is already there — whichever tool you open next. Not when you think to ask: when the work needs it.

  4. 4

    It works while you're away

    Automations run your standup, debrief each session and draft the reply you owe — on the agent you already pay for, inside rules you set.

Why "Slate"? A slate is the clapperboard that syncs separate cameras onto one timeline. Your agents are the cameras.

Getting started

Up and running in two minutes.

  1. 1

    Install

    One command downloads Slate, checks it and opens it. About thirty seconds — no Homebrew, no Node, nothing to build.

  2. 2

    Connect your tools

    Sign in once with Google or GitHub. Then a 4-step setup you can skip — Welcome, Agents, Integrations, Project — connects the agents you use and opens on Sessions. Slate asks before it touches any tool's config.

  3. 3

    Keep working

    Use your tools as you always do. Sessions are captured, memory grows, and Home tells you what needs you.

Why Slate is different

Local by design.

  1. Your work is SQLite files on your Mac. One file per workspace. Copy it, back it up, open it in any SQLite browser.
  2. No model, no embeddings. Slate downloads no model and stores no embeddings. Recall is word statistics fitted on your own memories.
  3. One memory for 16 agents. Served over MCP, so what one agent learns, the next one starts with.

    Questions

    Before you install.

    Does it cost anything?

    Free for individuals. Team plans are coming. There is no licence key or trial to activate. What you have written stays yours either way: it lives in files on your computer.

    What do I need?

    A Mac — Apple Silicon or Intel, a Linux PC on Ubuntu or Debian (x86_64, the .deb), a Windows 10/11 PC — and at least one of the 16 AI coding CLIs Slate supports, such as Claude Code, Codex, Cursor or GitHub Copilot, already signed in.

    The Mac needs macOS 13.5 or later, on Apple Silicon or Intel; each has its own download. Linux and Windows are early builds. You also sign in to Slate once, with Google or GitHub.

    Does Slate send my code or conversations anywhere?

    No. Slate reads the transcripts your tools already write and keeps them on your computer. Your agent still talks to its own model under its own sign-in, as it always did. A workspace you choose to share is readable by its members. Personal is not shared unless you turn its sharing on. Every exception, precisely.

    What does it change in my agents?

    Nothing until you connect one. Connecting installs Slate into that tool: as a plugin where the tool takes one, such as Claude Code, Codex, Gemini and Cursor, and through its own config file otherwise, such as OpenCode. A config file Slate changes is copied aside first, and turning a tool off takes out what Slate put there.

    Why a curl script and not a .dmg?

    Slate is not notarized by Apple yet. macOS quarantines anything a browser downloads, and for an un-notarized app that becomes a "could not verify" dialog you can only clear in System Settings. curl sets no quarantine flag, so the app simply opens. The script is short and commented — read it first.

    What does the installer verify?

    The download against the release's SHASUMS256.txt — which catches a corrupted download, not a compromised host, since both come from the same place. Updates are stronger: each is signed, and Slate checks the signature against a key built into the app before installing.

    # check a download yourself
shasum -a 256 -c SHASUMS256.txt
    How do updates work?

    Slate checks while it is open, downloads a new version in the background and installs it when you next quit. Nothing restarts on its own.

    How do I remove it?

    One command takes Slate out of every agent it was connected to and removes the app. Your workspace is kept unless you ask otherwise, and --dry-run shows every step first.

    curl -fsSL https://liozelmalem-star.github.io/slate-releases/uninstall.sh | bash -s -- --dry-run
    Can my team use it together?

    Yes, optionally. A shared workspace is a separate file that its members read; your Personal workspace stays private unless you share it. Each page has one author and opens read-only for everyone else. Team plans are coming.
